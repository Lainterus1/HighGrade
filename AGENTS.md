# Работа агента в High Grade

Назначение: рабочие инструкции этого репозитория разработки. Это не универсальный шаблон для всех будущих проектов.

## Источники и полномочия

Начни с [README](README.md) и [проектной инструкции](.highgrade/project/INSTRUCTIONS.md), когда она создана. Согласованный глобальный маршрут — в [GLOBAL](docs/workflow/GLOBAL.md), правила доказательств — в [QUALITY](docs/workflow/QUALITY.md), политика контекста — в [CONTEXT](docs/workflow/CONTEXT.md); [SPECIFICATION](docs/workflow/SPECIFICATION.md) хранит историю решений. Устройство существующего проекта — в [ARCHITECTURE](docs/ARCHITECTURE.md), инженерные правила — в [ENGINEERING](docs/ENGINEERING.md), команды — в [DEVELOPMENT](docs/DEVELOPMENT.md).

Читай только контекст затронутой области. Архив — история, не действующая инструкция; не загружай его целиком без причины. Для плагина читай его входные документы и тесты, но не запускай сам навык аудита/векторизации только из-за работы с его исходниками.

## Маршрут High Grade в этом репозитории

Новую неясную задачу прорабатывай через `highgrade-task`; уже ясное и разрешённое поручение не переспрашивай. Изменение поведения оформляй через `highgrade-spec` в OpenSpec и выполняй через `highgrade-work`; малую ясную техническую задачу можно выполнить прямо. Готовую задачу завершай через `highgrade-approve`: точный локальный коммит и местная активация из его SHA. Выбранный диапазон готовых коммитов отправляет отдельный `highgrade-push` по явному поручению. `highgrade-clear` — обзор по запросу, `highgrade-update` — отдельное переключение общей поставки. Команды — в [DEVELOPMENT](docs/DEVELOPMENT.md); вторые навыки для тех же обязанностей не создавай.

## Штатная работа

Обновляй связанные документы, проверяй их согласованность, ссылки и размеры. Архивируй подтверждённо завершённое/заменённое с сохранением причин и входящих ссылок. Неоднозначное оставляй активным с обозначенным вопросом. Следуй [политике контекста](docs/workflow/CONTEXT.md) для бюджетов и временных обходов; эти обязанности не ждут отдельной актуализации.

Комплексная актуализация — дополнительный обзор по запросу через глобальный `highgrade-clear`. Это процедура агента с `doctor`/`inspect`, а не самостоятельная программа смыслового анализа. Известный существенный конфликт останавливает только зависимую работу, превышение размера требует пересмотра. Статус бюджетов определяет [реестр](.highgrade/project/documents.json); неизвестное не считай успешной проверкой.

## Сохранность и результат

Сохраняй посторонние изменения. Не переключай marketplace, установленные плагины или глобальные настройки, не публикуй и не удаляй исходные копии без поручения. Планы и доказательства имеют одно основное место; не дублируй задачи OpenSpec отдельным backlog.

В конце кратко назови результат, проверку и существенный остаток; длинный отчёт готовь только по запросу или для решения. Постоянное разрешение автора на независимое ревью этого репозитория записано в [проектной инструкции](.highgrade/project/INSTRUCTIONS.md): запускай его без повторного вопроса и промежуточного уведомления. Блокировку внешнего действия объясняй один раз; не повторяй один и тот же запрос разрешения. Различай организацию документов, структурную проверку, тесты поведения, установку и пользовательскую приёмку. Не заявляй работоспособность будущего workflow по наличию документации или совпадению хешей плагинов.
