# Preparation and verification

Give real dependency, launch and diagnostic commands. Separate focused tests, mandatory full barriers, builds and scenario evidence. For each command, name coverage, trigger, environment, expected outcome and original-report path. If two runs cover the same tests, explain added coverage or select one primary route. Preserve independent mandatory coverage.

For supported reports, explain scenario-ID/executed-test matching. For manual scenarios, name the actual exercise record; instructions are not results. Run standard tests directly or through explicit spec-run selection with runners.json/checks. Catalog reads run no code. Define exercise setup, action, observation, causal inputs, report format and timeout. Manual methods remain valid.

State check selection: affected narrow behavior test, mandatory barriers, independent coverage and expansion for unknown mapping/shared risk. Reuse matching current results; explain omissions. spec-stats --root PATH --id HG-CHANGE gives bound-test timings. Read it for actual slowness, not every run. For a human observation, chat confirmation of version, actions and outcome is enough. Record manual evidence as reported by the user; do not repeat their action by default.
