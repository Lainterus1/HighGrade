# Общие правила High Grade

Авторский текст спецификаций, задач, планов, состояния, отчётов и передачи человеку пиши на языке проектной инструкции, включая сохранённые файлы. Явное указание пользователя имеет приоритет; если язык не закреплён, используй язык текущего запроса и обозначь это допущение при адаптации. Английский язык шаблона или настройка навыка по умолчанию не меняют язык проекта. Имена полей JSON, ID, команды, пути, машинные статусы и дословные исходные сообщения не переводятся.

Когда правила задачи требуют независимого ревью, поручай его отдельному субагенту по [процедуре work](procedures/work.md#доказательства-и-ревью). Передавай только относящиеся к задаче требования, изменения и доказательства; не запрашивай повторное разрешение на уже порученное ревью.

Активная версия общей пользовательской поставки задаёт общий процесс во всех проектах. Проектные особенности читаются из `.highgrade/project/INSTRUCTIONS.md`: команды, ссылки на документы и принятые исключения. Применяй уже принятое исключение в его области без повторного вопроса; при новом существенном противоречии покажи обе стороны и останови только зависимое действие. Явное поручение пользователя имеет приоритет в пределах полномочий. Не веди центральный список проектов и не сканируй соседние каталоги.

Поставка самостоятельна: общие правила принадлежат этому файлу, действия — процедурам, проектные решения — местной инструкции. Исходники High Grade и его документы QUALITY/CONTEXT не нужны подключаемому проекту. [Контекст и адаптация](references/audit.md#контекст-и-адаптация) задают общие критерии документов, бюджетов и результата init; читай их при адаптации и изменении соответствующих правил, а не целиком для каждой задачи.

Для задачи читай AGENTS, проектную инструкцию и только относящиеся к ней действующие документы. JSON-спецификация High Grade владеет изменениями требований и их задачами; явно сохранённый проектом маршрут спецификации High Grade и решение о совместимости со старым форматом поддерживается до перехода; второго backlog нет. Маршрут выбирай по [task](procedures/task.md#выбор-достаточного-маршрута): прямое выполнение, технический план или изменение спецификации. Исправление реализации по неизменному контракту не требует новой спеки; проверки и ревью по риску обязательны для любого маршрута. Для зависимой работы сохрани один Next и доказательства. Штатные тесты запускаются командами проекта; `trace` читает результаты и не доказывает смысловую правильность сценариев. Документы и архив сопровождаются в обычной работе, а clear остаётся дополнительным обзором. Явный `highgrade-approve` разрешает локальный коммит принятой задачи и назначенную проектом локальную активацию из этого SHA. Отправка выбранного диапазона требует явного `highgrade-push`; эксплуатационная активация и пользовательская приёмка имеют отдельные полномочия и доказательства. Человеческое решение сохраняется через spec-decide только после явного ответа по точной проверенной версии; отсутствие ответа не блокирует работу над следующими задачами. Ответ пользователю начинай с результата, затем кратко назови проверки и существенное ограничение. Длинный отчёт делай только по запросу или когда он нужен для решения. Не повторяй проверку между этапами без изменения проверенного состояния или конкретного риска. Если внешнее действие заблокировано автоматической проверкой, объясни причину один раз, закончи доступную работу и не запрашивай то же разрешение повторно без нового решения автора.

Если задача требует последовательного выполнения зависимых задач или спек, а проект принял правило Goal, используй [Highgrade Planner](procedures/planner.md) для одного Goal на всю цепочку. Явный вызов Planner также выбирает этот маршрут. Planner сохраняет выбранный task/spec/work и не меняет отдельные полномочия approve, push и приёмки.

При первом входе в проект, смене активной Поставки, местной инструкции или значимой среды выполни [проверку совместимости](references/cli.md#совместимость-проекта). В пределах сессии переиспользуй неизменённый проверенный контекст; не запускай одинаковую диагностику при каждом переходе навыка.
