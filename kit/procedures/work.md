# Выполнение задачи

Установи полномочия, проектную инструкцию, текущее состояние и один основной источник задач: OpenSpec change для изменения поведения, иначе технический план, если нужны зависимые этапы. Малую ясную задачу выполняй напрямую. Если область кода неясна, найди её целевым поиском и чтением проекта. Не заводи второй backlog. Для новых и изменённых сценариев проверь уникальность ID и подходящий способ доказательства. Изменяй только порученное и запускай штатные проверки проекта напрямую. После них используй `trace` только для поддерживаемых доказательств сценариев; одна отметка на тесте не означает выполненную проверку. Для ручного сценария зафиксируй действие, наблюдение, дату, состояние исходника и предел проверки; отсутствующее доказательство оставь пробелом.

Во время обычной работы доводи документы, бюджеты контекста, временные обходы и архив до состояния текущей задачи. Перед завершением сверь каждый затронутый сценарий с фактическим тестом, ручным наблюдением либо явно названным пробелом. Значимое изменение проходит независимое ревью по риску; недоступное ревью остаётся незавершённым. В итоге отделяй доказанное от неизвестного и называй один следующий шаг. `highgrade-approve` по явному вызову сверяет готовый результат, создаёт локальный коммит и выполняет назначенную проектом локальную активацию; `highgrade-push` отдельно публикует выбранный диапазон.
