# Выполнение задачи

Установи полномочия, проектную инструкцию, текущее состояние и один основной источник задач: OpenSpec change для изменения поведения, иначе технический план, если нужны зависимые этапы. Малую ясную задачу выполняй напрямую. Если область кода неясна, найди её целевым поиском и чтением проекта. Не заводи второй backlog. Изменяй только порученное и запускай штатные проверки проекта напрямую. После них используй `trace` только для поддерживаемых доказательств сценариев; одна отметка на тесте не означает выполненную проверку.

Во время обычной работы доводи документы, бюджеты контекста, временные обходы и архив до состояния текущей задачи. Значимое изменение проходит независимое ревью по риску; недоступное ревью остаётся незавершённым. В итоге отделяй доказанное от неизвестного и называй один следующий шаг. `highgrade-approve` по явному вызову сверяет готовый результат, создаёт локальный коммит и выполняет назначенную проектом локальную активацию; `highgrade-push` отдельно публикует выбранный диапазон.
