# Инициализация проекта

Начни с read-only `inspect --bootstrap --root <проект>`: он показывает семь обязательных путей, возможные альтернативы, связи и непросмотренные области до создания реестра. Структурный `failed` из-за отсутствующих путей или связей на этом этапе ожидаем: продолжай аудит, используя находки как список работ; недоступный корень или отсутствие пригодного отчёта останавливает зависимую адаптацию. Прочитай действующие AGENTS, README, архитектуру, инженерные правила, команды, OpenSpec, локальные навыки, тесты и применимые файлы проекта. Для существующего проекта проведи полный аудит по `references/audit.md` и read-only `inventory`; перечисли непрочитанное и неизвестное. Для нового проекта выясни назначение, критерии успеха, риски, ограничения и пожелания автора. Задавай только вопросы, на которые ещё нет ответа.

Сопоставь документы с пятью основными ролями и каноническими путями: `README.md`, `AGENTS.md`, `docs/ARCHITECTURE.md`, `docs/ENGINEERING.md`, `docs/DEVELOPMENT.md`; проектная инструкция и реестр находятся в `.highgrade/project/INSTRUCTIONS.md` и `.highgrade/project/documents.json`. Составь одну краткую таблицу адаптации: **обязательный путь и связь → состояние → проверенный источник и основание → результат поиска вне кандидатов → решение → открытый вопрос**. Для найденного по имени кандидата проверь содержание и явно отклони ложное совпадение с причиной. Если сканер не нашёл документ, ищи его содержание самостоятельно. Эквивалентный документ с другим именем перенеси, смешанный раздели по ответственности, действительно недостающее содержание создай; сохраняй дополнительные профильные источники. После переноса обнови входящие ссылки и реестр. Для каждого местного навыка установи повод вызова, вход, выход и владельца действия. При пересечении с общим навыком High Grade явно покажи конфликт и варианты: использовать общий, скорректировать местный или оставить местный как выбранный активный маршрут. Не устанавливай два конкурирующих активных пути молча.

Предложи проектную инструкцию, ссылки из README к четырём основным документам и из AGENTS к проектной инструкции, маршрут OpenSpec, проектные команды, бюджеты контекста и один план адаптации. Начальный init завершается согласованным планом; после его разрешённого выполнения проверь результат обычным `inspect`. Структурный отчёт не заменяет аудит и не разрешает автоматическую запись. Техническое подключение и пользовательская приёмка различаются. Общие навыки, CLI и процедуры в проект не копируются.
