# Обновление общей поставки

Если автор одним сообщением принимает и активирует уже представленный точный готовый результат, используй правило [совмещённого решения](commit.md#решение-пользователя) без повторного вопроса. Обычная установка или пробная активация не подразумевает приёмку проектных спек и не заменяет человеческое наблюдение.

Работай только по явному запросу обновить High Grade. Выбери конкретный источник; не ищи latest и не сканируй проекты. Для Git зафиксируй выбранный SHA, создай его изолированную копию через archive/worktree и собери CLI в ней по [справочнику](../references/tools/installation.md). Грязное рабочее дерево само не становится кандидатом; запрос на его использование требует отдельно обозначенного состава и неизменяемого снимка, без автоматического коммита. Для готового пакета зафиксируй происхождение и отпечатки, используй поставляемый с ним CLI; одна совпадающая версия бинарника не доказывает его происхождение. Если источник неоднозначен, уточни только этот выбор.

До переключения проверь текущую установку её CLI, сохрани его заведомо рабочую копию вне каталогов выпуска для диагностики сбоя. При ошибке status следуй разделу ниже, включая явное восстановление прерванной транзакции. Зафиксируй прежний release ID. Проверь кандидат: манифест, хеши, версию CLI, принадлежность обновляемых SKILL.md активному журналу и изменения общих правил. Выполни preview через CLI кандидата. Ожидаемый результат технически корректного preview — status=unknown, код выхода 2 и SemanticReviewRequired при validation=passed, decision=required, applied=false: это запрос смыслового обзора, не сбой установки и не успешное применение. Сохрани candidate_sha256; после обзора примени --apply true --candidate-sha256 <тот же отпечаток>. Иные ошибки или unknown разбирай по фактическим findings, не считай их этим ожидаемым состоянием. Изменение кандидата требует нового preview. После применения проверь global-status; ошибка или unknown не означают успех. Материалы выпуска неизменяемы; после успешной проверки CLI удаляет собственные файлы неактивных выпусков, сохраняя чужие с предупреждением. Восстановление после сбоя не является постоянной возможностью отката успешного обновления.

## Повтор и ошибки

- GlobalSameRelease запрещает повторное переключение, но само по себе не доказывает равенство состава. При успешном global-status сравни SHA256 кандидатного manifest.json с manifest_sha256 проверенного <профиль>/.highgrade/global/releases/<active>/journal.json и SHA256 кандидатного CLI с установленным CLI (`highgrade` в Linux, `highgrade.exe` в Windows). Сам manifest.json в установленный выпуск не копируется. Проверенный манифест связывает остальные материалы; status проверяет целостность установки. Только совпадение даёт ответ «этот состав уже установлен», без apply. Различие — конфликт неизменяемого release ID; не перезаписывай выпуск и не переименовывай его ради обхода. Нужен отдельно подготовленный новый выпуск. Недоступное сравнение оставь unknown.
- При сбое сохрани исходную ошибку и немедленно проверь global-status сохранённым прежним CLI. При миграции Approve → Commit прежняя CLI может не понимать новые поля журнала или состав выпуска: диагностируй и при GlobalSkillRecoveryRequired восстанавливай той же проверенной CLI кандидата. Сам отказ прежней CLI по формату не доказывает повреждение. Код предусматривает восстановление после ошибки postcheck, однако восстановление тоже может не выполниться. Сообщи фактически подтверждённый активный выпуск и незавершённую очистку отдельно от ошибки обновления. Если status не проходит, состояние не подтверждено: останови дальнейшие изменения установки, кроме описанного ниже восстановления при GlobalSkillRecoveryRequired. Для иной ошибки предложи восстановление по наблюдаемой причине; не редактируй указатель и не запускай очистку вслепую. Успешное восстановление не заявляй только по тексту инструкции.
- GlobalSkillRecoveryRequired означает незавершённую транзакцию навыков и служит явным исключением из остановки после ошибки status. Выполни `global-recover --profile <профиль>` CLI проверенного кандидата: он проверяет журнал, восстанавливает прежние навыки при старом активном указателе либо подтверждает уже активный новый выпуск. Затем повтори global-status совместимой CLI фактически активного выпуска; только успешная проверка подтверждает состояние и позволяет продолжить обновление. Пользовательские изменения либо ошибка кандидата/recover останавливают зависимые действия; сохрани исходную ошибку и журнал, не удаляй его и не переписывай навыки либо указатель вручную.

Проектные инструкции автоматически не переписываются. Применяй [контракт совместимости](../references/tools/diagnostics.md#совместимость-проекта): схема отдельно от смысла, принятые исключения сохраняются. При следующем входе в проект проверь совместимость; сложный конфликт разбирает highgrade-clear. Кратко сообщи исходный и фактический выпуск, результат проверки, ошибку и незавершённую очистку, если они есть; приёмку проектов не подразумевай.

Обновление общей Поставки не мигрирует проектные спецификации. Перед чтением или записью проверь поддержку выбранной CLI фактического формата каталога и используемых полей, включая каталоги v4 и новые поля без смены версии формата. Несовместимой прежней CLI нельзя редактировать каталог или оставшийся исторический store. Любая миграция — отдельное разрешённое проектное действие по [справочнику спецификаций](../references/tools/specifications.md#каталог-миграция-и-восстановление), с предусмотренной им сохранностью исходных данных. Смена общей CLI не откатывает проектный формат и поля автоматически; сохранность и доступ к каталогу проверяются отдельно.

## Совместимость проектного запуска UI

Запускатели протокола 1 читают стандартный active.json (schema 3) домашнего профиля при каждом запуске и вызывают `global-status`, затем `ui --root`. Не закрепляй в них release ID и не обходи проекты при Update. Preview проверяет `ui --check true` кандидата, включая launcher_protocol=1; та же проверка выполняется установленным кандидатом до признания обновления успешным. Неподдерживаемый протокол останавливает обновление; сбой postcheck проходит штатное восстановление прежнего выпуска. После восстановления те же проектные файлы выбирают восстановленный указатель. Это не добавляет откат успешного обновления. Изменение формата запускателей требует явной совместимой миграции, без перезаписи пользовательских файлов. Технические проверки выполняются на изолированных профиле и проекте; реальный UI проекта без поручения не запускай.
