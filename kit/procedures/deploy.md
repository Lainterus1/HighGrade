# Выпуск принятой доработки

Запускай только по явному запросу `deploy` для конкретной принятой задачи. Такой вызов разрешает коммит, обычный push и документированную активацию в её границах; окончательное состояние выпуска подтверждается проверками после каждого действия. Не выводи согласие на выпуск из завершения `work`, тестов или OpenSpec само по себе.

До мутаций установи основной источник задачи и перечень принятых результатов, нужные проверки и ревью, текущие Git HEAD/ветку/remote, точный состав файлов и участков, а также цель и процедуру активации из проектной инструкции. Раздели изменения на принятые, отклонённые, посторонние и неясные. Не включай неясное по умолчанию; уточни только решение, без которого нельзя продолжить зависимый выпуск. Не переписывай чужой индекс Git, не используй без разбора `git add -A`, `reset`, `stash` или force push.

Приведи действующие документы, ссылки, реестр и версию выпуска к принятому поведению. Причины отклонённых подходов и существенные доказательства сохрани в принятом архиве; удаляй одноразовые результаты только после проверки принадлежности, ссылок и отсутствия сохраняемой ценности. Ошибка проверки текущего кандидата возвращает задачу в `work`, а не становится автоматическим архивным отказом. Посторонние изменения оставь и перечисли отдельно.

Запусти штатные проверки проекта и проверь подготовленный состав коммита целиком: исходники, лицензии/происхождение, закрытые данные, кэши и доказательства. Создай коммит только выбранного состава, проверь, что обычный push в указанную ветку допустим, выполни его и сверь SHA удалённой ветки с локальным. После подтверждённого push активируй только артефакт из этого SHA или изолированной копии этого коммита; не собирай для активации из рабочего дерева с оставшимися изменениями. Проверь фактическое состояние активации. Если проект не задаёт цель, команды или критерий проверки, не придумывай их и остановись до зависимой мутации.

Отчёт отдельно называет выбранные и исключённые изменения, проверки, архив/удаление, локальный коммит, удалённый SHA, активную версию и откат. Если поздний этап не прошёл, сообщи уже выполненные действия и точную границу остановки; не скрывай опубликованный коммит и не отменяй удалённую историю без отдельного решения. Для выпуска самого High Grade используй процедуру в его проектной инструкции: `global-update` — технический шаг локальной активации после GitHub push. Навык `highgrade-update` сохраняет отдельную задачу переключения на заранее выбранный пакет.
