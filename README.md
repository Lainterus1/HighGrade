# High Grade

**High Grade — переносимый процесс разработки с Codex: навыки, процедуры и CLI.**

[Проверки исходников](https://github.com/Lainterus1/HighGrade/actions/workflows/verify.yml) · [Лицензия MIT](LICENSE) · [Команды CLI](kit/references/cli.md)

## Цель проекта

Делать разработку с участием агентов надёжной, эффективной и удобной: помогать им правильно понимать намерение пользователя, самостоятельно выполнять согласованную работу и получать проверяемый результат с минимальными затратами на уточнения, координацию и исправление ошибок.

## Принципы принятия решений

- **Соответствие цели.** Решения оцениваются по тому, насколько они приближают результат, нужный пользователю.
- **Обоснованная простота.** Сложность процесса оправданна, только если её польза превышает затраты.
- **Соразмерность.** Глубина проработки, формализации и проверки соответствует неопределённости и последствиям ошибки.
- **Согласованность.** Требования, действия и источники знаний образуют понятную систему без противоречий и лишнего дублирования.
- **Самостоятельность.** Агент использует доступный контекст и действует в пределах полномочий, обращаясь к пользователю за существенными недостающими решениями.
- **Адаптивность.** Общий подход учитывает особенности проекта и сохраняет полезные существующие решения.
- **Доказательность.** Выводы и заявления о готовности опираются на наблюдаемые результаты; предположения и неизвестное обозначаются явно.
- **Повторное использование.** Повторяющиеся задачи обеспечиваются готовыми инструментами и понятными процедурами, чтобы агент мог сосредоточиться на содержательной работе, не выстраивая заново уже определённый способ действий.

## Критерий улучшения

Изменение полезно, если оно повышает надёжность, сокращает путь до результата или снижает усилия участников без несоразмерного ухудшения остальных качеств.

## Быстрый старт

Для сборки нужны [Codex](https://openai.com/codex/), Git, [Rust/Cargo](https://rustup.rs/) 1.89+ и Node 24/npm. Установленному UI нужен браузер.

### 1. Установите

В Linux (Bash):

```bash
git clone https://github.com/Lainterus1/HighGrade.git
cd HighGrade
(cd ui && npm ci && npm run build)
cargo build --release --locked
./target/release/highgrade global-install --profile "$HOME" --source "$PWD/kit" --candidate-exe "$PWD/target/release/highgrade"
./target/release/highgrade global-status --profile "$HOME"
```

Сборочная версия закреплена в `rust-toolchain.toml`; rustup устанавливает её при первом запуске Cargo. После установки навыки обнаруживаются Codex из `~/.agents/skills`; если список не обновился, перезапустите Codex. Установка не подключает рабочие проекты автоматически.

В Windows (PowerShell):

```powershell
git clone https://github.com/Lainterus1/HighGrade.git
cd HighGrade
Push-Location ui
npm ci
npm run build
Pop-Location
cargo build --release --locked
.\target\release\highgrade.exe global-install `
  --profile "$env:USERPROFILE" `
  --source (Join-Path $PWD 'kit') `
  --candidate-exe (Join-Path $PWD 'target\release\highgrade.exe')
.\target\release\highgrade.exe global-status --profile "$env:USERPROFILE"
```

### 2. Подключите проект

Откройте **свой проект** в Codex и попросите:

> Используй `$highgrade-init`, обследуй этот проект и предложи минимальную адаптацию High Grade.

Init готовит репозиторий и начальные спеки; их проработка и реализация — позже. OpenSpec не требуется.

Просмотр и правка спек: `highgrade ui --root <путь-к-проекту>`. [Интерфейс и ограничения](docs/UI.md).

### 3. Выполняйте задачи

| Если нужно… | Используйте |
|---|---|
| Прояснить результат и границы | `highgrade-task` |
| Выполнить зависимые задачи или спеки под одним Goal | `highgrade-planner` |
| Изменить требование или нормативный сценарий | `highgrade-spec` → `highgrade-work` |
| Исправить реализацию по действующему контракту | `highgrade-work` |
| Провести дополнительный обзор проекта | `highgrade-clear` |
| Локально принять готовую задачу и создать коммит | `highgrade-approve` |
| Отправить выбранные коммиты | `highgrade-push` |
| Обновить общую установку | `highgrade-update` |

Каталог: `spec-list`, [спецификации](specs/README.md).

## Термины и границы

**Поставка** — устанавливаемые навыки, процедуры, шаблоны и Rust CLI. **Проект** — этот репозиторий. **Подключаемый проект** — репозиторий, адаптируемый High Grade. Поставка самостоятельна; SVG Vectorizer и Code Health Audit — отдельные плагины.
