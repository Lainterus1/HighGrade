# High Grade

**High Grade — переносимый процесс разработки с Codex.** Он помогает прояснить задачу, записать требования, проверить сценарии и передать результат человеку. Учитывает язык и проверки проекта.

[Проверки исходников](https://github.com/Lainterus1/HighGrade/actions/workflows/verify.yml) · [Лицензия MIT](LICENSE) · [Команды CLI](kit/references/cli.md)

## Что входит в Поставку

- **Навыки для всего маршрута:** от обследования проекта и постановки задачи до выполнения, локального принятия и отдельной публикации. Небольшая правка не требует формальной спеки.
- **Единый каталог спецификаций:** CLI назначает номер и создаёт JSON-заготовку. Требования и изменения лежат в отдельных файлах проекта, а сценарии описывают подготовку, действие и наблюдаемый исход.
- **Проверки с явными пробелами:** сценарий связывается с настоящим тестом или ручным наблюдением. Пропуск и устаревший результат не становятся успехом; значимые изменения проверяет независимый субагент.
- **Самостоятельность проекта:** общие навыки и CLI устанавливаются в профиль пользователя. Местная инструкция, спецификации, тесты и решения остаются в вашем репозитории даже после удаления High Grade.

High Grade не требует OpenSpec и не переносит прежние спеки без отдельного решения. Выполнение, коммит, отправка в Git и решение человека — разные действия.

## Быстрый старт

Поддерживается сборка из исходников для **Windows**. Нужны [Codex](https://openai.com/codex/), Git и [Rust с Cargo](https://rustup.rs/) 1.89 или новее.

### 1. Установите

В PowerShell:

```powershell
git clone https://github.com/Lainterus1/HighGrade.git
cd HighGrade
cargo build --release --locked
.\target\release\highgrade.exe global-install `
  --profile "$env:USERPROFILE" `
  --source (Join-Path $PWD 'kit') `
  --candidate-exe (Join-Path $PWD 'target\release\highgrade.exe')
.\target\release\highgrade.exe global-status --profile "$env:USERPROFILE"
```

Навыки `highgrade-*` и CLI устанавливаются в профиль пользователя. Подключённым проектам клон не нужен.

### 2. Подключите проект

Откройте **свой проект** в Codex и попросите:

> Используй `$highgrade-init`, обследуй этот проект и предложи минимальную адаптацию High Grade.

Навык найдёт документы и тесты, уточнит существенные решения и предложит план. После согласованной адаптации у проекта появится собственная `.highgrade/project/INSTRUCTIONS.md`. Спецификации хранятся отдельно от служебной `.highgrade`; путь выбирается при подключении.

### 3. Выполняйте задачи

| Если нужно… | Используйте |
|---|---|
| Прояснить результат и границы | `highgrade-task` |
| Выполнить зависимые задачи или спеки под одним Goal | `highgrade-planner` |
| Изменить требование или нормативный сценарий | `highgrade-spec` → `highgrade-work` |
| Исправить реализацию по действующему контракту | `highgrade-work` |
| Провести дополнительный обзор проекта | `highgrade-clear` |
| Локально принять готовую задачу и создать коммит | `highgrade-approve` |
| Отправить выбранные коммиты | `highgrade-push` |
| Обновить общую установку | `highgrade-update` |

Местная инструкция задаёт команды тестов и допустимые исключения. `spec-list` показывает состояние JSON-спецификаций; формат показан в [каталоге Проекта](specs/README.md).

## Термины и границы

**Поставка** — устанавливаемые навыки, процедуры, шаблоны и Rust CLI. **Проект** — этот репозиторий разработки Поставки. **Подключаемый проект** — ваш репозиторий, который High Grade адаптирует. Поставка работает без доступа к Проекту; дополнительные SVG Vectorizer и Code Health Audit ей не требуются.

## Для разработчиков Поставки

[AGENTS](AGENTS.md) задаёт правила работы здесь; [ARCHITECTURE](docs/ARCHITECTURE.md) — устройство, [ENGINEERING](docs/ENGINEERING.md) — инженерные правила, [DEVELOPMENT](docs/DEVELOPMENT.md) — команды проверки. [Карта документов](docs/README.md) — остальное. Общие устанавливаемые материалы находятся в [`kit/`](kit/), CLI — в [`src/`](src/), его тесты — в [`tests/`](tests/). Действующие требования Проекта — в [`specs/`](specs/README.md).
