# High Grade

**Разработка с Codex: от понятной задачи до проверяемого результата.**

Навыки для Codex, процедуры, Rust CLI и локальный интерфейс. High Grade помогает сохранить договорённости, продолжить работу после перерыва и проверить результат.

[Документация](docs/README.md) · [Команды CLI](kit/references/cli.md) · [Проверки исходников](https://github.com/Lainterus1/HighGrade/actions/workflows/verify.yml) · [MIT](LICENSE)

## Что это даёт

- **Меньше повторных объяснений.** Требования и решения остаются в проекте.
- **Подходящий процесс.** Багфикс по действующим требованиям — напрямую; изменение требований — через спецификацию.
- **Понятная готовность.** Проверки показывают результат и оставшиеся пробелы.

## Быстрый старт

Для сборки нужны [Codex](https://openai.com/codex/), Git, [Rust/Cargo](https://rustup.rs/) и Node.js 24/npm. Rust закреплён в `rust-toolchain.toml`; rustup установит нужную версию при первом запуске Cargo.

### 1. Установите High Grade

**Linux · Bash**

```bash
git clone https://github.com/Lainterus1/HighGrade.git
cd HighGrade
(cd ui && npm ci && npm run build)
cargo build --release --locked
./target/release/highgrade global-install --profile "$HOME" --source "$PWD/kit" --candidate-exe "$PWD/target/release/highgrade"
./target/release/highgrade global-status --profile "$HOME"
```

**Windows · PowerShell**

```powershell
git clone https://github.com/Lainterus1/HighGrade.git
cd HighGrade
Push-Location ui
npm ci
npm run build
Pop-Location
cargo build --release --locked
.\target\release\highgrade.exe global-install `
  --profile "$env:USERPROFILE" `
  --source (Join-Path $PWD 'kit') `
  --candidate-exe (Join-Path $PWD 'target\release\highgrade.exe')
.\target\release\highgrade.exe global-status --profile "$env:USERPROFILE"
```

Навыки устанавливаются в `~/.agents/skills`. Если Codex их не обнаружил, перезапустите его.

### 2. Подключите свой проект

Откройте проект в Codex и попросите:

> Используй `$highgrade-init`, обследуй этот проект и предложи минимальную адаптацию High Grade.

Init адаптирует правила к проекту и готовит нужные начальные спеки в разрешённой области. Реализация задач — следующий шаг. Установка сама по себе не подключает проекты. OpenSpec не требуется.

### 3. Начните работу

| Что нужно сделать | Навык |
|---|---|
| Уточнить результат и границы | `highgrade-task` |
| Вести зависимые задачи или спеки с общим планом | `highgrade-planner` |
| Изменить требования или нормативные сценарии | `highgrade-spec` → `highgrade-work` |
| Исправить реализацию по действующим требованиям | `highgrade-work` |
| Провести обзор проекта | `highgrade-clear` |
| Создать локальный коммит задачи или кандидата | `highgrade-commit` |
| Отправить выбранные коммиты | `highgrade-push` |
| Обновить общую установку | `highgrade-update` |

Проработка новой задачи:

> Используй `$highgrade-task`. Хочу добавить поиск по списку заказов. Уточни поведение и границы задачи.

Исправление по действующему требованию:

> Используй `$highgrade-work`. Исправь сортировку: новые записи должны быть первыми. Проверь этот сценарий.

Коммит, активация, публикация и приёмка результата подтверждаются отдельно.

## Спецификации в браузере

Читайте и редактируйте спеки, смотрите условия готовности, сохраняйте решения. Init создаёт в проекте `HighGrade UI.sh` и `HighGrade UI.cmd`: они запускают интерфейс текущей установки.

Интерфейс встроен в CLI. После установки ему нужен браузер; Node.js, Cargo и внешняя сеть не нужны.

## Цель проекта

Сделать разработку с агентами надёжной, эффективной и удобной. Помочь агенту правильно понять намерение пользователя, самостоятельно выполнить согласованную работу и получить проверяемый результат. Сократить затраты на уточнения, координацию и исправление ошибок.

## Принципы принятия решений

- **Соответствие цели.** Выбирать решения, которые приближают нужный пользователю результат.
- **Обоснованная простота.** Добавлять сложность, только когда её польза превышает затраты.
- **Соразмерность.** Выбирать глубину проработки, формализации и проверок с учётом неопределённости и последствий ошибки.
- **Согласованность.** Поддерживать понятную связь между требованиями, действиями и документами. Убирать противоречия и лишние повторы.
- **Самостоятельность.** Использовать доступный контекст и действовать в пределах полномочий. Запрашивать существенные недостающие решения.
- **Адаптивность.** Учитывать особенности проекта и сохранять полезные существующие решения.
- **Доказательность.** Подтверждать выводы наблюдаемыми результатами. Явно обозначать предположения и неизвестное.
- **Повторное использование.** Давать готовые инструменты и процедуры для повторяющихся задач, чтобы агент мог сосредоточиться на самой работе.

## Критерий улучшения

Изменение полезно, если повышает надёжность, сокращает путь до результата или снижает усилия участников без несоразмерного ухудшения остальных качеств.

## Термины и границы

**Поставка** — устанавливаемые навыки, процедуры, шаблоны и Rust CLI. **Проект** — этот репозиторий. **Подключаемый проект** — проект, адаптируемый High Grade.

Поставка работает без доступа к этому репозиторию. SVG Vectorizer и Code Health Audit — отдельные плагины.
