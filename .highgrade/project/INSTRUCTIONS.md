# Проектная инструкция High Grade для самого High Grade

Статус: действующая адаптация исходного проекта; исходная поставка v0-2-5. Фактическую активную версию проверяет `global-status`. Этот репозиторий разрабатывает workflow, но не управляет целевыми проектами.

## Работа над задачей и спецификацией

- OpenSpec 1.13.1 — источник требований и задач нового изменения поведения в этом репозитории. Конфигурация — [openspec/config.yaml](../../openspec/config.yaml); команда установки, отключение телеметрии на время работы и проверка версии — в [DEVELOPMENT](../../docs/DEVELOPMENT.md). Запуск из новой копии требует установленного CLI. Инициализация выполнена с `--tools none`: общие навыки High Grade остаются единственным маршрутом агента.
- При создании активного OpenSpec-изменения регистрируй его действующие `spec.md` и `tasks.md` в [реестре контекста](documents.json), а остальные артефакты — как историю; при архивировании перенеси контроль на итоговую спеку и убери активные пути изменения. Одна конфигурация `config.yaml` не покрывает размер и ссылки спек.
- Общие навыки High Grade маршрутизируют init, task, spec, work, clear, deploy и update. Исходные пакеты SVG и Code Health Audit под `plugins/` — отдельные специалисты и не заменяют общие маршруты.
- Штатные проверки: [DEVELOPMENT](../../docs/DEVELOPMENT.md). Trace охватывает только поддерживаемые Rust nextest/Playwright-сценарии после native запусков.

## Выпуск через `deploy`

- Область выпуска определяется принятой задачей и её OpenSpec/ревью; посторонние изменения рабочего дерева остаются вне коммита. Перед push выполни проверки из [DEVELOPMENT](../../docs/DEVELOPMENT.md), проверь полный staged diff, лицензию и отсутствие закрытых данных. Архивируй причины отклонённых подходов, а одноразовые результаты удаляй только после проверки ссылок и принадлежности.
- Git-цель этого исходного проекта — `origin/main` репозитория `Lainterus1/HighGrade`. Используй обычный push без force и сверь `refs/heads/main` на origin с SHA созданного коммита. Установленные SVG/CHA и другие проекты не входят в выпуск.
- После подтверждённого push создай изолированную копию именно опубликованного SHA (например, `git archive` или отдельный worktree), собери её `cargo build --release --locked` и выполни `global-update --profile <домашний-каталог> --source <изолированная-копия>/kit --candidate-exe <изолированная-копия>/target/release/highgrade.exe`: сначала preview и смысловая сверка с текущей поставкой, затем apply с его `candidate_sha256`. Не используй сборку из грязного рабочего дерева. Проверка — `global-status` с релизом из опубликованного `kit/manifest.json` и наличие нового маршрутизатора. Прежний релиз сохраняется для `global-update --rollback <релиз>`; при ошибке активации не называй опубликованный SHA локально активным.

## Полномочия и исключения

- Этот репозиторий поддерживает исходники High Grade. Работа с SNAF, PlantsNotify и другими целевыми проектами выполняется в их каталогах по отдельному поручению.
- Публикация следующих версий, переключение SVG/CHA, деплой и приёмка пилотов требуют соответствующего поручения; выпуск v0-2-1 не даёт постоянного разрешения на эти действия.
- Согласованных исключений из глобальных правил пока нет; найденный конфликт показывать автору до зависимого действия.
