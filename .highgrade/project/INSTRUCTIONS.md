# Проектная инструкция High Grade для самого High Grade

Статус: действующая адаптация исходного проекта v0-2-7. Этапы выпуска — в [записи](../../docs/releases/v0-2-7.md), установленную версию проверяет `global-status`. Этот репозиторий не управляет целевыми проектами.

- Агентские правила: [AGENTS](../../AGENTS.md).
- Фактическое устройство: [ARCHITECTURE](../../docs/ARCHITECTURE.md).
- Инженерные правила и команды: [ENGINEERING](../../docs/ENGINEERING.md) и [DEVELOPMENT](../../docs/DEVELOPMENT.md).
- Общий продуктовый контракт: [GLOBAL](../../docs/workflow/GLOBAL.md). Действующие правила доказательств и контекста: [QUALITY](../../docs/workflow/QUALITY.md) и [CONTEXT](../../docs/workflow/CONTEXT.md); [SPECIFICATION](../../docs/workflow/SPECIFICATION.md) — история решений.

## Работа над задачей и спецификацией

- OpenSpec 1.13.1 — источник требований и задач нового изменения поведения в этом репозитории. Конфигурация — [openspec/config.yaml](../../openspec/config.yaml); команда установки, отключение телеметрии на время работы и проверка версии — в [DEVELOPMENT](../../docs/DEVELOPMENT.md). Запуск из новой копии требует установленного CLI. Инициализация выполнена с `--tools none`: общие навыки High Grade остаются единственным маршрутом агента.
- При создании активного OpenSpec-изменения регистрируй его действующие `spec.md` и `tasks.md` в [реестре контекста](documents.json), а остальные артефакты — как историю; при архивировании перенеси контроль на итоговую спеку и убери активные пути изменения. Одна конфигурация `config.yaml` не покрывает размер и ссылки спек.
- Общие навыки High Grade маршрутизируют init, task, spec, work, clear, approve, push и update. Исходные пакеты SVG и Code Health Audit под `plugins/` — отдельные специалисты и не заменяют общие маршруты.
- Штатные проверки: [DEVELOPMENT](../../docs/DEVELOPMENT.md). Trace охватывает только поддерживаемые Rust nextest/Playwright-сценарии после native запусков.

## Локальное принятие через `highgrade-approve`

- Область коммита определяется принятой задачей и её OpenSpec/ревью; посторонние изменения остаются вне него. Перед коммитом выполни проверки из [DEVELOPMENT](../../docs/DEVELOPMENT.md), проверь полный staged diff, лицензию и отсутствие закрытых данных. Рабочие документы и архив готовит work; approve устраняет найденный разрыв. Неудача проверки возвращает задачу в work.
- Разовый переход v0-2-6 → v0-2-7: пока `global-status` показывает v0-2-6, нового установленного `highgrade-approve` нет. По явному поручению `highgrade-approve` для первого выпуска проверь активный журнал v0-2-6, прочитай его `procedures/deploy.md` и выполни только локальную часть проверки и коммита как переходную процедуру этого проекта, без push. Затем используй описанную ниже активацию из созданного SHA. Не выдавай чтение исходного `kit/skills/highgrade-approve/SKILL.md` за запуск установленного навыка, а переходную процедуру — за вызов старого навыка. После подтверждения `global-status` v0-2-7 переходное правило больше не применяется. Если поручен только код без принятия, не коммить и не активируй.
- Для этого исходного проекта вызов `highgrade-approve` разрешает локальную активацию из созданного коммита. После коммита создай изолированную копию его SHA (`git archive` или отдельный worktree), собери `cargo build --release --locked` и запусти **CLI из этой копии**: `<копия>/target/release/highgrade.exe global-update --profile <домашний-каталог> --source <копия>/kit --candidate-exe <копия>/target/release/highgrade.exe`. Сначала preview и смысловая сверка, затем apply с тем же `candidate_sha256`. Установленный CLI прежней версии может не понимать новый манифест. Не собирай из грязного рабочего дерева. Проверка — `global-status`; прежний релиз сохраняется для `global-update --rollback <релиз>`. Если активация не прошла, коммит остаётся, а статус задачи частичный. Вызов approve не разрешает GitHub push.

## Публикация через `highgrade-push`

- По отдельному поручению отправь выбранный непрерывный диапазон готовых коммитов в `origin/main` репозитория `Lainterus1/HighGrade`. Диапазон может включать несколько задач. До отправки проверь его целиком, актуальное состояние удалённой ветки и последствия CI; неоднозначный состав покажи автору. Используй обычный push без force и сверь `refs/heads/main` на origin с итоговым SHA. Отправка не доказывает местную активацию каждого коммита; установленная версия определяется только `global-status`. Установленные SVG/CHA и другие проекты не входят в маршрут.

## Полномочия и исключения

- Этот репозиторий поддерживает исходники High Grade. Работа с SNAF, PlantsNotify и другими целевыми проектами выполняется в их каталогах по отдельному поручению.
- Публикация следующих версий, переключение SVG/CHA, деплой и приёмка пилотов требуют соответствующего поручения; выпуск v0-2-1 не даёт постоянного разрешения на эти действия.
- Согласованных исключений из глобальных правил пока нет; найденный конфликт показывать автору до зависимого действия.
