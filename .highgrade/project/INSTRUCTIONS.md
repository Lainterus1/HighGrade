# Местная инструкция Проекта High Grade

Статус: Поставка v0-2-14 [активирована локально](../../docs/releases/v0-2-14.md). Установленную версию проверяет `global-status`. Эта инструкция управляет только Проектом — репозиторием разработки Поставки — и не входит в установленную Поставку. Подключаемые проекты получают собственную адаптацию; термины определены в [README](../../README.md#термины-и-границы).

## Владение знаниями

- Цель и вход: [README](../../README.md).
- Агентские правила: [AGENTS](../../AGENTS.md).
- Фактическое устройство: [ARCHITECTURE](../../docs/ARCHITECTURE.md).
- Инженерные правила и команды: [ENGINEERING](../../docs/ENGINEERING.md) и [DEVELOPMENT](../../docs/DEVELOPMENT.md).
- Общий продуктовый контракт: [GLOBAL](../../docs/workflow/GLOBAL.md). Действующие правила доказательств и контекста: [QUALITY](../../docs/workflow/QUALITY.md) и [CONTEXT](../../docs/workflow/CONTEXT.md); [SPECIFICATION](../../docs/workflow/SPECIFICATION.md) — история решений.
- Реестр ролей, областей и бюджетов: [documents.json](documents.json). Текущий статус и основание бюджетов приведены в реестре; исходные измерения и предложенные диапазоны — в [обосновании](../../docs/proposals/context-budget-2026-09-23.md).

## Работа над задачей и спецификацией

- Язык Проекта — русский, в том числе для сохраняемых спецификаций, задач, планов, состояния, отчётов и передачи человеку. Это явный выбор языка для навыков с английским по умолчанию. Имена полей JSON, ID, команды, пути, машинные статусы и дословные исходные сообщения не переводятся.
- Новые изменения поведения веди через установленный `highgrade-spec` и команды `spec-*`: `specs/changes/<ID>/spec.json` и `results.json`, schema_version 3, установленная CLI 0.2.14. Шаблон создаёт CLI; агент заполняет его и сохраняет через инструмент. Команды и проверки — в [DEVELOPMENT](../../docs/DEVELOPMENT.md), формат — в [справочнике Поставки](../../kit/references/cli.md#структурированные-спецификации). Не создавай новое OpenSpec-изменение или второй список задач.
- Существующие `openspec/specs/`, `openspec/changes/` и config.yaml сохраняются без изменений. Прежние действующие требования остаются источником своего поведения, архив — историей. Читай нужные требования при анализе; не объявляй весь каталог устаревшим. Перенос — отдельное поручение; не создавай конкурирующий JSON-контракт для уже принадлежащего старой спеке требования.
- Каталог specs принадлежит Проекту и зарегистрирован в [реестре](documents.json). Действующие требования — requirements; изменения и результаты — changes/<ID>. Читай выборочно через spec-list/read, включая краткие зависимости; теги помогают выборке, но не доказывают полноту. Повторные проверки сохраняют историю results; изменение поведения требует новой спеки. Структуру и готовность проверяют spec-validate/check, не Markdown-проверка inspect. Старый store после миграции — история, писать в него старой CLI нельзя.
- Общие навыки High Grade маршрутизируют init, task, spec, work, clear, approve, push и update. Исходные пакеты SVG и Code Health Audit под `plugins/` — отдельные специалисты и не заменяют общие маршруты.
- Штатные проверки и сценарные ID: [DEVELOPMENT](../../docs/DEVELOPMENT.md), критерии доказательств — [QUALITY](../../docs/workflow/QUALITY.md). Trace охватывает только поддерживаемые Rust nextest/Playwright-сценарии после native запусков; ручные сценарии требуют отдельного наблюдения.
- Автор разрешил независимое `codex review` для изменений этого репозитория через Codex API, включая незакоммиченные изменения, без отдельного вопроса и промежуточного уведомления при каждом запуске. Перед отправкой проверяй diff на секреты и данные других проектов; если они обнаружены, исключи их из ревью. При новом существенном риске или отказе автоматического допуска объясни причину один раз и продолжи доступную работу.

## Локальное принятие через `highgrade-approve`

- Область коммита определяется принятой задачей и её спецификацией и ревью; посторонние изменения остаются вне него. Перед коммитом выполни проверки из [DEVELOPMENT](../../docs/DEVELOPMENT.md), проверь полный staged diff, лицензию и отсутствие закрытых данных. Рабочие документы и архив готовит work; approve устраняет найденный разрыв. Неудача проверки возвращает задачу в work.
- Разовый переход на v0-2-7 завершён; его условия сохранены в [спецификации выпуска](../../openspec/specs/release-workflow/spec.md), результат — в [записи выпуска](../../docs/releases/v0-2-7.md). К текущим задачам переходная процедура не применяется.
- Для этого исходного проекта вызов `highgrade-approve` разрешает локальную активацию из созданного коммита. После коммита создай изолированную копию его SHA (`git archive` или отдельный worktree), собери `cargo build --release --locked` и запусти **CLI из этой копии**: `<копия>/target/release/highgrade.exe global-update --profile <домашний-каталог> --source <копия>/kit --candidate-exe <копия>/target/release/highgrade.exe`. Сначала preview и смысловая сверка, затем apply с тем же `candidate_sha256`. Установленный CLI прежней версии может не понимать новый манифест. Не собирай из грязного рабочего дерева. Проверка — `global-status`; после успешного postcheck прежние файлы поставки удаляются, при ошибке postcheck CLI пытается восстановить прежний выпуск. После сбоя проверь фактическое состояние по [процедуре Update](../../kit/procedures/update.md#повтор-и-ошибки). Если активация не прошла, коммит остаётся, а статус задачи частичный. Вызов approve не разрешает GitHub push.

## Публикация через `highgrade-push`

- По отдельному поручению отправь выбранный непрерывный диапазон готовых коммитов в `origin/main` репозитория `Lainterus1/HighGrade`. Диапазон может включать несколько задач. До отправки сверь состав, результаты approve, актуальное состояние удалённой ветки и последствия CI; неоднозначный состав покажи автору. Используй обычный push без force и сверь `refs/heads/main` на origin с итоговым SHA. Отправка не доказывает местную активацию каждого коммита; установленная версия определяется только `global-status`. Установленные SVG/CHA и другие проекты не входят в маршрут.

## Полномочия и исключения

- Этот репозиторий поддерживает исходники High Grade. Работа с SNAF, PlantsNotify и другими целевыми проектами выполняется в их каталогах по отдельному поручению.
- Публикация следующих версий, переключение SVG/CHA, деплой и приёмка пилотов требуют соответствующего поручения; прежние выпуски не дают постоянного разрешения на эти действия.
- Согласованных исключений из глобальных правил пока нет; найденный конфликт показывать автору до зависимого действия.
