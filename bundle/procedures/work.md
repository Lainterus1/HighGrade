# Выполнение многоэтапной задачи

1. Установи полномочия, актуальное состояние проекта и главный источник задач: OpenSpec change, если он используется; иначе один технический план. Не заводи второй backlog. Читай AGENTS, документы своей области и нужные требования. При первоначальной адаптации до приёмки выполняй только её этапы и необходимые срочные исправления.
2. Для зависимых этапов веди минимальное состояние: источник, фактическое наблюдение, текущий этап, один `Next`, блокер и ссылки на доказательства. Малую задачу выполняй за один проход без лишнего состояния.
3. Изменяй только порученное. Запускай штатные команды проекта напрямую; High Grade не является общим тестовым runner. Проверяй документацию и контекст, связи, бюджеты, временные обходы, необходимость штатного архива по `procedures/archive.md`. Значимое изменение требует независимого ревью по риску; недоступность проверяющего остаётся незавершённым ревью.
4. Для сценариев OpenSpec используй `trace` из [активного exe и формат записи](../references/cli.md) после native тестов. Отметка на тесте не подтверждает исполнение; провал, пропуск, пустой suite, неизвестный ID и устаревший отчёт остаются явными. Перепроверяй затронутое по влиянию изменения, а не слепо весь проект.
5. Подведи итог с выполненным, командами и результатами, неизвестным и одним следующим действием. Коммитуй локально лишь по выбранной политике проекта и только файлы задачи. Push, развёртывание и пользовательская приёмка — отдельные границы.
