## Соответствие сценариям и причинным входам

- **HG-0019-S1:** lifecycle-тест реально создаёт свой Git-репозиторий, Cargo-программу, kit и UI, строит точный коммит несмотря на грязное дерево, повторяет сборку, проверяет candidate/build-cache/log/work и сохранение кандидата при сломанной компиляции. Временные исходники отсутствуют после успешного и неуспешного действия. Не утверждается активация настоящего пользовательского релиза; исходный отчёт находится вне target
- **HG-0019-S2 / HG-0044-S1:** проверены реальные сравнения байтов до/после preview, совпадение выбранных целей preview/apply, реальная сборка и удаление Cargo build-cache, выбранные scratch/report и сохранение candidate/неизвестных соседей
- **HG-0019-S3 / HG-0044-S2:** проверены внешняя ссылка с sentinel, escape и неправильная смешанная выборка, активная сборка и незавершённые work/recovery. В реализации все проверки предшествуют первому удалению. Наличие активного процесса контролируется test double; ссылка/sentinel и файловая сохранность реальны. Windows junction-ветка в этом Linux-прогоне не выполнялась
- **HG-0043-S1:** прочитанные Spec/Work/verification/QUALITY/DEVELOPMENT единообразно различают нормативное содержание и наблюдение фактического исполнения. Сокращение формулировки DEVELOPMENT сохраняет смысл, не добавляет обязательный пилот редакторской правки
- **HG-0043-S2:** реальные новые Python-результаты сужены по исполненной реализации и самодостаточным данным тестов; чужие Cargo/UI/kit-файлы настоящего проекта эти фикстуры не читают. Версии среды отдельно подтверждены. Общие нормативные rules/task/spec/work и вызванные справочники сохранены. Новый тест действительно выполняет два Python unittest через product spec-run; собственная реализация/тест делает stale только свою область, общий модуль/runner/config — обе, соседний документ/манифест — ни одну. Изменение определения shared_inputs делает свой run stale без удаления прежних runs
- **HG-0043-S3:** fix, clear, audit, CONTEXT и docs/README сохраняют единичного владельца повторяемого решения в существующей карточке; задача ссылается на него, реестр не обязателен, планы/архив не выдаются за действующую норму
- **HG-0044-S3:** BUILD/DEVELOPMENT/местная инструкция дают пути, назначение и условия удаления, выделяют specs/issues и постоянные доказательства, фиксируют Nextest и выбор активной CLI/кандидата. Это смысловая сверка маршрута, не воспроизведение чистой Windows-машины

Широкий состав Rust-исходников оставлен консервативно только для реального compiled scope regression. Он не копируется в самостоятельные Python-доказательства или чисто нормативные S1/S3. Неизвестные зависимости не удаляются ради зелёного статуса.
