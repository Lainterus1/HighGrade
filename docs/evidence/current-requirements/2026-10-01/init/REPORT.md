# HG-0010-S2: фактическая адаптация двух изолированных проектов

## Результат и предел вывода

Исполнитель выполнил Init по текущим исходным инструкциям в двух принадлежащих упражнению временных проектах. В пустом проекте подготовлены минимальные владельцы знаний, содержательное **предложение** местной инструкции, реестр, survey и предметный черновик HG-0001. В проекте с собственной документацией все 6 исходных файлов сохранены байт-в-байт; сохранены предметные правила, существующие владельцы и отдельная ответственность местного навыка. Неизвестные команды и бюджеты не выданы за проверенные. Новая инструкция нигде не помечена принятой автором.

Это **manual, source-guided agent exercise**, а не автоматическое обнаружение установленного `$highgrade-init`. Исполнитель прочитал фактические `kit/skills/highgrade-init/SKILL.md`, `kit/procedures/init.md` и вызываемые справочники, затем реально прочитал/записал файлы и вызвал CLI. Скрипты здесь — сохранённые инструменты исполнения решений агента и регистрации исходов, не тесты, которые заранее записывают ожидаемый исход как наблюдение. Дополнительная независимая проверка доказательства выполняется координатором; survey-review ниже сделан самим исполнителем и не объявляется независимым ревью.

Упражнение подтверждает ограниченный исход HG-0010-S2. Оно не подтверждает установленный skill-dispatch, пользовательский production-пилот, human acceptance, commit, активацию, публикацию, Windows или незапущенные будущие продуктовые сценарии. HG-0010-S3/S4 и уточнения HG-0063 отдельным PASS не объявляются.

## Контекст, входы и повторяемость

Общий прочитанный контекст использован для обоих случаев без повторного массового чтения. Повторное чтение в CLI нужно для CAS текущего survey/spec, а не для имитации нового чтения инструкции. Процедура init была прочитана дополнительно к generated SKILL один раз для сверки точного источника; это намеренная избыточность упражнения, не свидетельство автоматического context reuse установленного runtime.

`claim-inputs.json` перечисляет причинно значимые материалы. Общие `kit/rules.md`, Init, task/spec и реально использованные audit/survey/specification/diagnostic references входят; чужие этапы commit/push/planner и весь kit/manifest без причинной связи не включаются. Шаблон INSTRUCTIONS использован как перечень существенных полей, не скопирован как принятая инструкция. Шаблон survey/CLI-схема определяли формат данных, не ожидаемый исход поведения.

Для повторения восстановить отдельные пустые каталоги из before-снимков, передать тому же или новому исполнителю fixture-intent и закреплённую Init-инструкцию, предоставить совместимую CLI и наблюдать реальные действия. Не запускать фазовые скрипты поверх completed survey: потребуется новый каталог. Фазовые скрипты и raw-история показывают этот конкретный прогон, а не универсальный автономный Init-runner. Сборка кандидата, независимый повтор и установленный skill-dispatch требуют отдельной проверки.
