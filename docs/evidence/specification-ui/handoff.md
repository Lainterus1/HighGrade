## Проверка человеком

1. Откройте локальный UI: слева обращения и спеки, справа исходные цель/требования/сценарии. Старые неподдержанные структуры учитываются отдельно, без миграции и пересказов.
2. На новой незавершённой тестовой спеке измените цель/условие, сохраните, перечитайте через CLI: значение совпадает. Отмена оставляет документ прежним; одновременная внешняя правка требует сравнения.
3. Откройте обращение «Согласовать требования»: оно согласует содержание и не запускает работу. Для «Принять результат» укажите проверенную версию выше; возврат требует комментария. Решение запишется только после вашего явного действия.
4. В Storybook проверьте основы, иконки, компоненты и состояния. Истории изолированы от каталога проекта и не являются записью реальных спек.

Интегрированные требования защищены от перезаписи; новые требования оформляются связанным изменением. Согласованное пользователем оформление не заменяет приёмку всех шести результатов. Установка/обновление/восстановление проверены во временном профиле; публикация, внешний пилот и CI не выполнялись.
