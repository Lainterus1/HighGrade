# Сверка требований после корректировок UI

Согласованное поручение пользователя: актуализировать требования по уже выполненным корректировкам. Создана HG-0058 как одно связанное изменение: HG-0054–HG-0056 интегрированы и исторические спеки не переписываются.

| Требование | Уточнение |
|---|---|
| HG-0054-R1 | Компактная широкая композиция, типографика, состояния элементов |
| HG-0054-R4 | Демонстрации компактного состава без раздела зависимостей |
| HG-0054-R6 | Три значка операций, цветовые метки, служебные подписи |
| HG-0055-R2 | Цель/требования/границы/готовность, скрытые разделы, исходный текст |
| HG-0055-R3 | Короткий блок решения, отсутствие дубля статуса, подпись неизвестного |
| HG-0055-R4 | Последний выбор, отмена ненужного чтения, контекст и актуальность |
| HG-0056-R1 | Разрешённые поля, then и сохранность скрытых данных |
| HG-0056-R4 | Компактная приёмка при сохранении автора/версии/CAS |

Сохранены прежние ID требований и сценариев, добавлены HG-0058-S1–S4 с воспроизводимыми наблюдениями. Новые API, серверный cache, автозаполнение версии/автора и popover диагностики в объём не включены.

Запись: совместимый CLI-кандидат target/release/highgrade.exe, spec-new → spec-read editable → spec-edit с CAS и validate → spec-validate. Проверка каталога: из прежних JSON изменён только catalog.json; добавлен changes/HG-0058/spec.json. Все прежние specs/changes и requirements побайтно сохранены.

Прежние отчёты остаются историческими доказательствами своих редакций. Evidence, review и acceptance не копировались; задачи подтверждения новой редакции открыты. spec-validate подтверждает структуру, а не выполнение. Канонические requirements обновятся только при отдельной подтверждённой интеграции HG-0058.

Проверка общей установки вернула RootInvalid: Отказано в доступе (os error5); глобальная установка не изменялась. Коммит, интеграция, активация, публикация и новая приёмка не выполнялись.

Независимое смысловое ревью review_ui_refinement: REVIEW_GO после уточнения HG-0055-S6, HG-0056-R1/S3/S8. Повторный spec-validate и diff-check пройдены. Ревью подтверждает согласованность контракта, не техническую готовность новой редакции.
