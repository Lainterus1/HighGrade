# Актуальность результата от запуска до окончательной проверки

## Проблема и критерии до исправления

На c561dba prepare принимал старый JUnit после изменения kit, изменения src с восстановленным mtime и удаления src. Также принимался дрейф во время теста до записи отчёта. Причины: неполные закреплённые входы, проверка сохранённых хешей только при changedSpec и отсутствие снимка до запуска.

Начальная гипотеза: единый before/after snapshot и завершённая попытка закроют разрыв без новой пользовательской стадии. Критерии: изменения байтов/состава входов и during-run drift отклоняются; failed/timeout/interruption не наследуют старый PASS; новая полноценная проверка проходит; эквивалентные metadata и неизменённые доказательства переиспользуются.

## Решение

Существующий `python scripts/verify.py tests` автоматически создаёт snapshot, запускает штатные list/run и завершает ту же попытку. UUID связывает отдельные capture/completion; закреплены kit, bundle, все fixtures и оба protocol scripts. Prepare и окончательный verify проверяют источник, отчёт, inventory и соответствие завершённой попытке. Хешируются именно прочитанные bytes snapshot/completion; их hashes включены в существующий run.source_hashes, поэтому настоящий CLI trace также обнаруживает смену попытки. Сверяется provenance trace.

CLI и schema не менялись. Пользовательский маршрут tests/scenarios сохранён. Перенос неизменённого checkout не требует нового теста: original capture_root/captured_at сохраняются при совпадающих влияющих входах.

## Журнал отвергнутых упрощений

- Ограничиться mtime: не обнаруживает восстановленный timestamp, удаление и дрейф до записи JUnit; отвергнуто воспроизведением
- Snapshot плюс общая mutable completion: старый успешный запуск A мог завершить новую failed-попытку B. Два настоящих orchestration subprocess воспроизвели false-PASS; введены UUID и раздельные записи
- Привязать completed к текущему абсолютному root: лишний rerun при побайтовом переносе; восстановлена прежняя переносимость
- Остановить защиту на complete: независимое ревью дало NO_GO. Новый capture между чтением и публикацией run позволял prepare/trace/verify пройти без текущего completion. Добавлены привязка manifests и окончательная проверка. Старый raw NO_GO сохранён, а неизменённый repro теперь даёт 1/1/1
- Общий scheduler, длительный lock и новые публичные команды не вводились. Успешное параллельное выполнение одного root не обещается

## Фактические проверки

- Окончательный Nextest: 196/196, 0 skipped
- Python: 36/36, в том числе 17 адресных регрессий. Это отдельный знаменатель от Rust
- Настоящие failed/interrupted subprocess, concurrent late completion и surviving child отклоняются; deterministic interleavings проверяют публикацию и final gate
- Независимый неизменённый repro: prepare / реальный CLI trace / verify = 1/1/1; текущий completion отсутствует
- Trace/reuse/реальный перенос: PASS. Из 249 сценариев 118 автоматических, 131 вне trace
- 431 snapshot input и оба manifest hash актуальны; окончательный run содержит 434 входа
- Spec validation и scale переиспользованы из неизменённой области; fmt, repository, render, inspect и diff check прошли. Inspect не имеет failed/unknown
- Независимое повторное ревью точного patch SHA-256 из index.json: GO; первоначальный NO_GO устранён. Windows CI пока не заявлен

Скорость не улучшалась и не измерялась сравнительно: добавлены проверки целостности ради надёжности. Эти результаты не являются агентным пилотом или человеческой приёмкой.

## Пределы гарантии

Проверка имеет обычную границу наблюдения: после неё файлы могут измениться. Хеши не удостоверяют авторство отчёта и не обнаруживают transient edit→restore между наблюдениями. Частичный JUnit summary parser в source-scenarios остаётся прежним; полный trace→verify обязателен и отвергает retry failures. Отдельная Rust JUnit-правка не является зависимостью этого исправления.

## Доказательства и независимость

Lossless XZ содержит выбранные исходные machine reports, test scripts и patch прежней отклонённой редакции. JSON files[] восстанавливается из content_base64; SHA-256/размеры закреплены index.json. Native-файлы из restore_native_report_files восстанавливаются в target/nextest/highgrade, остальные — в отдельный каталог исходных наблюдений. Для нового запуска используйте новые пути вывода; не перезаписывайте сохранённые доказательства. Служебные абсолютные пути обозначают исходное изолированное окружение. Приватные материалы других проектов и переписка в пакет не входят.

База — c561dba, draft PR #1. Ветка не требует других ночных исправлений. Main, установленная Поставка, release ID, merge и человеческая приёмка не менялись. Точные commit, публикация и CI сообщаются отдельно.
