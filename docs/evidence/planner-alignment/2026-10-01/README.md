В этой среде обычный HTTPS push не имеет учётных данных; ранее проверенные крупные запросы GitHub connector зависали. Эти запросы повторно не запускались. Малые правки и исходные доказательства публикуются обычными Git-объектами; история не удаляется, формат каталога не меняется.

Подготовленный `deferred-evidence-batch.json` — вход поддерживаемой команды `spec-evidence-batch`, а не выполненная запись. Перед его применением нужно повторно сверить исходные входы и отчёты, получить текущий store_sha256 и использовать совместимую CLI. Применимость пакета проверена настоящей командой на отдельной полной копии проекта: [исходный результат](checks/deferred-batch-validation.json). Основной results.json при этом побайтно сохранился. Пакет не обновляет остальные stale-наблюдения и не закрывает S2/S6. Его наличие не является основанием для `ready`, `spec-integrate` или приёмки.
