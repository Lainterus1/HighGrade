# Проверка HG-0051: два маршрута init

Дата: 2026-09-27. Основа: кандидат Поставки 0.3.3; изменена версия пакета, исходники CLI не менялись. Проверены нормативные изменения и представимость состояний через существующую CLI. Поведение будущего агента и создание работающего прототипа не заявляются.

## Нормативная таблица

Метод: чтение изменённых init/task/spec, audit, survey, шаблона INSTRUCTIONS и README; сопоставление с требованиями HG-0051 и изменённым HG-0047-R2.

| Условия | Проверенное правило | Результат сверки |
|---|---|---|
| Пустая папка, намерение неизвестно | Первый смысловой выбор создания/продолжения | Вопрос задаётся; пустота не заменяет намерение |
| Новый проект из шаблона | Сохранность и независимость состояния подключения | Шаблон не объявляется существующим продуктом, файлы не перезаписываются |
| Существующий продукт | Адаптация и начальные спеки только согласованной области | Нет переписывания, обязательного полного аудита или массовой формализации |
| Намерение уже указано | Переиспользование решения с источником | Повторный вопрос не требуется |
| Поручен только анализ/план | Граница записи | Полный результат init не навязывается ограниченному поручению |
| Часть первичных ответов известна | Task выясняет недостающее | Нет повторного опроса и выбора всех библиотек автором |
| Детали будущей реализации неизвестны | Questions соответствующей спеки | Не превращаются в выдуманные факты; не блокируют уже определённую подготовку |
| Неизвестна сама цель | Достаточность основания | Нельзя объявить подготовку законченной без существенного уточнения |
| Небольшая CLI | Структура по ответственности и стеку | UI/deploy/apps/packages не обязательны; тесты могут лежать рядом с кодом |
| Приложение из шаблона | Полезные соглашения сохраняются | Дерево служит примером; косметическая перестройка не навязана |
| Пять ролей документов | Совмещение ролей | Пять отдельных файлов не обязательны, пустые заглушки не создаются |
| Локальный проект / существующий Git | Граница Git/remote | Отсутствие Git не дефект само по себе; git init требует соответствующего поручения; remote/publicity/license/push не выбираются молча |
| Принято создать компонент | Concrete confirmed assertion в adaptation | Подтверждено решение, не факт существования кода |
| Кода ещё нет | Observed confirmed absence с basis | Не подменяется not_applicable; пустые разделы не считаются обследованными |
| Нет файлов до подготовки / после обещанного создания | Bootstrap и итоговая проверка | Исходные findings/коды сохранены; ожидаемое отсутствие отличается от незавершённого обязательства |
| Завершён survey, спека с вопросами | Раздельная готовность | Init не требует продуктовой интеграции, spec-check ready или приёмки будущего продукта |
| Есть ближайшая и следующая спеки | Порядок и зависимости | Tasks упорядочены; первая спека указана в передаче/Next; depends_on только для реальной зависимости |
| Далёкая неопределённая идея | Глубина формализации | Не требуется пустая спека или второй backlog |
| Пользователь позже возвращается к черновику | Task/spec → work | Тот же неинтегрированный ID уточняется; до work разрешаются существенные вопросы выбранной работы |
| Завершён init | Граница результата | Репозиторий и начальные спеки; прототип выполняется отдельно, автоматического запуска разработки нет |

## Наблюдение CLI на изолированных данных

Команда: `python docs/evidence/init-routes/probe.py`. Сохранён исходный результат операций в cli-observations.json; SHA256 исполняемой CLI указан в нём. Подготовлены два временных каталога в target/highgrade/tmp: пустой и с README-sentinel. После наблюдения удалены только принадлежащие проверке каталоги с проверкой абсолютной границы.

В каждом случае непосредственно наблюдено:

1. Inventory показывает исходное состояние. Inspect bootstrap возвращает legacy failed из-за отсутствующих обязательных путей, при validation=passed и adaptation=required; это ожидаемый результат, не общий PASS.
2. Survey сохраняет известные решения, обследованное отсутствие и будущее устройство без фиктивных source_paths. После снимка/сверки план и адаптация технически доступны.
3. Существенная правка сохраняет adapting и делает прежнее ревью неактуальным.
4. Создан нативный каталог и осмысленный образец черновика: известное требование, две задачи в порядке уточнение→выполнение, открытый вопрос. Spec-validate возвращает именно OpenQuestions; spec-check не ready. Пробел не скрыт.
5. После нового снимка/сверки survey завершается; продуктовая спека остаётся незавершённой. Последующее spec-edit уточняет вопрос того же ID и сохраняет задачи.
6. README шаблона побайтно сохранён. Src, Git и приложение не создавались; runner не запускался.

Эти данные доказывают представимость состояний нынешним интерфейсом и сохранность конкретного sentinel. Они не подтверждают готовность реального репозитория, корректность всех команд будущего стека или способность модели выполнять процесс без ошибок. Завершение survey не сертифицирует смысл введённых утверждений. Изменение Rust/схемы и вторая спека не понадобились.

## Достаточность проверок

Source-scenarios check сверяет IDs и существующие связи; новые сценарии нормативные, новых Rust-селекторов нет.
