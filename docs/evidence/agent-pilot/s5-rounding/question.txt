D1 — Как округлять сумму со скидкой до копеек?
Контекст и последствия: README прямо говорит, что правило округления не установлено. На текущем коде `total([0.05, 0.05], 0.10)` возвращает `0.09000000000000001`, а `total([0.05], 0.10)` — `0.045000000000000005`. Разные денежные правила дают разные суммы.
Рекомендую: A, если скидка относится ко всему заказу: сначала рассчитать итог, затем один раз округлить до копеек по HALF_UP. Это сохраняет смысл текущего суммирования позиций, но правило должен подтвердить владелец.
A) Скидка на сумму заказа, итог округляется HALF_UP — для двух позиций по 0,05 ₽ при скидке 10% будет 0,09 ₽; для одной позиции 0,05 ₽ будет 0,05 ₽.
B) Скидка и округление HALF_UP отдельно для каждой позиции, затем сумма — для двух позиций будет 0,10 ₽; для одной позиции 0,05 ₽ будет 0,05 ₽.
C) Скидка на сумму заказа, итог округляется HALF_EVEN — для двух позиций будет 0,09 ₽; для одной позиции 0,05 ₽ будет 0,04 ₽.
Свой вариант: укажите, на каком шаге округлять и как обрабатывать ровно половину копейки.
