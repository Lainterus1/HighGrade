# Ручное наблюдение и граница автоматического trace

Случай: синтетический проект s5, сценарий HG-0016-S3. [Исходные файлы и их SHA](../s5-csv/baseline.json) сохранены до действия. Агент изучил отсутствие правила разделителя и часового пояса, затем [отправил координатору одним сообщением два вопроса](../s5-csv/questions.md) с вариантами и последствиями. Координатор как владелец синтетического проекта отложил решения; [отчёт](../s5-csv/report.md) фиксирует остановку зависимой работы и совпадение SHA четырёх исходных файлов после вопроса.

Наблюдение сохранено как `method=manual`, `outcome=passed` в [снимке результатов HG-0016](HG-0016-results.json). [Точный `spec-check`](HG-0016-check.json) прошёл после независимого ревью. Это подтверждает конкретное действие агента и неизменность входа в данном пилоте, но не превращает его в автоматический тест.

Отдельно выполнена цепочка `source-scenarios check` → `cargo-nextest nextest list/run` → `prepare` → `trace` → `verify` для текущего Проекта. `nextest` выполнил 116/116 тестов; `verify` подтвердил 38 автоматических сценариев и оставил 51 неподтверждённым в структурном trace. Сырые [list](list.json), [run](run.json) и [trace](trace.json) сохранены. В trace у `HG-0016-S3` статус `unlinked`, без приписанного теста и без автоматического PASS. Его ручное подтверждение существует отдельно в results.

Предел: один синтетический агентный проход. `unlinked` в trace само по себе не доказывает результат ручного действия; результат подтверждают исходный снимок, сообщение, ответ владельца, повторные SHA и независимое ревью. Действительные проекты пользователя в пилоте не использовались.
