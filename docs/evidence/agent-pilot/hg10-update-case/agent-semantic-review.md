Источник кандидата — изолированная копия Git SHA `2bf93b6`, зафиксированная и проверенная по archive/manifest в `setup.json`. Собственная сверка подтвердила SHA-256 манифеста `8ae8fce4a825724697bfd6240fd1e4826f58f529a305bf05e78400f2ba344288`, все его файлы, CLI SHA-256 `0353eef50be25d04246a7f40060b84d26288d918ef27c38d21f13ec6e12209bd` и версию CLI 0.2.14. Шесть установленных стабильных маршрутизаторов совпадают побайтово с кандидатом; подробности — `agent-preflight.json`.

Сравнение установленных v0-2-13 и кандидатных v0-2-14 `rules.md` и `procedures/update.md` сохранено в `agent-rules-update.diff`. `rules.md` не изменился. В update.md добавлено уточнение: общее обновление не мигрирует проектные спецификации, CLI для каталога v3 проверяется отдельно, `spec-migrate --to directory` требует отдельного разрешённого проектного действия, а откат общей CLI не откатывает формат проекта. Это согласуется с ограничением пилота: никакие проекты не трогаются и миграция не выполняется.

Preview `agent-good-preview.json` вернул `status: unknown` только с `SemanticReviewRequired`; это ожидаемое требование смысловой сверки, а не успешное применение. Он зафиксировал `candidate_sha256` `809f915dad34754ab5e6b1d6c05d239331833fbe79753e5ecfb0e17a77121713`. После указанной сверки применение ровно этого кандидата к изолированному профилю разрешено входным поручением. Если apply вернёт ошибку/unknown, фактическое состояние нужно сразу проверить сохранённой старой CLI и остановить зависимые действия.
