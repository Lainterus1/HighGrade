# Проектная инструкция High Grade

Это локальное подключение синтетического расчёта заказа. Язык авторских документов, планов и отчётов — русский по [правилам проекта](../../AGENTS.md). [README](../../README.md) владеет назначением и действующим правилом результата для существующих входов.

## Действующие источники

- [Архитектура](../../docs/ARCHITECTURE.md) описывает модули, модель и данные; [инженерные соглашения](../../docs/ENGINEERING.md) — правило изменений; [разработка](../../docs/DEVELOPMENT.md) — команду и границы проверки.
- [Стратегия проверок](../../docs/test-strategy.md) отдельно владеет выбором сценариев. [Карта прежнего руководства](../../docs/project-guide.md) сохраняет входящие ссылки после разделения его трёх разделов и не является вторым владельцем правил.
- [PLAN.md](../../PLAN.md) и [test-results.txt](../../test-results.txt) — история завершённой технической перестройки, не действующее новое требование. [Реестр](documents.json) задаёт роли, области чтения и бюджеты.

## Маршрут и проверки

- Новые изменения поведения оформляй в проектном каталоге [specs/](../../specs/README.md) в нативном JSON High Grade. Прежнего хранилища спецификаций в обследованной фикстуре нет; завершённый PLAN не мигрируется в новое требование. Исправление по неизменному контракту выполняй прямой технической работой с проверками по установленной процедуре task.
- Штатный запуск: `python -B -m unittest discover -v` из корня проекта. Проектный runner для `spec-run` не настроен; запуск прямой. Проверяй оба расчёта и отчёт по [профильной стратегии](../../docs/test-strategy.md). Структурные `doctor` и `inspect` не подтверждают поведение.
- Пересекающихся местных навыков в обследованном списке файлов нет. Теги и дополнительные runner не согласованы, поэтому не созданы.

## Полномочия и неизвестное

- Для этого пилота разрешены локальная адаптация s2 и проверки. Коммит, публикация, глобальное переключение и активация не разрешены. Общее право на будущие коммиты, пользовательская приёмка и её условия неизвестны; локальные тесты не являются такой приёмкой.
- Принятое местное исключение для этой синтетической области: пока runner `spec-run` не настроен, проверка проводится прямым `python -B -m unittest discover -v` по документу разработки. Само по себе это исключение не разрешает пропуск новых обязательных проверок.
- Бюджеты документов и маршрута не согласованы и остаются `null` в [реестре](documents.json). Это открытое решение, а не успешная проверка размера.
- Внешняя эксплуатация и способ её активации не установлены. Прежнее руководство сообщает об отсутствии отдельной сборки, развёртывания и внешнего CI в обследованной фикстуре; это не утверждение о системах вне неё.
