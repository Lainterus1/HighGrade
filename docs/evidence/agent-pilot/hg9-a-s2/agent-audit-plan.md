# Аудит и план адаптации s2 до изменений

## Проверенный вход

Полномочия и входные SHA-256 — в [setup.json](setup.json), побайтовые копии — в [before/](before/). Сверка всех 14 исходных файлов с обеими сторонами дала `all_match: true` ([agent-input-verification.json](agent-input-verification.json)). Повторный `inspect --bootstrap` структурно завершился `failed`: пять канонических путей и пять входящих связей отсутствуют; для них `not_found_in_scan`, но это не доказывает отсутствие содержания. [agent-bootstrap.json](agent-bootstrap.json), [agent-inventory.json](agent-inventory.json), [agent-initial-commands.json](agent-initial-commands.json) сохраняют результат. Предварительный `doctor` даёт `unknown`, местная инструкция ещё не создана.

Прочитаны существующие `AGENTS.md`, `README.md`, `PLAN.md`, `docs/project-guide.md`, `docs/test-strategy.md`, шесть исходных модулей расчёта и загрузки, оба файла тестов, `orders.json`, исходный `test-results.txt`. Обзор структуры охватывает s2 через inventory; материалы `evidence/hg9-a/before/` служат снимком, а не активными правилами. Других продуктовых каталогов в исходном inventory нет. Это аудит подключаемой синтетической области, не реального проекта и не внешних интеграций.

`README.md` задаёт действующее правило: для существующих входов результаты `quote.py` и `receipt.py` после скидки сохраняются. Код реализует целочисленную формулу `sum(prices) * (100 - discount_percent) // 100`; оба публичных расчёта зовут её. `order_loader.py` строит неизменяемые `Order`, `order_report.py` возвращает список строк с `id`, `quote`, `receipt`; существующие тесты покрывают фикстуру, округление, крайние целочисленные случаи, модель и отчёт. `PLAN.md` — уже закрытый технический план с `REVIEW_GO`, не новый нормативный контракт. `docs/test-strategy.md` владеет выбором проверок и прямо отделяет его от команд и устройства. `docs/project-guide.md` — найденный по содержанию смешанный источник всех трёх канонических ролей, хотя bootstrap не предложил его как кандидата.

## Разрешённое выполнение и проверки

Сохранить текст и смысл правила расчёта, код, тесты, `orders.json`, завершённый `PLAN.md` и прежний результат тестов. Разнести содержание смешанного руководства по пяти ролям, при этом профильная стратегия остаётся отдельной. Создать проектное `specs/` штатным `spec-init` без новой спецификации требований: текущая работа только организационная, контракт не меняется. Теги и runner не добавлять без согласованного применения; прямой тест запускается `python -B -m unittest discover -v`. После изменений выполнить `doctor`, обычный `inspect`, тесты и проверку ссылок; сравнить итоговые SHA и diff. Структурный `doctor` не означает смысловую готовность, а `BudgetNotAgreed` остаётся `unknown`. Коммит, публикация, сеть, глобальное переключение и человеческая приёмка не входят в разрешение.
