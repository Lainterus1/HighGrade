# HG-0063: локальный кандидат Commit / Push

База: `69e1c098b4ca5552b1f3b1ffe66ee808d8d81ab7` (`origin/main` проверен GitHub connector). Изолированная ветка: `feat/portable-commit-push`. HG-0062/ветка Update не изменялись. Это локальный кандидат, не опубликованный выпуск и не пользовательская установка.

## Область

- Канонические `highgrade-commit` и `procedures/commit.md` вместо Approve; актуальные инструкции, ссылки и generated skills согласованы. Исторические записи не переписаны
- Work → Commit-кандидат → разрешённый Push/PR → Work допускает обязательный удалённый CI после отправки. Pre-submit и финальная готовность разделены без изменения readiness/fingerprint кода CLI
- «Активируй» не означает принятия. Release ID, активация, Git, ветки/PR и правила идентичности после squash/rebase задаются проектом
- Init собирает/сохраняет нужную адаптацию из существующих источников, а неизвестное ограничивает зависимый шаг; принятые инструкции не перезаписываются молча
- Журналируемый Approve безопасно заменяется Commit. Старые Deploy-форматы сохраняют прежние гарантии. Новая транзакция различает обновлённые, введённые и удаляемые маршруты; explicit recovery не удаляет пользовательские правки

## Проверки и пределы

[checks.json](checks.json) хранит команды, время, длительность и коды итогового локального прогона; рядом лежат исходные отчёты. [Нормативная матрица](decision-matrix.md) подтверждает содержание правил, а не поведение модели. Фактические агентные упражнения и исходные снимки находятся в [pilots/2026-10-01](pilots/2026-10-01/).

Native Nextest использует реальную CLI/файловую систему и изолированные профили; это не пользовательский пилот обновления профиля. Windows-only проверка блокировки файла не исполняется в Linux и не помечена общим source-scenario marker: нынешний scanner не различает cfg(windows). Четыре переносимых S11-теста проверяют реальные сбои/прерывания/восстановление; Windows-расширение остаётся самостоятельным незапущенным здесь CI-тестом. Hosted CI, настоящий PR, merge, release, deploy и установка в профиль пользователя не выполнялись. В агентных упражнениях удалённый Git — локальный bare-репозиторий, CI/PR при наличии явно симулированы; навык передан агенту из временной установки, автоматический dispatch не проверен.

При подготовке были выявлены и исправлены: отсутствующий PATH Cargo в первом Python-прогоне; отсутствие UI в первом сборочном кандидате; пропуск постпроверки разрешённого автодеплоя в тексте; выбор совместимой CLI для восстановления новой rename-транзакции. После влияющих правок проверки повторялись. Временные символьные ссылки на общий build/report cache были заменены собственными обычными каталогами, поскольку trace правильно отклонил symlink-путь. Итоговые отчёты не основаны на этих неуспешных попытках.

Человеческая приёмка не записывалась. Техническая готовность определяется фактическим `spec-check`, а не количеством успешных тестов; незакрытые сценарии и обязательный внешний CI остаются отдельным остатком.

## Объединение с HG-0062

HG-0062 существует в отдельном неопубликованном коммите `4cd1324885a4482e0b57ece693735a389c3e9f29`. У задач нет пересекающихся requirement ID; HG-0063 выделен CLI с compatibility `--id` специально для предотвращения известной коллизии.

При последующем **разрешённом** объединении:

1. Сохранить обе записи changes/requirements/results и общий `next_number` не ниже 64; не выбирать одну версию каталога целиком
2. В `kit/procedures/update.md` сохранить новую ссылку на Commit, уточнение совместимой CLI rename-recovery и более полный маршрут Update из HG-0062
3. Сохранить генератор HG-0062, затем заново выполнить `python scripts/render-skills.py`: generated Update skill и `kit/manifest.json` не объединять выбором одной стороны
4. Повторить актуальные проверки и ревью на объединённом составе. Доказательства двух отдельных веток не подтверждают объединённый кандидат автоматически

Версия `0.3.6` / `v0-3-6` намеренно не повышалась: выпуск и активация не поручены. Такой рабочий кандидат нельзя подставлять вместо уже существующего неизменяемого выпуска с тем же ID. Новый выпуск, его точный SHA, версия и установка требуют отдельного разрешённого маршрута.
