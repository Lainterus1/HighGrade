# HG-0063: независимое ревью локального кандидата

Дата: 2026-10-01T06:31:59Z. База: `69e1c098b4ca5552b1f3b1ffe66ee808d8d81ab7`; оценивается незакоммиченный состав HG-0063 в изолированной рабочей ветке. Это техническое ревью, не решение пользователя.

## Вердикт и границы

**NO_GO для полного завершения HG-0063.** Не подтверждены настоящие Goal-сценарии HG-0020-S6/S7 и обязательные hosted Windows/Ubuntu проверки точного публикуемого SHA. Тест Windows file-lock не выполнялся в Linux. Эти пробелы нельзя закрыть нормативной матрицей, локальным bare remote, симулятором CI или переименованием статуса.

**GO по реализации и локальному pre-submit кандидата** на зафиксированных ниже исходниках: блокирующих дефектов изменённого кода и нормативного маршрута после исправлений не найдено. Финальная регистрация замороженных пилотных отчётов независимо сверена: 32 записи evidence, 30 passed и ровно два unknown Goal; все закреплённые файлы доступны и их хеши совпали. Отсутствующая пользовательская приёмка сохранена пустой. Проверка конкретного выбранного индекса перед коммитом остаётся отдельным обязательным шагом Commit. Незавершённые финальные критерии должны остаться явными, без spec-integrate/result/accepted и без заявления о полностью завершённом Work.

Разрешения на commit, push, PR, merge, release или применение в профиль пользователя из ревью не следуют. Полномочия определяет исходное поручение. Версия 0.3.6 не повышалась; рабочий кандидат не заменяет неизменяемый существующий выпуск с тем же ID.

## Что проверено независимо

Прочитаны README, AGENTS, местная инструкция, ENGINEERING/DEVELOPMENT и метод `kit/references/review.md`; сопоставлены все операции HG-0063 с затронутым diff, новыми файлами и исходными результатами. В область вошли:

- Переносимый Work → Commit → Push/PR → Work: local pre-submit отдельно от поздних remote final gates, сохранение pending/failed/unknown и разрешений
- Solo Git без навязанного release/активации; noGit без git init; точный build/artifact ID и прежние readiness/fingerprint/CAS барьеры приёмки
- «Активируй» отдельно от принятия; SHA1 → запись решения → разрешённый metadata-only SHA2; исторический verified_revision и сравнение результата после squash/rebase/merge
- Init → проектный шаблон → последующие Commit/Push: reuse известных ответов, проектные ветки/base/PR, side effects и права, конкретный upgrade gap без молчаливого изменения правил
- Права autodeploy: остановка до разрешения эффекта/среды, наблюдение фактического deploy для отправленного SHA и запрет повторного deploy ради проверки
- Выбранный состав и доказательства передачи: Work без поручения передачи не получает новый барьер; Commit сверяет индекс, Push — отправляемые SHA
- Canonical highgrade-commit и отсутствие штатного Approve-алиаса; generated skills согласованы с процедурами, manifest актуален, текущие ссылки разрешаются
- `src/global.rs`: распознавание прежних journal-layout, владение и конфликты путей, before/after/introduced/retired, сбой staging/pointer, recovery до/после переключения, сохранность пользовательских байтов и старых транзакций

Изменён единственный runtime-файл `src/global.rs`. Код принятия/fingerprint/readiness в `src/specs/` и обработка attention не изменены; нормативное разрешение кандидата не превращено в обход CLI-защит.

## Исправленные замечания

1. HG-0063-S3: первоначальный Push не задавал явную проверку фактического autodeploy и запрет повторного запуска ради проверки. Оба правила добавлены; процедура, generated skill и manifest повторно сверены
2. Rename-recovery: прежняя CLI использует deny_unknown_fields для старого журнала и не знает нового Commit-набора. В Update/installation добавлен узкий маршрут той же проверенной CLI кандидата; отказ старой CLI по формату не объявляется повреждением. Незавершённое восстановление сохраняет журнал и останавливает зависимые изменения
3. Trace S11: Windows-only дополнительный lock-тест ошибочно связывался с переносимым сценарием и давал unknown в Linux. Нормативный сценарий явно назначает четыре переносимых теста; их метки сохранены. Только метка Windows extension заменена пояснением, сам тест и его Windows запуск сохранены. Новый полный capture/Nextest/trace выполнен; неизвестное Windows-наблюдение осталось в unexecuted.json
4. В новых HG-0063 операциях HG-0020-S8/HG-0048-S2 приведено canonical имя Commit; исторические файлы и результаты не переписаны
5. Пилотная provenance уточняет фактически установленный manifest 5b9db4… и более поздний исходный 81e830…: отличаются только Update/installation recovery-документы и generated Update. Commit/Push/Init/Work входы пилотов побайтово совпадают с текущими
6. Для native evidence расширен явный охват компилируемых Rust-модулей, кандидата, build/toolchain/runner и retained embedded UI; один неизменяемый файл snapshot не подменяет зависимость от живых исходников

## Достаточность входов и предел наблюдения

Для installer-сценариев 258 прямых входов охватывают весь компилируемый src, build/dependencies/toolchain, конкретный test/support, все поставляемые kit-файлы, runner и оригинальные raw artifacts. `native/embedded-ui.tar.gz` сохраняет ровно 119 файлов, действительно встроенных build.rs; каждый хеш сопоставлен с исходным pre-run attempt. Manifest архива и сам архив закреплены в evidence. Tracked UI source/config отмечены как происхождение сборки, не замена реально использованных dist-байтов.

Исторические профили в runtime-тестах синтетические; реальная пользовательская установка не менялась. Пилотный актор продолжал один контекст между отдельными фикстурами, поэтому это не независимые clean-context повторения. Автоматический dispatch не проверялся. Ранние английские ответы и отдельная подсказанная русская коррекция сохранены раздельно. Публичные сокращённые журналы явно маркированы выдержками; проектные входы/полномочия/команды и результаты сохранены, неизменённые оригиналы не выдаются за эти выдержки.

Не исполнялись hosted PR/CI, настоящий production deploy, squash/rebase-пилот, пользовательская активация, приёмка native результата или настоящий Goal. Для HG-0063-S1–S7 нормативный метод назначен самим контрактом и не требует подменять его такими прогонами. Для Goal S6/S7 фактическое исполнение обязательно и остаётся пробелом.
