# Местная инструкция High Grade

## Основание и владельцы

Минимальная адаптация существующего проекта по явному поручению пользователя от 2026-10-01. Область — весь маленький проект; сохранить продукт, исходники, MIT-лицензию, проверки и Git-историю. Новые материалы, планы и отчёты — по-русски. Технические ID и исходные машинные сообщения не переводятся.

[README](../../README.md) владеет назначением, архитектурой, инженерными правилами, командами и хранением доказательств. [AGENTS](../../AGENTS.md) задаёт вход агента и полномочия. [Реестр](documents.json) фиксирует роли/области; [survey](survey.json) хранит историю подключения, решения, проверенные источники и ограничения. Контекстные бюджеты неизвестны до решения автора; null не означает отсутствие ограничения.

## Задачи и проверки

В исходном проекте нет каталога спецификаций и сформулированных новых продуктовых требований. При Init фиктивные спеки и spec ID не создаются; продуктовая реализация не выполняется. Для последующих задач сохраняй один основной источник поручения/требований. Новые устойчивые требования идут через task/spec установленной Поставки, технические задачи при неизменном контракте через work. Наличие spec ID не требуется для простой технической задачи. Массовая формализация и миграция прежнего содержания не назначены.

Штатная проверка, формат отчётов и их хранение: [README, команды](../../README.md#команды-и-доказательства). Обязательное ревью определяется процедурой work и риском изменения; собственную проверку не выдавать за независимое ревью. Местных дополнительных навыков и конфликтующих маршрутов не обнаружено.

Исходное расхождение starting/ready подтверждено [проверкой](../../evidence/init-baseline.json). Подключение не исправляет его и не утверждает продуктовую готовность. Следующий продуктовый шаг требует отдельного поручения и сверки ожидаемого поведения; повторная реализация по умолчанию не начинается.

## Сопровождение

Ниже адаптирован маршрут исходного README; команды сами не дают полномочий.

- Git применим: существующий репозиторий сохранён. Выбирать только файлы/участки порученной задачи и обязательные evidence; неизвестное и чужое сохранять вне коммита, не сбрасывая чужой индекс. Не применять без разбора git add -A/reset/stash
- Pre-submit до candidate commit и push: успешная python3 tools/check.py, актуальные входы доказательства и применимое ревью. Успешные неизменённые проверки повторно не запускать. Упавший обязательный локальный тест не позволяет считать кандидата готовым к отправке
- Финальная техническая готовность дополнительно требует удалённого CI со статусом passed для точного отправленного SHA. Источник/команда CI пока неизвестны и недоступны: это блок финальной готовности, но не независимой локальной проверки или разрешённого candidate commit после pre-submit. Pending/failed/unknown CI возвращает продолжение в Work; не подменять его ready, result, accepted или интеграцией требований
- highgrade-commit по отдельному поручению создаёт только выбранный локальный коммит; допустим кандидат с явно незакрытым remote CI. Не требуется заранее закрывать неизвестный CI фиктивным результатом. Локальная активация не используется; номер выпуска и release ID не нужны. High Grade global-update не является командой активации проекта
- highgrade-push по отдельному поручению отправляет явно выбранный непрерывный диапазон в origin, candidate branch feature/ready. Remote уже настроен на локальный bare-репозиторий; перед отправкой проверить актуальный URL и удалённый SHA. Обычный push без force; после него проверить SHA ветки и доступный CI именно для него
- Перед интеграцией обязателен PR: head feature/ready, base integration. Создание PR, merge, tag/release и deployment не следуют автоматически из commit/push и требуют отдельного поручения. Hosted PR/CI-сервис сейчас не подключён; это ограничение соответствующих будущих действий. По README push не запускает автоматический deployment
- При squash/rebase/merge сверить фактические деревья, значимые входы и обязательные проверки нового SHA; сохранить связь с проверенной редакцией в отчёте задачи. Существенный дрейф требует новых проверок и человеческого решения. Исторический verified_revision вручную не заменять и не приписывать человеку проверку другого SHA
- Результат принимает автор только явным решением по точной проверенной редакции; тест, commit, push, CI и активация не являются человеческой приёмкой. Вызов «активируй» сам по себе приёмку не выражает

## Проверка подключения и продолжение

Обычный inspect по documents.json проверяет принятые роли и ссылки; doctor подтверждает только совместимость схемы. Legacy-поиск cargo/openspec не создаёт потребности устанавливать их в Python-проект. Survey-check удостоверяет структуру/снимок/запись собственной смысловой сверки, а не человеческую приёмку или корректность продукта.

Первой продуктовой спеки нет, поскольку нового требования не дано. После Init остановиться: рекомендуемый следующий шаг — получить конкретное поручение на разбор starting/ready либо другую задачу, затем task/work или task/spec/work по её смыслу. Git-коммит, публикация и продуктовая реализация в текущее поручение не входят.
