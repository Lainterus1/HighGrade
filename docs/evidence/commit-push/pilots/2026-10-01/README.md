# Изолированные упражнения Commit/Push, 2026-10-01

## Что это доказывает

Это настоящие действия агента над синтетическими проектами: выполненные команды, Git-коммиты, отправка в временный локальный bare remote, чтение точного SHA для игрушечной активации и наблюдение файлов после действий. Установленные generated skills переданы явными путями как контекст. Автоматическое обнаружение/dispatch навыков не проверялось. Внешняя публикация, пользовательская установка, hosted PR/CI, merge, release и production deploy не выполнялись.

HG-0063-S1–S7 определены как нормативная смысловая сверка. Эти упражнения — дополнительное наблюдение, не переопределение метода их проверки. Основные целевые агентные исходы — унаследованные HG-0011-S1–S8, S11–S12; точная завершённая матрица — в `coverage.json`.

- Установка: `install-frozen.json`, `global-status.json`; release v0-3-6 в отдельном временном профиле, manifest `5b9db4b07e640b91b552a796457ef87aeb984d24e8503d5d90a36bae62c2d1d6`
- Текущий source manifest отличается от установленного из-за узкой правки только Update/recovery; точные три файла перечислены в `provenance.json`. Commit/Push/Init/Work/Planner и шаблон побайтово совпадают; исходы не переименовывались и не повторялись ради несвязанной правки
- Входы: `provenance.json`, `installed-context/sha256.json` и побайтовые копии установленных навыков/правил/документов
- `fixture_harness.py` создаёт игрушечные проекты, реально запускает первоначальную Python-проверку, сохраняет snapshots и независимо читает Git/файлы после работы
- В каждом случае: `prompt.txt`, `before/` и `after/`, `observed-result.json`; `after/actions.project.jsonl` (либо неповреждённый `actions.jsonl`/`actions.txt`) содержит проектные команды, stdout/stderr и код выхода. Непроектные указания о маршрутизации отчёта исключены из публичных выдержек и явно маркированы; оригиналы не переписывались. Git-история сохранена в bundle, индекс отдельно, проектные файлы в tar.gz; исключённые raw audit members перечислены в snapshot-exclusions.json
- `observe_results.py` собирает независимые наблюдения; он не переписывает native results и не объявляет человеческую приёмку

## Пределы и неудачные подготовки

Первый clean-context актор остановился на дефекте фикстуры: в местной инструкции отсутствовал schema header. Его вывод и снимки сохранены в `solo-invalid-schema/`. После исправления инфраструктуры проекты пересозданы, исходные задания и входы проверки сохранены по смыслу. Успешный повтор и последующие изолированные проекты выполнены одним продолжающим актором. Поэтому положительные исходы не называются независимыми clean-context повторениями.

Первоначальные отчёты первых семи случаев были на английском при русских запросах. Они сохранены без замены; русская исправленная передача выполнена отдельно по замечанию проверяющего и маркируется как подсказанная коррекция. Это ограничение соблюдения языка/передачи, а не изменение наблюдаемых Git-действий. Первоначальные отчёты занимали 98–135 слов в первых шести случаях и раздельно показывали проверки, фиксацию, активацию, публикацию и приёмку.

Активация — реальная запись игрушечного локального состояния из `git show SHA:app.py`, а не установка продукта High Grade. В случае ошибки код 23 введён фикстурой перед переключением состояния; никакая гарантия автоматического отката не выдумывается. Активация по слову «активируй» проверяется на проекте без native spec: отсутствие записи приёмки и разделение отчёта наблюдаются, но барьер native `spec-decide` этим случаем не проверяется.

Состояния PR/CI и последствия production описаны фикстурами. Остановка перед неразрешённым объявленным автодеплоем наблюдается на настоящем локальном Git remote, но не является выполнением настоящего deploy. CI pending берётся из локального симулятора, не из hosted CI. Для настоящей публикации и удалённых проверок нужны отдельное поручение и доступы.

## Дополнительный установленный CLI

`catalog-survival/` содержит реальный цикл installed CLI: spec-init → spec-new → spec-edit → spec-list → spec-validate → два одинаковых spec-check → удаление служебной конфигурации из корня → spec-read. Удаление выполнено переносом `.highgrade` в соседнюю временную папку, сохранив резервную копию. Чтение после удаления прошло; хеши каждого файла specs/ не изменились. Структурная валидация прошла, техническая готовность честно осталась failed из-за незакрытой задачи/evidence/review. `catalog-snapshot/` — настоящий русский native JSON, а не выдуманный пример.

Первый CLI-подход с абсолютным путём patch за пределами проекта был отвергнут `UnsafePath`; его исходы сохранены в `catalog-survival-first-invalid-input/`. Исправленный ввод расположен внутри проекта и передан относительным путём. Этот случай — runtime-срез HG-0004-S3, не агентный dispatch и не полная приёмка всей процедуры Init.

## Воспроизведение

Пути целевых временных проектов заданы в `fixture_harness.py`. Для нового прогона используйте новую пустую базу либо сохраните и удалите только принадлежащие прошлому прогону фикстуры. Установите проверяемую CLI/kit в отдельный существующий профиль командой из install report; не используйте пользовательский HOME. После `fixture_harness.py prepare` передавайте соответствующий `prompt.txt` актору вместе с установленным навыком; ожидаемые результаты ему не передавайте. После каждого ответа вызывайте `fixture_harness.py snapshot NAME after`, затем `observe_results.py`. Не выполняйте реальную внешнюю публикацию вместо локальных remotes. Команды и выходы наблюдателя доступны в сохранённых артефактах; пересоздание коммитов даёт новые SHA и не должно подменять исходные наблюдения.

## Итог дополнительных цепочек

Init завершил настоящее обследование со stage completed / survey-check passed. Он сохранил исходный падающий тест как failed и не изменил продукт. Реально созданная инструкция затем использована в копии проекта: Commit/Push сначала остановился на отсутствующем независимом review, после настоящего GO создал кандидат a4235edc444b8e10662051e0c85423006620ef39 и отправил его в origin/feature/ready. Remote SHA совпал; CI unknown и обязательный PR остались явными критериями Work. Тест не повторялся, готовность/приёмка/merge/активация не выдуманы.

Planner-проверка охватила два реально проверенных этапа alpha → beta: оба evidence переиспользованы, продукт и индекс сохранены, обычный местный plan/state завершён с Next: none. Goal недоступен, goal_tool_id остался null; создание/закрытие Goal не подменялось имитацией. Это подтверждает завершение по разрешённому fallback и границы полномочий; HG-0020-S6/S7 с настоящим Goal остаются unknown.

Сохранённые prompt.txt — проектно значимые выдержки: пользовательское задание, installed skill paths, полномочия и audit boundary сохранены; непроектная маршрутизация отчётов исключена. Это не побайтовая копия всей беседы. public-excerpt-provenance.json фиксирует исходные и публичные хеши, точную область исключения и сохранность оригиналов вне поставляемых файлов. Штатные Git/test/activation команды и их исходы не заменялись.

Основные фикстуры воспроизводит fixture_harness.py; дополнительные Planner и post-Init исходные состояния полностью сохранены в before snapshots. Для воспроизведения именно этих входов восстановите snapshot + историю/index в отдельной песочнице и согласованно замените абсолютные пути; не выдавайте изменённый путь/новый SHA за оригинальный прогон.
