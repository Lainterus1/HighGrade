# JUnit retry не скрывает неудачную попытку

## Проблема и критерии до правки

На c561dba настоящий тест Nextest 0.9.146 сначала падал, затем проходил retry. Процесс завершался с кодом 0, XML сохранял flakyFailure. `spec-run` и `spec-run-import` ошибочно записывали passed; `trace` уже отвергал тот же тест. Причина: первый parser учитывал только failure/error и пропускал четыре retry-тега.

Гипотеза: тот же набор failure/error/retry-тегов, который использует trace, устранит ложный passed без изменения формата и обычных исходов. Критерии: ни один из шести тегов не даёт passed; обычный pass сохранён, skipped/missing/duplicate остаются неподтверждёнными; отвергнутый импорт не меняет каталог.

## Минимальное решение

В checks.rs добавлены rerunFailure/flakyFailure/rerunError/flakyError. Регрессия исполняет настоящий падающий unittest с намеренно нулевым выходом runner и проверяет все теги. Импортная фикстура дополнена проходящим sibling: прежний тест мог отказывать из-за отсутствующего соседа, маскируя ошибку parser. Новые требования не вводятся: восстановлены HG-0004-R2, HG-0034-R1 и HG-0050-R3.

## Фактические результаты

- RED до изменения: явный run возвращал passed; импорт ошибочно принимал negative fixture
- Настоящий Nextest retry после изменения: run failed, evidence unknown, import отклонён как ImportedCheckNotPassed
- Адресные контракты: 68 passed; независимо повторены при ревью
- Окончательный Nextest: 197/197, 0 skipped; полный XML без retry/failure/error/skip
- Python: 19/19; UI build, cargo build/fmt, render, spec validation, scenarios, scale, reuse, repository и diff check прошли
- Trace: всего 249 сценариев — 118 автоматических и 131 вне trace; 197 — отдельное число исполненных тестов
- Inspect: девять прежних ExternalLinkUnchecked, без failed/unknown
- Независимое ревью точного implementation diff из index.json: GO; проверены все 370 привязок run manifest, исходные RED/GREEN, окончательный XML и усиленная импортная регрессия

После упаковки .gitattributes стал новым входом: повторены полный Nextest 197/197, trace 118/118 и reuse. Актуальные исходные отчёты имеют префикс junit-retry-post-packaging-; предшествующие отчёты сохранены как история. Spec validation переиспользована, поскольку каталог не менялся.

Windows CI и browser E2E этой ветки здесь не заявлены. Исторический final-validation.json отражает момент до независимого ревью; его байты сохранены неизменно. Поздний GO описан выше. Снятая конфликтующая сценарная метка не скрывает тест: он входит в окончательные 197, но не выдаётся за новый автоматически трассируемый сценарий.

## Доказательства и повторение

Используйте новые каталоги вывода при повторении, не изменяйте исходные отчёты. Проектные команды — docs/DEVELOPMENT.md; адресные тесты находятся в tests/catalog_contracts.rs.
