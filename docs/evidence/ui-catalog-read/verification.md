# Одно чтение каталога на HTTP GET

Поручение пользователя 2026-10-02: убрать повторную загрузку каталога внутри запроса списка/документа UI. Техническая оптимизация существующих HG-0053/HG-0055; новый продуктовый контракт не вводится.

## Изменение

До: HTTP preflight `catalog()` → specs::load; затем spec-ui/ui_read → повторное load_unlocked. После: ui_list/ui_read вызывают command_inner один раз; проверка отсутствия/старого формата выполняется по загруженному снимку внутри существующей блокировки. Проверка UI-профиля отдельной спеки сохранена. CLI command и HTTP POST продолжают прежний путь. Не введён кеш между запросами, данные всех спек по-прежнему читаются для построения каталога.

## Проверка до реализации

Сохранены before-inputs.json, бинарник и его SHA в identity.json. Узкий новый тест свежести/ошибок прошёл на исходной реализации (before-contract.txt). Это проверка сохранения поведения, а не воспроизведение функционального дефекта. Исходные измерения performance.ts (обычный каталог и 250 спек) записаны в before/ до изменения production-кода. Время: API list 242 мс, API read 185 мс, первое открытие 847 мс на 250 спеках.

## Методика

Тот же benchmark ui/benchmarks/performance.ts и config: Chromium, production UI внутри debug CLI, Linux, один worker, 1440×900; 7 API-чтений и открытий с холодным browser cache, 20 переключений/поисков. Исходный и итоговый прогоны выполняются последовательно без параллельных тестов/сборок. Клиент и данные неизменны. Median/p95 вычислены по исходным samples. Действия включают Playwright/ожидания кадров; inputToPaint означает input→RAF, не физическое появление кадра. Idle — одно наблюдение 11 секунд. Не SLA и не измерение release-сборки/другой ОС.

Команды из ui: `HIGHGRADE_PERF_OUTPUT=../docs/evidence/ui-catalog-read/{before,after} HIGHGRADE_TEST_EXE=<binary> npx playwright test --config benchmarks/playwright.config.ts --grep 'ordinary|catalog'`. Для before — копия target/highgrade/tmp/ui-catalog-read/before-highgrade; для after переменная HIGHGRADE_TEST_EXE не задана, используется target/debug/highgrade.

## Проверки

Новый HTTP-тест на одном работающем сервере проверяет оба GET: missing 404, legacy 422 без миграции, внешние изменения и свежие store_sha256, journal/corruption 422 без исправления данных. Все 6 tests/ui_contracts прошли (contracts.txt), включая профиль, CAS, origins/tokens и прерывание записи. cargo build --locked пройден. Итоговые benchmark: 2 passed. Полный Nextest: 213 passed (nextest.txt; исходный JUnit target/nextest/highgrade/junit.xml). Playwright: 36 passed, 1 installed skipped, 0 failed/flaky (playwright.json). Снимки редактора побайтно равны (visual.json). Trace: 127/127 автоматических сценариев passed, 213 test cases без missing/skip/unknown; 154 сценария вне automatic trace не объявляются выполненными. Структура, skills и inspect проверены; inspect содержит только предупреждения о внешних ссылках. Итоговое ревью и вспомогательные проверки фиксируются ниже.

Коммит, активация, публикация и приёмка не выполнялись. Exact-SHA Windows/Ubuntu CI и installed E2E остаются выпускными пробелами.

## Замеры после изменения

| Медиана, мс | 7 спек до → после | 250 спек до → после |
|---|---|---|
| GET списка | 11.4 → 8.7 | 242.1 → 150.2 |
| GET документа | 10.0 → 6.4 | 185.3 → 95.0 |
| Первое открытие | 104.4 → 95.0 | 846.8 → 339.2 |
| Переключение | 100.0 → 100.0 | 300.0 → 183.4 |
| Поиск | 33.5 → 33.4 | 33.4 → 33.4 |

На 250 спеках медиана списка снижена на 38%, документа — на 49%, первого открытия — на 60%, переключения — на 39%. Это результаты конкретного end-to-end benchmark, не обещание одинакового выигрыша на каждом проекте. Одно чтение вместо двух подтверждено просмотром пути вызовов; тайминг сам по себе не считает чтения. Первое открытие включает браузерные ожидания, поэтому процент отличается от API. Состояние каталога до/после benchmark совпало по хешам; POST не было.

Первые sandbox-запуски scenario-scale/reuse завершились ошибкой пустого JSON; первый reuse также стартовал до завершения JUnit. Эти попытки не считаются успешными; сохранены отдельно. После полного Nextest проверки повторены вне sandbox, результаты в scenario-*-unsandboxed.json.

## Итог

Полная проверка `python scripts/verify.py specs` завершилась с exit 0; trace, scale/reuse, fmt, структура, skills и inspect пройдены (предупреждения внешних ссылок сохранены). Независимое ревью — локальный GO, см. review.md. Финальные причинные входы сверены без дрейфа (completion.json).

Временная копия исходного бинарника удалена после ревью и проверок; SHA сохранён в identity.json. Исходные успешные/неудачные отчёты не переписаны. Выпускные пробелы и статусы полномочий остаются указанными выше.
