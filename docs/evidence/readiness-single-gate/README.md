# Один барьер готовности перед интеграцией

## Проблема и основание

На основе `c561dba` процедуры work/planner/archive и таблица команд требовали отдельный `spec-check` непосредственно перед `spec-integrate`. Действующее требование HG-0030-R1 и подробный справочник уже определяют встроенную проверку готовности в `spec-integrate`. Исполняемый код вызывает тот же readiness до любой записи.

Гипотеза до правки: согласование четырёх формулировок устранит обязательный лишний вызов, сохранив все критерии готовности. Критерии: прямая интеграция готового изменения, отказ при отсутствующем/устаревшем evidence или GO без изменения каталога, сохранение диагностического check и согласованность сгенерированных навыков.

## Решение и гарантии

Четыре исходные формулировки синхронизированы; два навыка и manifest созданы штатным `render-skills.py`. CLI, требования, полномочия и версия не меняются. Предварительный check остаётся доступен для диагностики; check при продолжении, approve, повторной проверке интегрированной спеки и человеческом решении сохранён.

## Фактическая проверка

- Реальная CLI основы: прямая интеграция без отдельного check проходит
- Три отрицательных случая: нет evidence/GO, нет GO при evidence, изменён значимый вход после GO. Каждый отклонён; байты каталога не изменились
- `render-skills --check`, `check-repository`, `git diff --check`: PASS
- `inspect`: только девять прежних ExternalLinkUnchecked; новых failed/unknown нет
- Независимое смысловое ревью: GO точного implementation diff с SHA-256 из index.json. Сверены исходные отчёты, CLI hash, сохранение readiness и генерация

Фикстура детерминированная; её запись GO моделирует данные для проверки механизма, а не человеческую приёмку или независимое ревью. Реальное независимое ревью относится к этой правке. Исполнение workflow агентом и ускорение по времени не измерены. Изменение снимает один обязательный отдельный вызов на интеграцию нового change; это структурный эффект, не измеренное ускорение.

## Доказательства и повторение

`index.json` закрепляет SHA-256 каждого исходного файла и lossless XZ-контейнера. После `lzma.decompress` содержимое является JSON: каждый `files[]` содержит path, sha256 и content_base64. Восстановите base64-байты, проверьте SHA-256 и не редактируйте исходные отчёты. Скрипт `check-readiness-gate.py` сохранён вместе с командами/stdout; для нового прогона задайте путь к проверяемой CLI, новый временный ROOT и новый уникальный LOG. Не перезаписывайте сохранённые исходные доказательства. Абсолютные пути внутри отчётов обозначают исходное изолированное окружение.
