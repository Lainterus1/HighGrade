# Нормативная сверка переносимого workflow

Проверка: 2026-09-26, кандидат рабочего дерева на базе 0330ca2. Источник задачи — docs/proposals/portable-workflow-pilot-followup-task.md; требования HG-0048–HG-0050. Это наблюдение чтения правил и сопоставления контрактов, без утверждения о фактическом поведении будущего агента.

## Подготовка и метод

Прочитаны изменённые процедуры init/work/approve/push, audit, CLI, survey/diagnostics/verification и шаблон INSTRUCTIONS. Сопоставлены пункты задачи, владельцы правил и существующие местные границы. Ниже зафиксированы действие и наблюдённый результат для независимых от пилота случаев. Исполняемые гарантии подтверждаются отдельно JUnit; чтение нормативного текста не заменяет эти тесты.

| Исходные условия | Действие проверки | Наблюдённый результат и граница |
|---|---|---|
| Git с ignored evidence | Прослежены work → approve → diagnostics → push | Проверка состава после подготовки индекса; ignored не считается переданным, index blob сверяется по хешу; выбранный commit сверяется перед push. Нет add-all/изменения ignore |
| Проект без Git, согласованная передача | Прочитан bundle-контракт | Явный список локальных путей; неизвестный состав остаётся unknown. Внешняя доставка и срок хранения проверяются по существующей политике, URL не доказательство |
| Локальная задача без передачи | Сопоставлены work и диагностика | Проверка состава необязательна; локальная готовность/приёмка не становятся публикацией |
| Нет принятого места хранения | Прочитаны init и шаблон | Определяются существующий владелец, обязательные отчёты/невосстановимые входы, срок и маршрут. Обязательного нового документа или внешнего сервиса нет |
| План без разрешения адаптации | Сопоставлены survey и init | plan_ready и mandate независимы; блокер adaptation сохраняется, полномочий из go не выводится |
| Разрешена частичная адаптация, неизвестное независимо | Сопоставлены blocks, other_dependencies и шаги init | Выполняется разрешённая определённая часть; неизвестное ограничивает связанные действия, не удаляется ради оформления этапа |
| Находка во время adapting | Прочитан survey-edit контракт | Фактический этап сохраняется, значимое содержание инвалидирует review; завершение после снимка/go, без выдуманной перемотки |
| Завершённый документ и новый вход | Сверены completed/reopen и версия схемы | Завершённая редакция сохраняется, чтение v1 не мигрирует её; текущая пригодность не выводится из истории |
| Строгий formatter/CI | Прочитан preflight в processes/findings | Охват и владелец сериализации устанавливаются до адаптации; только точные исключения CLI-данных и в пределах поручения |
| Нет formatter/CI | Проверен контрпример audit | Установка formatter, новый CI или новые обязательные поля survey не требуются |
| Короткая правка инструкции | Сопоставлены work и DEVELOPMENT | Смысловой diff и адресные структурные проверки; импровизированный проект/агентный пилот не требуется |
| Штатный запуск использует дочерний инструмент | Проверен init preflight среды | Сначала существующий проектный маршрут; новая среда не устанавливается по шаблону |
| Совпадающие селекторы | Прочитан verification | launch_selector необязателен, прежний selector и хеши сохраняются |
| Разные launch/report идентификаторы | Прослежены конфигурация → запуск → импорт | Значение launch_selector передаётся отдельно и буквально; selector точно сопоставляется в отчёте. Regex задаёт владелец runner |
| Нет реального check при init | Прочитан маршрут настройки | Непроверенная настройка остаётся такой до первой задачи; фиктивная спека и обязательные адаптеры не создаются |
| Exit 0, но skipped/missing/duplicate/failure | Сверен контракт результата | Успех процесса недостаточен; адресные тесты подтверждают отклонение ложного успеха |
| Бюджет известен / неизвестен / принята неопределённость рядом с ошибкой | Сверены diagnostics и survey basis/sources | Числа не выдумываются, unknown остаётся unknown; принятие ограничения проверяется по существующему источнику и не подавляет структурную ошибку |
| Новый результат CLI и старый потребитель | Прочитан именованный интерфейс | Старые measurements/status/коды сохранены; result без неоднозначных ключей. Хеши областей не взаимозаменяемы |

Нормализация байтов в Git может дать index_differs: это явное расхождение закреплённых файлов, а не разрешение переписывать хеши или запускать фильтры.
