## Исправления

- Source-scenarios учитывает создание, изменение и удаление `.cargo/config.toml` и `.cargo/config` в проекте. Новый отрицательный тест воспроизвёл ложное разрешение повторного использования. После исправления он проходит.
- Clear batch отклоняет Windows имена с конечной точкой/пробелом и входы, совпадающие без учёта регистра. Они могли совпасть с защищённым тестом или observer. Сохранены реальные отрицательные и исправленные результаты.
- Смена выбранной спеки в UI отменяет старое фоновое чтение. Реальный браузерный RED удерживал ответ A и не позволял открыть B до release. Тот же сценарий после исправления проходит. Постоянный тест дополнительно ждёт завершения позднего callback.
- Unix Update создаёт временные pointer/router файлы через `create_new`. Чужие `.next` и внешние цели symlink больше не перезаписываются. Реальный тест проверяет все четыре случая: файл/ссылка для pointer/router.
- Усилены существующие assertions: запуск runner только при исполнении, сохранность при каждом отказе transfer, отсутствие утечек токена/частных байтов, точные UI счётчики, old-current и accepted-current проекция, хронология запросов и ID tie-break, окончательное наблюдение quiet reading, отмена GET во время живого retry timer. Реальная ошибка запуска браузера проверяется отдельным Unix тестом с пригодным URL и живым сервером.
- Скриншоты трёх UI тестовых файлов записываются в каталог текущего запуска. 17 прежних файлов `hg58` сохранили байты.

Нормативные поправки внесены через CLI в существующие незавершённые спеки. HG-0063 устраняет оставшиеся approve/Commit термины, уточняет отдельное полномочие plan-only Goal и необязательный внешний build ID при приёмке. HG-0067 исправляет ссылку на архивный план. Задачи, строгие snapshots, ручные методы, история и прежние решения сохранены. Эти цепочки целиком не интегрированы и не объявлены готовыми.

## Реальные мутации и затраты

Выбраны четыре важные реализации нарушения: ложное обнаружение при несовпадающем source witness; продолжение после неизвестной чужой правки; ложный reuse после causal drift; отсутствие Cargo config в снимке. Все четыре обнаружены нужными assertion failures. Baseline и final прошли. Байты и режимы входов восстановлены. Сохранены исходные nested отчёты и отдельные свежие receipts каждого observer command.

Батч трёх helper нарушений использовал 5 верхнеуровневых команд. Батч Cargo config использовал 3. Это не полный счётчик внутренних subprocess. Измеренного отдельного небатчевого контроля для этих трёх нарушений нет. Телеметрии токенов нет. Экономия процентов не заявляется. Мутации проверяют выбранные нарушения, а не процент качества всего проекта.

Все эти батчи fresh-only: `scope_complete=false`, `reused=false`. Копия каталога не является security sandbox. Receipt загруженного кода сама по себе не доказывает завершение; вердикт основан также на исходных framework результатах и нужных assertions.
