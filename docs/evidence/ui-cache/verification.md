# Ограничение кеша и ревью интерфейса

Поручение пользователя: самостоятельно выбрать минимально достаточную оптимизацию памяти и затем провести ревью интерфейса. Выбран LRU-кеш максимум 10 полных снимков; API/список/поиск/дизайн сохранены. 10 — рабочий инженерный предел, не результат измерения heap и не нормативный SLA. Пагинация и переработка API не нужны для этого локального изменения.

## Реализация

NativeWorkspace при показе документа обновляет его место в Map и удаляет самый давно использованный снимок при превышении лимита. Показ кешированного документа обновляет давность так же, как новое чтение. Каждый выбор продолжает проверять актуальность на сервере. Текущий снимок самый новый; черновик принадлежит SpecEditor, а малые записи прокрутки/раскрытия — отдельному places. Вытеснение не удаляет данные проекта.

Лимит ограничивает сохранённые snapshot, но не всю память браузера: остаются полный список, активная форма, временный ответ и состояние навигации. Выигрыш в байтах/процентах или ускорение первого открытия не заявляются.

## Проверка до/после

Начальные before.json / before-cleanup-fixed.json наблюдали кешированный HG-0009 под удержанным GET после обхода более 10 документов. Первый также содержит ошибку teardown; второй её устранил. Ожидание старого h1 было неточным: существующий UI скрывает предыдущий article при загрузке нового документа. Первый after.json: 36 passed, 1 skipped, 1 failed именно из-за этого ошибочного ожидания; не считается успешным финальным результатом.

Окончательный тест ожидает кешированный HG-0008 (повторно использован), отсутствие article и статус загрузки для вытесненного HG-0009, затем фактическую загрузку, сохранность черновика при отказе от навигации, поиск HG-0001 вне кеша и неизменность файлов. Baseline UI восстановлен из HEAD только после сверки SHA NativeWorkspace с before-inputs; остальные изменения дерева сохранены. Изолированная копия бинарника baseline-highgrade собрана, рабочий файл и финальная сборка восстановлены. Окончательный тест на baseline упал именно на отсутствии вытеснения: expected .document count 0, received 1 (baseline-final-test.json). Эта же версия теста выполняется в финальном наборе.

## Ревью интерфейса

Основной агент проверил Storybook в браузере: чтение, переход в редактор и возврат с восстановлением фокуса. Визуально просмотрены native-390/1440, независимо также native-720, desktop/narrow/zoom-200. Сохранена иерархия заголовка, цели, требований и действий; переносы и управление на узком экране работают. Блокирующих визуальных дефектов не обнаружено. Неблокирующее замечание: полный путь проекта на мобильном занимает заметную полосу; компактное представление с раскрытием можно рассмотреть отдельно. Сейчас информация сохраняется без изменения состава.

Ручной просмотр не равен полному аудиту WCAG. Автоматические проверки доступности, клавиатуры, 200%, состояний и реального API выполняются существующим Playwright-набором. Независимый итог — review.md.

Коммит, активация, публикация и человеческая приёмка не выполнены. Exact-SHA CI и installed E2E остаются открытыми выпускными критериями.
