# HG-0064 / HG-0065: хранение доказательств и Rust-сборок

## Что изменено

- HG-0064 расширяет существующего владельца HG-0033-R1: явный формат каталога 5 переиспользует одинаковые наборы `files`/`input_paths` между текущими и историческими доказательствами внутри одного results.json. Модель, история и смысловые отпечатки восстанавливаются до обычных проверок; объём входов не сужается
- HG-0065 уточняет HG-0044-R1: инвентаризация не считает hardlink дважды, различает уникальные байты, сумму по путям и выделенные блоки. Прежняя точная выборка и запреты удаления сохранены
- Один dev/test-профиль `debug=0`, `incremental=false` уменьшает обычные Rust-выходы без создания отдельного тестового кэша. Отладочная информация включается временно по инструкции BUILD
- До замены результатов и компиляции `verify.py tests` проверяет минимум 1 ГиБ свободного места на файловых системах проекта и эффективного Cargo target. Это нижний запас, не обещание максимального расхода. Автоматической очистки нет

## Отдельные причины объёма

В исходном окружении target основного дерева занимал 719.81 МиБ выделенного места, CommitPush — 764.71 МиБ, Update — 31.55 МиБ. Основной debug занимал 666.59 МиБ; incremental — 0.80 МиБ. Это прежде всего связанные тестовые бинарники и зависимости, а не накопление incremental. Старый инвентаризатор показывал 808.54 МиБ из-за повторного подсчёта hardlink; исправленный показывает 716.22 МиБ уникальных байтов и 719.81 МиБ выделенного места.

Отдельно HG-0063 results.json занимал 1 714 470 байт. Это сериализация повторных списков входов, не Rust-кэш. Ошибка GitHub-транспорта не воспроизводилась как ENOSPC: в окружении было около 27 ГиБ свободного места. Уменьшение файла не доказывает исправление транспорта или ускорение публикации.

## Измерение Rust

[Исходное сравнение](profile/comparison.json) использует один точный SHA `69e1c098b4ca5552b1f3b1ffe66ee808d8d81ab7`, отдельные чистые временные target и одинаковую последовательность Nextest list → cargo build. Рядом сохранены исходные inventories и stderr.

- Прежний профиль: 609.31 МиБ уникальных байтов, 611.73 МиБ выделенного места
- Единый dev/test debug=0: 293.41 / 295.79 МиБ, на 51.8% меньше
- Нормализованный состав всех 197 тестов совпадает; CLI доступна уже после Nextest
- Наблюдаемый пик самого target: 637.13 → 305.87 МиБ. Замер CLI-only, без UI bundle; это не предел общего потребления и не статистическое исследование времени

Пробный отдельный test-only debug=0 был отвергнут: последующая dev-сборка сохраняла второй набор, возвращая общий размер примерно к исходному. Поэтому изменён существующий dev-профиль, test продолжает наследование.

## Формат и проверка

[Проверка опубликованной JSON Schema](shared-input-schema-validation.json) использует реальные результаты новой CLI: все 59 мигрированных документов, включая HG-0063, соответствуют схеме; смешение встроенных входов и ссылки либо отсутствие ссылки отклоняется.

Полный замер миграции выполнен на изолированном Git archive точного CommitPush SHA `fd39b0d03ed7c8bda69559774f8bbf20b49a2834`. Проверяются все изменения, их `change_sha256`/`inputs_sha256`, повторная миграция и отказ старой CLI. Исходные ветки и исторические доказательства не переписываются этим упражнением. [Исходный отчёт](migration-measurement.json): все 59 изменений и их отпечатки равны, общий размер results.json 14 769 920 → 4 778 945 байт (−67.65%); HG-0063 1 714 470 → 661 344 байт (−61.43%). Повторная миграция байт-в-байт стабильна, прежняя CLI отказывает на версии 5.

Контрактные тесты отдельно проверяют v3/v4 → v5, точное восстановление current/history/review/acceptance, сохранение отсутствующего и пустого input_paths, рост повторных наблюдений, новые наборы, отсутствие/порчу/смешение ссылок, все порядки частично применённого журнала, отказ при лимите и неизменность обнаружения stale.

## Границы применения

Переход каталогов выполняется только `spec-migrate --to shared-inputs --expected <прочитанный хеш>` совместимой CLI. Установка не мигрирует данные. Старые каталоги 3/4 продолжают записываться в прежнем формате; старые CLI отказывают на 5. При объединении параллельных веток сначала согласуют все спеки/результаты, затем явно мигрируют объединённый каталог: нельзя просто добавить v4 results.json под заголовок v5.

Существующие main/CommitPush/Update target, общий toolchain и сторонние кэши не удалялись. Экспериментальные каталоги создавались изолированно и удалены владельцем. Для старых воспроизводимых кэшей остаётся preview → явная выборка `--apply` после проверки владельца и использования. Сохранённые доказательства, кандидат и инструменты не очищаются ради бюджета.

Коммит, публикация, удалённый Windows CI и активация имеют отдельные результаты. Локальные Linux-проверки и миграция не доказывают Windows, пользовательскую приёмку, доступность Planner Goal API или успешность GitHub-транспорта.
