# Объединённые Update / Commit / Push: повторная смысловая сверка

Дата: 2026-10-01. Проверена редакция объединённого дерева `integrate/highgrade-improvements` с HEAD из `inputs-before.json`, включая незакоммиченное восстановление корректного description Update. Это новая сверка текущего текста, а не перепривязка прежнего PASS. Автор этой сверки не изменял продуктовые файлы. Итоговое независимое ревью всего кандидата проводится отдельно.

До сверки закреплены 562 исходных файла: полная прежняя область доказательств плюс текущие исходники, процедуры, генератор, тесты и оба контракта. `inputs-after.json` подтверждает неизменность 602 объединённых исходных/context-файлов после наблюдений; отдельный native capture сверяет 440 входов запуска. Временная побайтовая копия kit проверена и затем удалена как воспроизводимый дубликат; её соответствие source фиксирует `context-provenance.json`.

## HG-0062

| Сценарий | Разобранные ветви текущего контракта | Наблюдение |
|---|---|---|
| S1 | GlobalSkillRecoveryRequired; иная ошибка status; пользовательский конфликт; старый/новый active pointer | Update оставляет одно явное исключение: global-recover проверенным совместимым кандидатом. После него обязателен status CLI фактически активного выпуска. `src/global.rs::recover_skills` сверяет весь набор до записи, отказывает при изменённых пользовательских байтах; `recover` вызывает `status`. Иная ошибка не разрешает ручную правку указателя/журнала. Комбинированные recovery-тесты действительно выполнены |
| S2 | Успешный postcheck с очисткой; ошибочное обновление; неуспешное восстановление | Description теперь обещает восстановление после сбоя. Процедура прямо отрицает постоянный rollback успешного обновления и требует наблюдать статус после отказа. `global_update_preview_switch_and_cleanup_keep_unrelated_files` проверяет удаление старого выпуска; механизм восстановления не объявлен безусловным |
| S3 | Вне проекта; проект без местной инструкции; все остальные навыки | Генератор даёт только Update безусловную возможность входа без проекта; AGENTS/инструкция читаются при наличии. Три целевых регрессии `test_render_skills.py` заново прошли. Полное сравнение render --check подтверждает согласованность всех generated skills; других вводных эта правка не меняет |
| S4 | v3/v4/v5; новое поле без смены версии; смена общей CLI | Правило касается фактического формата и используемых полей, пример v4 не является верхним пределом. Текущий справочник явно описывает v5/shared-inputs, совместимую CLI и явную миграцию. Update не разрешает неявно мигрировать проект или писать старой CLI. Комбинированная миграция отдельно учтена родительским исполнителем; это наблюдение её не заменяет |
| S5 | Корректный preview; изменившийся кандидат; иной unknown/error | Процедура перечисляет unknown/exit 2/SemanticReviewRequired при validation=passed, decision=required, applied=false; `src/global.rs::update` формирует именно эту ветвь, `Report::exit_code` даёт 2. Apply сравнивает candidate_sha256 до изменения. Выполненный native тест проверяет неизменность active после preview, отказ wrong/changed fingerprint и успешное применение исходного кандидата. Иное unknown требует разбора findings |

Все пять нормативных исходов соответствуют текущему контракту. Это доказательство текста, генерации и относящихся runtime-границ, не устойчивости исполнения Update моделью.

## HG-0063 и унаследованные нормативные сценарии

| Сценарий | Проверенный переход и предел |
|---|---|
| HG-0063-S1 | Solo Git + пройденный pre-submit допускает точный локальный кандидат. Отсутствие активации/release ID/remote не блокирует Commit; провал местной обязательной проверки либо неизвестный состав блокирует. Шаблон не подставляет main/global-update |
| HG-0063-S2 | После pre-submit допустим кандидат и отдельно разрешённые push/PR. Pending, unavailable, failed и успех другого SHA оставляют финальный пробел; failure возвращает в Work. Success точного SHA закрывает только этот критерий, без merge/accepted/deploy. Общие Work и Push согласованы с этим циклом |
| HG-0063-S3 | Commit либо push без разрешения объявленного autodeploy не разрешает зависимую отправку. Явное разрешение эффекта в выбранной среде допускает push; затем нужны чтение фактического deploy и связь с SHA. Повторный deploy ради проверки запрещён; pending/failed/unknown остаются отдельными |
| HG-0063-S4 | Без Git не запускается git init и не выдумывается remote. Work может завершиться без коммита; точный неизменяемый build ID и прежние readiness/fingerprint остаются обязательны для native result/accepted. При отсутствии ID решение не записывается |
| HG-0063-S5 | SHA1 кандидат допустим до поздних gates. Result/accepted требуют действительной готовности и явного решения. Metadata-only SHA2 содержит запись, но не подменяет проверенную реализацию SHA1. «Активируй» само не даёт acceptance |
| HG-0063-S6 | Для нового SHA после squash/rebase/merge нужно установленное сопоставление состава и значимых входов. Доказанное соответствие допускает reuse; drift требует новых проверок, unknown остаётся пробелом. Исторический verified_revision вручную не заменяется |
| HG-0063-S7 | Init извлекает известные Git/PR/base, pre-submit/final gates, последствия, активацию и полномочия из источников и сохраняет в проектной инструкции. Commit/Push её читают. При старой адаптации показывается конкретный пробел; нет молчаливой перезаписи или глобального запрета независимой локальной работы |
| HG-0031-S1 | «Принимаю и активируй» по показанному точному готовому результату допускает оба действия; «активируй», «выполняй» и пробная установка не дают human evidence/acceptance. Старый снимок не получает решение после существенного drift |
| HG-0048-S2 | Init/Work/Commit/Push проверяют фактический состав только порученной передачи. Локальная работа без такой передачи не получает искусственного transport gate; техническая готовность и человеческое решение самостоятельны |

Сверены полностью Commit, Push, Init, Work, Planner, rules, проектный шаблон и тематические справочники specifications/verification/diagnostics; для Update также генератор и фактические ветви Rust. Шесть новых узких Python-проверок структуры/генерации прошли, но сами по себе не считаются смысловым доказательством.

## Сохранённый конфликт и непроверенное

HG-0020-S6 и S7 требуют настоящего Goal API. В доступном реестре инструментов нет чтения/создания/изменения Goal; ни существующий чужой Goal, ни новый Goal не моделировались как настоящий.

Кроме отсутствия API остаётся нормативный конфликт: `kit/procedures/planner.md`, «Цель и полномочия», запрещает создание Goal по запросу только плана и не выводит разрешение из автоматического правила проекта. HG-0020-R3/S7 (также сохранённый в HG-0063) требует «Создать Goal» при plan-only; HG-0020-R1 и task также сохраняют иной текст автоправила. Этот проход не меняет и не устраняет конфликт. S6/S7 остаются unknown, не passed.

HG-0020-S8 также остаётся unknown в новом пакете: свежий technical-only случай действительно сохранил продукт/индекс/HEAD и не выполнил commit, activation, push или acceptance, однако не воспроизвёл завершённую зависимую цепочку с планом Planner. Это полезное частичное наблюдение, не полный новый исход S8. Прежний более полный пилот сохранён исторически, но не перепривязан к объединённым входам.

Нет новой человеческой приёмки, пользовательской активации, hosted Windows/Ubuntu CI, настоящего PR/merge/release/deploy. Windows file-lock тест не исполнялся на Linux. Эти ограничения не превращаются в PASS от успешного локального пакета.
