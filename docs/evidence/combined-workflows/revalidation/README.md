## Метод свежих наблюдений

Использован один продолжающий агент, который ранее читал требования и ожидаемые исходы. Это осознанная прямая проверка действий, не независимый/clean-context пилот и не статистическое доказательство поведения модели. Новый актор не был доступен из-за лимита потоков. Файлы prompt.txt сохраняют проектное задание из прежнего упражнения с новыми путями; informed-actor-input.txt явно снимает невыполнимое утверждение о нечитанном ожидаемом исходе. Отдельного скрытого контекста не заявлено.

Каждый исход опирается на реально выполненные audit-команды и before/after-файлы, Git bundle и индекс. Commit выбрал app.py/evidence/work.json; чужие staged/unstaged байты сохранены. Неизменные toy тесты не запускались повторно. Активация — игрушечный state из git show точного SHA, отказ apply дал 23 и прежний old-build. Push был только в новые локальные bare remotes; CI явно симулирован. Два остановленных Push не создали целевую ветку. Техническая несовместимость не скрывается: doctor вернул schema compatible, semantic not_assessed/status unknown; это не общий PASS и не основание утверждать семантическую готовность проекта.

`verify_observations.py` после действий заново прочитал snapshot/CLI/Git-состояния; это автоматический проверяющий исполнителя, а не независимый ревьюер. Его сырой вывод сохранён. Нормативные проверки noGit и разрешённого deploy не выдаются за свежий runtime-пилот: дополнительные подготовленные фикстуры не исполнялись.

## Входы и хранение

`inputs-before.json` выбран до новой смысловой сверки/пилотов. `pilot-inputs-before.json` дополнительно выбран до первого действия актора; `native/attempt.json` существовал до полного native запуска. `inputs-after.json` подтверждает отсутствие drift до завершения наблюдения. Новые отчёты являются результатами наблюдения, не подложными заранее существовавшими входами.

Нормативные/native записи сохраняют прежнюю объявленную область, добавляя новые релевантные источники и фактические отчёты. Старые результаты в этом наборе служат лишь сохранённой историей; новые выводы получены отдельно. Для новых actor/catalоg опытов сохранены прежние пути плюс текущая Поставка, CLI-источники и новые исходные/результирующие наблюдения. Ничего не сужено ради свежести. `scenario-input-plan.json` и batch задают точные пути.

Целиком установленный профиль и бинарник не копируются в tracked evidence. Временная copy kit удалена после сверки всех байтов с kit/; хеши и путь исходной установки сохраняются в `context-provenance.json`. Сами снимки игрушечных проектов малы и содержат невосстановимые фактические SHA/журнал/индекс. Native JUnit/attempt/completion/list сохранены, поскольку нужны для доказательства именно этого прогона. История прежних доказательств не переписывается.

Для повтора используйте новую пустую базу в fixture_driver.py и новый evidence-каталог. Установите CLI из проверяемого дерева и kit с подтверждёнными хешами в отдельный существующий профиль; бинарник не берётся по одному совпадению версии. Сначала новые input capture и snapshots, затем актор, after snapshot и наблюдатель. Не запускайте harness напрямую с его историческими путями. Новый запуск порождает новые SHA; не заменяйте ими сохранённые исходы.
