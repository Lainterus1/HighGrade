# Восстановление сохранённого ответа при продолжении

## Проблема и критерии до правки

В CLI основы c561dba после `spec-attention respond` содержимое summary/brief не меняется: прежний вопрос остаётся, ответ хранится отдельно в attention. Указание возобновить работу только через эти краткие представления не объясняло, где восстановить уже полученный ответ.

Гипотеза: условная адресная подсказка в work позволит использовать существующий источник ответа без нового API и обязательной загрузки полной истории. Критерии: сохранить краткий маршрут; перед повторным вопросом/зависимым действием восстановить отсутствующий в текущем контексте ответ или комментарий; проверить применимость к редакции; не выдумывать ответ, приёмку или полномочия.

## Решение

Изменён один абзац work, штатно сгенерированы highgrade-work/SKILL.md и manifest. При указанной необходимости читается исходное сообщение либо attention только выбранной спеки через существующий `spec-read --id ID --view full`. Источники норм, CLI, schema, release ID и способы фиксации решений не меняются.

## Проверка

- Настоящая CLI на детерминированных данных: отсутствие attention, неотвеченный вопрос, ответ, needs_changes с комментарием и устаревший ответ с исходным snapshot
- Исходное воспроизведение подтверждает неизменность summary/brief после ответа; full содержит ответ и его контекст
- render-skills --check, check-repository, diff --check: PASS
- inspect: те же девять ExternalLinkUnchecked, без новых failed/unknown
- Независимое ревью точного diff с SHA-256 из index.json: GO; дополнительно сверены saved cases текущими read-only вызовами CLI

Это проверка содержания инструкции и доступности данных. Она не измеряет вероятность ошибки реального агента и не доказывает ускорения workflow. Синтетические ответы в фикстуре не являются пользовательскими решениями или приёмкой этой правки.

## Доказательства и границы

Lossless XZ содержит JSON files[] с path/sha256/bytes/content_base64. index.json закрепляет архив и каждый восстановленный файл; исходные JSON/команды не редактировались. Для повторения сохранён check-resume-cases.py: назначьте путь к проверяемой CLI, новый временный ROOT и новый уникальный LOG. Не перезаписывайте сохранённые исходные доказательства. Исходные абсолютные пути относятся к изолированной среде проверки.

Основа — draft PR #1 c561dba. Readiness и остальные исправления не являются зависимостями. При совместном применении правок разных абзацев work следует штатно перегенерировать общий SKILL.md/manifest и проверить итоговый diff. Установка, активация, merge и человеческая приёмка не выполнялись; commit/publication/CI сообщаются отдельно.
