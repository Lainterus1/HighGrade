# Подтверждение спецификаций и выпуск High Grade (версия 2)

Цель: зафиксировать решение автора от 2026-09-25 принять действующие JSON-спецификации, честно сохранить статус технических проверок, убрать временные синтетические примеры, локально активировать выбранный коммит Поставки и отправить его в `origin/main`.

Границы: не объявлять `passed` по наличию документа или общему успешному тесту; не использовать SNAF и другие реальные проекты. Разрешённые ранее локальные агентные пилоты остановлены по новому решению автора. Сохранить посторонние изменения рабочего дерева. Цель и маршрут Git — в проектной инструкции; штатная приёмка — в `specs/changes/*/results.json`, исключение для двух неготовых редакций — в отдельной записи решения.

## Этапы и барьеры

1. Сверить состав 15 действующих изменений, текущие статусы, установку и область публикации. Критерий: точный перечень пробелов и исходных коммитов.
2. Освежить доступные локальные проверки и доказательства без выдуманного PASS. Критерий: по каждому сценарию есть актуальное доказательство либо явно названный пробел.
3. Проверить агентные сценарии только в разрешённой среде и зафиксировать исходные наблюдения. Критерий: воспроизводимые входы, действия, результаты и ограничения; отказ или пропуск остаётся открытым.
4. Зафиксировать решение автора без выдуманного `passed`: для технически готовых редакций использовать `spec-decide`; для оставшихся отдельно записать принятое автором исключение и конкретные пробелы, поскольку CLI не принимает `accepted` при `spec-check: failed`. Критерий: решение и ограничения читаются однозначно, статус CLI не искажён.
5. Сверить ссылки на доказательства, удалить временные синтетические проекты и лишние результаты прогонов из `target/`, сохранив доказательства, входящие в выбранный пакет. Критерий: постоянный пакет не ссылается на удалённые временные файлы.
6. Проверить выбранный staged diff, создать локальный коммит, собрать кандидат из его SHA, выполнить preview/apply с одним отпечатком и проверить `global-status`.
7. Сверить `origin/main`, отправить непрерывный проверенный диапазон без force, проверить удалённый SHA и результат CI.

Автор явно остановил дальнейшие агентные пилоты и принял оставшиеся риски сценарных пробелов. Это решение не меняет машинный `spec-check`; в выпуске нужно показать отличие человеческого решения от технической готовности. Локальная активация и push зависят от однозначного состава коммита и необходимых проверок самого пакета. Фактический результат каждого этапа фиксируется в состоянии рядом с этим планом.
