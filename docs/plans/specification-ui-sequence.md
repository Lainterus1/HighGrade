# Маршрут локального интерфейса спецификаций

Статус: HG-0052–0057 технически интегрированы, независимое REVIEW_GO. Пользователь одобрил оформление после HG-0054 и поручил продолжить тот же Goal. [Передача результата и проверенная версия](../evidence/specification-ui/handoff.md); общая человеческая приёмка, commit/activation/push отдельны. Исходное обсуждение — в [постановке](../proposals/specification-ui-task.md); требования и задачи принадлежат спекам ниже.

## Один Planner после поручения выполнить

После отдельного поручения на выполнение — один highgrade-planner/Goal на всю согласованную цепочку, с явной остановкой после третьего этапа. Если последующее поручение ограничит объём иначе, соблюдать его буквально. Сразу после создания Goal показать эти шесть этапов в штатном update_plan, не более одного in_progress. Действия внутри этапа берутся из tasks соответствующей спеки.

Локальное состояние: `.highgrade/local/specification-ui-state.md`. Оно содержит только ссылки, наблюдённые редакции, текущий этап, краткую последнюю сверку перехода, один Next, блокер/барьер и ссылки на доказательства. Требования, задачи и их результаты в локальный файл не копируются.

## Проверка следующей спеки после каждого этапа

1. Сверить выполненную спеку с актуальными доказательствами, обязательным независимым ревью и условиями spec-check/integrate по work. Не объявлять её выполненной по одной структурной валидации.
2. До изменения последней задачи выполненной спеки и её интеграции прочитать следующую через spec-read; сопоставить её предпосылки с фактическим результатом этапа. Если интеграция меняет базу следующей спеки, после интеграции повторить только затронутую сверку.
3. Проверить предметные поля/схему и доступные команды/API, границы совместимости, зависимости, визуальные решения и ограничения, сохранность, сценарии доказательств и пути/селекторы уже существующих проверок. Проверить также влияние на оставшиеся спеки, если оно явно обнаружено; не запускать полный повторный анализ цепочки без причины.
4. Если уточнения не нужны, записать в локальное состояние ID/редакцию следующей спеки, проверенные предпосылки и результат «уточнений не требуется». Формальная отметка без сопоставления фактов недостаточна.
5. Если уточнение укладывается в согласованные цель и границы — обновить тот же неинтегрированный ID через highgrade-spec/spec-edit с CAS, сохранив ID требований/сценариев при редактуре. Зафиксировать кратко основание и что уточнено; выполнить spec-validate и смысловую сверку. Изменённые существенные требования/сценарии проходят независимое ревью перед зависимой работой; не подгонять ожидания под дефект реализации.
6. Если появился новый существенный выбор, изменение полномочий/объёма или противоречие — задать адресный вопрос пользователю и остановить зависимый переход. Обнаруженный незавершённый критерий предыдущей спеки исправить по действующему контракту. Интегрированные требования задним числом не редактировать: при изменении контракта нужен отдельный change.
7. Только при выполненном барьере и актуальном контракте следующей спеки менять этап в чек-листе и Next. Это не требует нового согласования человека на каждом шаге, если решение уже дано и существенного нового выбора нет.

Результат сверки — короткая запись рядом с точкой продолжения, без отдельного отчёта/спеки/подписи на каждый переход. Перед возобновлением после перерыва проверить редакции и переиспользовать неизменённые доказательства, а не повторять все проверки механически.

## Обязательная остановка после визуального оформления

После HG-0054 показать открываемый локальный Storybook, основной экран, редактирование, запрос решения/приёмку и отрицательные состояния, выбранный SVG-логотип в реальных размерах; сообщить ограничения демонстрационных данных. До остановки выполнить сверку HG-0055 по правилам выше, но не начинать её реализацию.

Сохранить `Next: получить обратную связь/команду пользователя по визуальному результату HG-0054; затем повторно сверить HG-0055`. При активном Goal применить паузу на основании явного поручения пользователя остановиться здесь. Goal всей цепочки не отмечать complete. Технический REVIEW_GO, интеграция S3 или отсутствие замечаний не заменяют новую команду продолжить и не считаются визуальным одобрением человека.

После обратной связи учесть её влияние: уточнить незавершённые спеки теми же ID; выполненный контракт менять отдельным change только при реальном изменении требований. Возобновить тот же Goal, сверить ближайший этап и продолжить цепочку в разрешённых пределах.

## Завершение и полномочия

После HG-0057 проверить весь конечный результат и тогда закрыть Goal/Next. Approve/коммит, назначенная локальная активация, публикация, CI и человеческая приёмка остаются отдельными состояниями по местной инструкции. Ни оформление этих спек, ни будущая готовность интерфейса не разрешают push, внешние пилоты или публикацию Storybook.
