# Контракт кандидата P3–P5

Дата: 2026-09-23. Это описание реализованных интерфейсов первого кандидата. Требования остаются в [SPECIFICATION](../../../workflow/SPECIFICATION.md), проектная политика — в [CONTEXT](../../../workflow/CONTEXT.md). Подключение и явная приёмка адаптации остаются разными состояниями.

## Состав и подключение

Проект может явно перечислить исключения технического снимка в `.highgrade/project/inventory-exclusions.json` с путём и причиной. `inventory` показывает список и SHA256 конфигурации; при её наличии receipt обязан содержать тот же `exclusions_sha256`. Это позволяет не читать локальные служебные каталоги при хешировании, но не снимает обязанности аудитора классифицировать их и назвать непрочитанное. `inspect` также не считает такие пути источниками документации.

`cli_version` в манифесте версии 2 фиксирует ожидаемую версию исполняемого файла: первая установка сверяет её с запускаемым CLI, обновление — с явно выбранным новым exe.

`bundle/manifest.json` версии 2 перечисляет ровно четыре маршрутизирующих навыка `highgrade-init/work/refresh/update`, общие правила, пять шаблонов документов, общий аудит, [команды и форматы](../../../../bundle/references/cli.md) и процедуры. SHA256 относится к байтам файлов. Установщик добавляет исполняемый файл текущего процесса, пишет неизменяемый `.highgrade/releases/<release>/journal.json` и активирует `.highgrade/active.json` последним. Навыки лежат в `.agents/skills/`. Проектные решения принадлежат `.highgrade/project/` и не обновляются вместе с основой. После подключения команды вызывают exe из проверенной активной основы, а не имя из PATH.

`highgrade inventory --root ABS` даёт структурный список файлов и хешей; это не смысловой аудит. Для первой установки нужен утверждённый receipt полного аудита формата P0–P2. `highgrade install --root ABS --source ABS --audit REL` сверяет его с текущим инвентарём до записи. Чужой навык, повреждённая поставка и устаревший аудит блокируют подключение. Повтор того же кандидата идемпотентен. Старый прототип schema_version 1 не мигрирует автоматически: при `.highgrade/installed.json` возвращается `PrototypeInstalled`; миграция требует отдельного проверенного пути. Свежим проектам P6 это не мешает.

Init существующего проекта требует полный смысловой аудит, интервью, выбор режима документов A/B, политики локальных коммитов A/B и плана. Начальный init завершается планом. Адаптация начинается по отдельному поручению, заканчивается проверками и обязательным независимым ревью; результат `READY_FOR_ACCEPTANCE` до явной приёмки. Work ведёт обычные задачи со штатными проверками и архивом; refresh — дополнительный обзор по запросу. Archive — процедура агента, не утилита удаления.

## Доказательства сценариев

`highgrade trace --root ABS --record REL` только читает запись запуска и исходные отчёты; native тесты запускаются отдельно. В обычных заголовках OpenSpec используй `### Requirement: [PROJECT-...-R1] Название` и `#### Scenario: [PROJECT-...-S1] Название`; префикс проекта не фиксирован как `HG`. Наличие структурных заголовков проверяет `openspec validate --strict` версии 1.13.1, а формат и связь ID проверяет `highgrade trace`.

Запись JSON версии 1 содержит `tool` (`rust-nextest`/`playwright`), фактическую команду, область, время, абсолютный `capture_root` во время запуска, `exit_code`, `report`, `report_sha256`, массивы `spec_files`/`test_sources` и `source_hashes` для них. Исторические абсолютные пути в нативном отчёте переносятся относительно `capture_root` в текущий checkout; старый каталог не обязан существовать. Для Rust нужен `inventory` с JSON-выводом `cargo nextest list --message-format json`; он тоже входит в `source_hashes`. Nextest JUnit должен быть включён в проектном профиле. Комментарий `// highgrade: PROJECT-...-S1` перед `#[test] fn ...` и аннотация Playwright `{ type: 'highgrade', description: 'PROJECT-...-S1' }` связывают тест с сценарием. Связь сама по себе не подтверждает запуск.

Вывод содержит статус для каждого сценария и находки. Дубли и отсутствие ID, неизвестный ID, отсутствие результата, пустой набор, пропуск, падение, повтор с ошибкой, изменённый отчёт/источник и ненулевой код запуска не дают `passed`. Для Playwright `spec.file` относительно `config.rootDir` приводится к корню проекта и обязан совпасть с указанным исходником. Rust-связь первого кандидата проверяется для обычного top-level integration test `tests/<binary-name>.rs` относительно `cwd` из nextest list; вложенные модули, нестандартные targets и unit tests остаются `unknown`. `source_hashes` подтверждает неизменность перечисленных файлов, но CLI не доказывает полноту выбранной области, качество теста или истинность внешней записи о запуске; это предмет ревью агента.

## Добровольное обновление

`highgrade update --root ABS --source ABS --candidate-exe ABS --decision REL` делает пред-проверку без записи и возвращает необходимость смыслового решения. Старый активный CLI запускает операцию, но байты нового exe берутся только по явному пути `--candidate-exe`. В preview включены хеши manifest, выбранного exe, адаптации и проектного инвентаря с исключением именно файла решения. Неизменные маршрутизирующие навыки и отдельная директория новой версии — структурный контракт кандидата; изменение router-файлов потребует отдельной миграции. Для переключения требуется `--apply true --decision REL` и JSON с `status: approved`, `from`, `to`, `active_journal_sha256`, `candidate_manifest_sha256`, `candidate_exe_sha256`, `adaptation_sha256`, `project_sha256`, непустым `evidence` с результатом смыслового сравнения. Эти поля привязывают решение к текущей основе, кандидату, бинарнику и состоянию проекта, но CLI не выносит решение вместо автора/агента. Обновление сохраняет старую основу и `.highgrade/project/`, атомарно заменяет один активный указатель на Windows и проверяет его. `--rollback RELEASE` возвращает проверенную прежнюю основу. Повторные/неполные попытки не перезаписывают чужие файлы; несовместимые маршруты и коллизии отклоняются.

Проверены Windows и локальная сборка Rust. Общего runner, автоматического `latest`, телеметрии High Grade, Covers и миграции старого прототипа в этой версии нет.
