# Контракт прототипа P0–P2

Дата проверки: 2026-09-23. Состояние: реализован локальный прототип, не готовый первый выпуск. Требования остаются в [SPECIFICATION](../../../workflow/SPECIFICATION.md); последовательность — в [плане](../../plans/first-release.md). Этот документ владеет форматами реализации, а не повторяет продуктовую политику.

## Состав и команды

Исходная поставка: Cargo.toml, Cargo.lock, src/, tests/, bundle/. Локальная сборка `cargo build --release --locked` создаёт highgrade.exe. Конкретный Git ref и разрешение публикации определяются отдельно. SVG/CHA не входят в устанавливаемую основу.

```text
highgrade --version
highgrade doctor --root ABS
highgrade inspect --root ABS [--registry REL] [--scope REL]
highgrade install --root ABS --source ABS --audit REL
```

Вывод команд — JSON с `operation`, `status`, `findings`, `measurements`, `limitations`. Finding: `status`, `code`, `location`, `message`. Приоритет: failed > unknown > warning > passed. Коды процесса: failed=1, unknown=2, warning/passed=0. Ошибка аргументов/чтения/формата даёт failed; неизвестные и повторные параметры отклоняются. Код 0 не означает пользовательскую приёмку или готовность workflow.

doctor проверяет присутствие cargo/codex/node/openspec в PATH без исполнения найденных команд, показывает `version:null`, `executed:false`; отсутствие — unknown. Он сверяет установленную основу с журналом. Изменённый файл/незавершённая установка — failed; отсутствие подключения — unknown. Само обнаружение файла не доказывает совместимость зависимости.

## Пути и границы

Все REL — относительно заданного корня, с `/`. Отклоняются абсолютные пути, `..`, обратная косая черта, Windows ADS, резервные имена и reparse points/junction. Корень также проверяется. Markdown-ссылки могут содержать `../`, только если после разрешения остаются внутри корня. Абсолютные авторские пути не вшиваются в bundle.

JSON/документ до 8 MiB; файл снимка аудита до 32 MiB, снимок до 10000 файлов; поставляемый исполняемый файл до 128 MiB. Превышение — явная ошибка, не скрытый пропуск. Установка использует hard links на одном томе; файловая система без этой возможности даёт PublishFailed. Проверено на текущем Windows-томе, не на всех файловых системах.

Защита путей предотвращает обычный выход за корень. Она не является защитой от враждебного процесса, меняющего компоненты пути между системными вызовами. Параллельные установщики координируются файловой блокировкой; внешние редакторы обязаны не менять устанавливаемые файлы во время операции.

## Подключение и аудит

```text
.agents/skills/highgrade-init/SKILL.md  # единственная обнаруживаемая точка входа
.highgrade/releases/<release>/
  highgrade.exe                       # текущий собранный установщик/диагностика
  rules.md                            # выбранная неизменяемая основа
.highgrade/install.json               # журнал ожидаемых SHA256
.highgrade/installed.json             # финальный маркер prototype-connected
.highgrade/install.lock               # блокировка писателя
.highgrade/project/                   # проектная адаптация, установщик её не создаёт
```

`bundle/manifest.json`: schema_version=1, release (1–64 символов a-z/0-9/-), files ровно SKILL.md и rules.md с SHA256. Шаблон `{{release}}` заменяется перед записью. Сам исполняемый файл берётся из текущего процесса; разные сборки не считаются одним кандидатом по одному лишь имени release.

До первой записи требуется файл подтверждения аудита:

```json
{
  "schema_version": 1,
  "status": "approved",
  "scope": "full-project",
  "evidence": "Ссылка или описание выполненного аудита и согласования",
  "files": {"README.md": "<sha256>"}
}
```

`files` содержит полный инвентарь файлов, включая проектные инструкции и документацию. Исключения: сам receipt, корневые .git/.highgrade/target/node_modules/.venv и собственная точка входа .agents/skills/highgrade-init. Это граница структурного снимка, а не разрешение исключить важную для аудита область. Исключённые генерируемые/служебные каталоги оценивает аудитор по необходимости. Символические ссылки не обходятся молча.

CLI **не выполняет смысловой аудит и не подтверждает согласие автора самостоятельно**: receipt — внешнее явное свидетельство. Отсутствующий, pending или устаревший снимок отклоняется до подключения. Тестовый receipt в испытаниях обозначен synthetic и не распространяется на реальные проекты. Автоматическая генерация approved отсутствует. Полная процедура аудита/интервью — P3.

Установщик не меняет AGENTS.md и проектную адаптацию. Без совпавшего журнала даже совпадающий по содержимому чужой целевой файл — конфликт. Сначала журнал, затем файлы, последним маркер. Повтор того же кандидата идемпотентен; другой кандидат требует будущего update, не затирает старый.

Запись: create_new `.part` → write/sync → hard_link без замены назначения → удаление собственного временного файла. Обрыв между публикациями автоматически продолжается; изменённый чужой файл сохраняется и блокирует продолжение. Завершённый `.part` может быть опубликован повторно. Неполный/изменённый `.part` сохраняется с PartialWriteConflict для ручного разбора; это безопасный отказ, не обещание автоматического восстановления при любом аварийном обрыве. Без маркера skill не разрешает продуктовое выполнение. Полный workflow и приёмка адаптации всегда `workflow_ready:false` в этом прототипе.

## Реестр и карта контекста

По умолчанию выбирается один существующий `.highgrade/project/documents.json` либо исторический `.mycodex/project/documents.json`. Два файла — ошибка неоднозначности; для явного выбора используется --registry. Нет скрытого переключения при повреждении. schema_version=1; отсутствие версии допускается для существующего реестра High Grade.

Обязательные `documents`: уникальные id, path, role. Ровно по одной роли: purpose-navigation, agent-rules, current-architecture, engineering-rules, commands-procedures. `additional_sources` содержит path/role; active=false исключает запись. Пути не повторяются, с учётом регистра Windows. `scope` — массив явно покрываемых относительных поддеревьев; `loading` — entry/task/history, отсутствие трактуется как task.

Без --scope читаются все активные зарегистрированные документы. С --scope читаются entry и документы, чьи области пересекаются с запросом в любую сторону, либо чей путь совпадает с запросом. Наличие entry не доказывает покрытие области; если никто явно не покрывает всю область, выдаётся ScopeUnclassified. Родительская папка документа не получает автоматическое покрытие. Новые папки и непокрытые ветви частично описанных областей дают AreaUnclassified. Корневые служебные .git/.highgrade/.mycodex/.agents/target/node_modules/.venv пропускаются при поиске новых областей. Это структурная карта, не анализ зависимостей исходников. Файлы в полностью объявленной области требуют смыслового ревью при её изменении.

Измеряются байты UTF-8, строки, SHA256 и приблизительная оценка chars/4. Последняя не является размером окна модели или точным tokenizer count. Документы history измеряются, но не включаются в суммарный маршрут. Основные документы имеют отдельные бюджеты; additional_sources входят в бюджет маршрута. Общий маршрут всех документов — консервативная верхняя оценка, а не инструкция загрузить их все.

```json
{
  "unit": "bytes", "agreed": true,
  "min": 1000, "baseline": 6000, "current": 6500, "ceiling": 9000,
  "history": [{"from": 6000, "to": 6500, "reason": "Добавлена область по решению автора"}],
  "review_trigger": "Изменение архитектуры или превышение"
}
```

Это пример, **не согласованные лимиты High Grade**. Бюджет документа хранится в budget, маршрута — в route_budget. null/отсутствие → unknown. Диапазон и непрерывная история проверяются; значения истории не могут обходить ceiling; итог обязан совпадать с current. Превышение размера → warning, без автоматического повышения и запрета работы. Переписывание целиком прежнего baseline требует сравнения с историческим свидетельством/решением автора; проверка одной записи не доказывает неизменность её истории.

Markdown разбирается парсером: inline/reference links и изображения, существование целей, стандартные заголовки/якоря. Кодовые блоки не считаются ссылками. Сеть не используется: внешние ссылки помечаются unchecked. HTML/custom anchors и отличающиеся диалекты требуют ручной проверки. Все doctor/inspect операции read-only, в том числе при ошибках.

## Граница OpenSpec и доказательств P4

Для P3 предусмотрены обычные `openspec/specs`, `openspec/changes`, config.yaml и стандартные status/instructions/validate с JSON по подтверждённой версии. High Grade не вводит второй backlog и не использует stores для управления чужими проектами. Интеграция и исполнение OpenSpec в P0–P2 не реализованы.

Кандидат аннотаций P4: устойчивый ID сценария в заголовке OpenSpec; Rust — комментарий `// highgrade: SCENARIO-ID` непосредственно перед тестом; Playwright — annotation с type `highgrade` и description, содержащим ID. Точный парсер/отчётный ключ проверяются в P4; комментарий и ссылка сами по себе не считаются выполнением.

Обычный [cargo test --message-format=json](https://doc.rust-lang.org/cargo/commands/cargo-test.html) даёт JSON сообщений компиляции и не выбран как достоверный отчёт отдельных тестов. Кандидат Rust-отчёта — [cargo-nextest JUnit](https://nexte.st/docs/machine-readable/junit/) плюс список обнаруженных тестов; nextest ещё не установлен, совместимость и пропуски проверяются в P4. Агент запускает native команду напрямую. Для браузера кандидат — [Playwright JSON reporter](https://playwright.dev/docs/test-reporters) и [annotations](https://playwright.dev/docs/test-annotations); браузерные тесты в этих этапах не запускались.

Будущий компактный результат должен связывать native test identity, scenario ID, outcome, команду, время, хеш проверяемых входов и исходный отчёт. Неизвестный ID, дубли, skipped/пустой suite и старый отчёт не подтверждают сценарий. Ни trace, ни update, ни общий тестовый runner сейчас не добавлены.
