# Spec Delta

## Purpose

Дать общим навыкам High Grade ограниченную карту одного рабочего проекта для быстрого выбора источников контекста, сохраняя явную границу между структурным обнаружением и завершённым аудитом.

## ADDED Requirements

### Requirement: Быстрая команда карты
Общий CLI SHALL предоставлять команду `map --root <абсолютный путь>` с машиночитаемым, ограниченным по объёму результатом. Команда SHALL работать только на чтение в указанном корне, не запускать проектные команды и не обращаться к сети.

#### Scenario: Обычный проект
- **WHEN** пользователь запускает `highgrade map --root <проект>` для доступного каталога
- **THEN** результат содержит сводку структуры и кандидатов на входные документы, точки запуска, стек, тесты и CI с относительными путями-основаниями

#### Scenario: Неверный корень
- **WHEN** корень отсутствует, недоступен или не является каталогом
- **THEN** команда возвращает явную ошибку без изменения файлов

### Requirement: Область рабочего дерева
Карта SHALL рассматривать отслеживаемые и новые файлы внутри указанного проекта, включая скрытые инструкции. Она SHALL отделять пропущенные кэши, генерируемые и закрытые файлы от изученной области и SHALL обозначать неполный обход как неполный результат. Переходы по ссылкам и точкам повторного разбора за пределы корня SHALL быть запрещены.

#### Scenario: Новая скрытая инструкция
- **WHEN** в рабочем дереве есть ещё не добавленный в Git `.agents/skills/example/SKILL.md`
- **THEN** карта показывает его как кандидат на локальную инструкцию независимо от статуса Git

#### Scenario: Служебные и закрытые файлы
- **WHEN** проект содержит генерируемый каталог и файл с известным закрытым именем, например `.env`
- **THEN** карта не читает их содержимое и показывает их исключение с причиной, не выдавая закрытые значения

#### Scenario: Неполный обход
- **WHEN** каталог нельзя прочитать или достигнут установленный предел обхода либо вывода
- **THEN** результат отмечает пропущенную область и не сообщает о полной карте проекта

### Requirement: Ограниченное извлечение сведений
Карта SHALL читать содержимое только документированных разрешённых типов входных файлов, включая README, манифесты проекта, конфигурации тестов и CI. Извлечённый результат SHALL содержать только классификации, счётчики и пути-основания; произвольные строки, значения параметров, фрагменты файлов и команды из проекта SHALL не выводиться. Нераспознанная технология SHALL оставаться неизвестной.

#### Scenario: Распознанные входы
- **WHEN** в проекте есть README, манифест и конфигурация тестов поддерживаемого типа
- **THEN** карта показывает соответствующие категории и пути-основания без копирования содержимого этих файлов

#### Scenario: Неизвестный стек
- **WHEN** файлы не позволяют уверенно определить технологию или точку запуска
- **THEN** поле остаётся неизвестным, без догадки по имени каталога или неподтверждённой команде

#### Scenario: Закрытое значение в разрешённом файле
- **WHEN** разрешённый к разбору файл содержит токен, пароль или иное значение вне фиксированных категорий вывода
- **THEN** значение не появляется в результате карты

### Requirement: Корректная граница применения
Общие процедуры init, task, spec, work и clear SHALL описывать карту как вспомогательный способ выбрать дальнейшее чтение, когда нужна общая ориентация в проекте. Они SHALL сохранять полный аудит init, штатные проверки и назначение `inventory`, `doctor`, `inspect` и `trace` отдельно от результата карты.

#### Scenario: Инициализация существующего проекта
- **WHEN** init использует карту перед аудитом
- **THEN** карта помогает составить маршрут чтения, но не считается доказательством прочтения файлов или завершения аудита

#### Scenario: Работа над локальной задачей
- **WHEN** task, spec, work или clear уже знает нужные пути и не требует общей ориентации
- **THEN** процедура не обязывает выполнять карту повторно
