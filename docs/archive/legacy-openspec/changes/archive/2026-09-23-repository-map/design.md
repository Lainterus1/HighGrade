# Design

## Context

См. [proposal.md](proposal.md). Нынешний `inventory` рекурсивно хеширует файлы и нужен для снимка аудита; `doctor`, `inspect` и `trace` решают другие задачи. CLI уже возвращает JSON-отчёты с различением `passed`, `warning`, `unknown` и `failed`. Глобальная поставка работает из профиля пользователя, а проект задаётся явным `--root`.

## Goals / Non-Goals

**Goals:** быстро получить компактный маршрут дальнейшего чтения в одном проекте; сохранить источники каждого вывода, пропуски и ограничения; использовать карту из нескольких общих процедур без обязательного запуска при каждом обращении.

**Non-Goals:** семантический аудит, поиск по произвольному тексту, индекс символов, вывод готовых команд запуска, расчёт влияния изменений, доказательство качества тестов, обход соседних проектов.

## Decisions

### Отдельная операция существующего CLI

Добавить `map` в Rust CLI и его общий формат `Report`, с собственным модулем обхода. Не вызывать `inventory` как основу: полное чтение и хеширование противоречат цели быстрого обзора. Не создавать седьмой навык или обязательные `git`/`rg`/`tokei`: команда доступна в новом и существующем проекте без их установки. Альтернатива из набора команд оболочки короче в реализации, но не даёт единых лимитов, структуры результата и поведения при неполном обходе.

### Обход рабочего каталога без зависимости от Git

Обходить только переданный корень средствами стандартной библиотеки, сортируя записи для устойчивого результата. Это включает отслеживаемые и новые файлы, скрытые инструкции и проекты без Git. Не переходить по символическим ссылкам и точкам повторного разбора; использовать действующую проверку безопасных путей. Пропускать `.git`, распространённые каталоги сборки и кэша, а также файлы с известными закрытыми именами; показывать относительный путь либо группу, причину и число пропусков. Не делать вывод «полный аудит» из того, что файл не попал в исключения. Альтернатива `git ls-files` была бы точной для Git-индекса, но пропустила бы часть новых файлов и не работала бы в новом проекте без Git.

### Строго ограниченное чтение и закрытый словарь вывода

Для разрешённых типов использовать отдельные небольшие распознаватели: `README.md` (наличие разделов о запуске, разработке и тестах), `Cargo.toml`, `package.json` и `pyproject.toml` (тип экосистемы и наличие стандартных целей), `pytest.ini`, `playwright.config.*`, `vitest.config.*` и `.github/workflows/*.{yml,yaml}` (тип проверки и наличие CI). `go.mod`, `pom.xml`, `build.gradle[.kts]`, `*.sln` и `*.csproj` дают только признак экосистемы по имени файла; их содержимое не читается в первой версии. Первую таблицу поддерживаемых имён и лимиты чтения/вывода закрепить в справочнике CLI и тестах. Разбор не возвращает исходные заголовки, команды, значения полей или фрагменты файлов: только фиксированные категории, количества, относительные пути и при необходимости номера строк. Для неизвестных форматов результат `unknown`, а не догадка по названию каталога. Альтернатива выводить выдержки удобнее для чтения человеком, но может раскрыть закрытое значение даже в README или CI.

### Ограничения и неполнота

Ввести предел числа посещённых записей, размера читаемого разрешённого файла и числа путей в каждой категории. При достижении предела или отказе доступа возвращать полезную частичную карту со статусом `unknown`, причиной и счётчиками; при неверном корне — `failed`. Сортировка и фиксированные категории позволяют сравнивать результаты без хранения снимка на диске. Конкретные пределы выбрать по тесту на малом и искусственно большом дереве и документировать до реализации; не заявлять SLA без измерения.

### Подключение к процедурам

В `init` карта предваряет выбор файлов для полного аудита. В `task`, `spec`, `work` и `clear` она доступна, когда контекст проекта неясен или изменилась область; при уже известных путях повтор не обязателен. Справочник CLI описывает поля и пределы, а процедура обследования подчёркивает, что наличие пути в карте не означает прочтения содержания. Источником задач остаётся OpenSpec.

## Risks / Trade-offs

- **Неузнанный стек или нестандартный кэш** → пометить `unknown` либо исключение, оставить агенту целевое чтение и пересмотр таблицы форматов только по реальным примерам.
- **Секрет внутри разрешённого файла** → возвращать лишь элементы закрытого словаря; добавить тест с контрольным секретом в README, манифесте и CI.
- **Большое дерево или Windows junction** → лимиты, отсутствие перехода по ссылкам, частичный результат с явной причиной; проверить на фикстурах.
- **Карта ошибочно воспринята как аудит** → ограничение в результате, справочнике и общих процедурах; `inventory` и полный аудит остаются отдельными действиями.

## Migration Plan

После реализации проверить CLI и процедуры в исходном репозитории и изолированном профиле. Новая команда появится у пользователя только после отдельного проверенного обновления глобальной поставки через `highgrade-update`; текущее изменение OpenSpec само её не переключает. При неудачном будущем обновлении действует существующий откат поставки.
