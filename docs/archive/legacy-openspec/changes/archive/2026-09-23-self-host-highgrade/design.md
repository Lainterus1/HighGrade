# Design

## Context

Проект уже хранит общие процедуры в пользовательской поставке High Grade v0-2-1 и собственную адаптацию в `.highgrade/project/INSTRUCTIONS.md`. OpenSpec 1.13.1 добавлен в пользовательский npm-профиль; `openspec init --tools none --language Russian` создал только `openspec/`, без конкурирующих навыков. Завершённый план глобальной поставки ещё находится в активном маршруте. См. [proposal.md](proposal.md).

## Goals / Non-Goals

**Goals:** оставить один набор общих навыков и один источник задач на поведенческое изменение; сделать команды для новой копии воспроизводимыми; перевести завершённые планы в архив без потери истории.

**Non-Goals:** менять опубликованный CLI, автоматически обновлять глобальную поставку, настраивать целевые проекты или доказывать семантическую правильность всех будущих спек.

## Decisions

- Использовать проектный `openspec/` и CLI 1.13.1. В `DEVELOPMENT.md` записать установку закреплённой версии и прямой вызов `openspec.cmd` для Windows; `doctor` запускать в среде, где путь npm CLI доступен в `PATH`. Альтернатива — генерация OpenSpec-навыков Codex — дала бы вторую роль task/spec рядом с High Grade, поэтому `--tools none`.
- Для первого изменения завести способность `self-hosted-workflow`. Её требования описывают наблюдаемый маршрут, а не сам факт наличия файлов. После реализации и проверки завершённое изменение архивировать штатным OpenSpec, чтобы его спецификация стала действующей.
- Числа бюджетов фиксировать только после решения автора по уже измеренному предложению; превышение обрабатывать предупреждением и пересмотром. Это отделяет согласование границ от механической записи JSON.
- Завершённые планы переместить в `docs/archive/plans/`, сохранить индекс и обновить входящие ссылки. Текущий план исполнения содержит только этапы и доказательства; подробные задачи поведения принадлежат OpenSpec.

## Risks / Trade-offs

- Риск: CLI доступен в пользовательском профиле, но не в каждой среде `PATH`. Мера: показывать проверку версии и явный путь для Windows; не трактовать `doctor: unknown` как успех.
- Риск: структурная проверка OpenSpec не доказывает поведение агента. Мера: выполнить один реальный внутренний цикл и отдельно описать его границы.
- Риск: перемещение старых планов ломает ссылки. Мера: найти все входящие ссылки и проверить их после переноса.

## Migration Plan

Сначала проверить OpenSpec и подготовить изменение; затем обновить входной маршрут и документы; после проверок архивировать завершённые планы и это OpenSpec-изменение. Откат локальных текстовых изменений возможен через Git, а установленный пользовательский OpenSpec не включён в репозиторий.
