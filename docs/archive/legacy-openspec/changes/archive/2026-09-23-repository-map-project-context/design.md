# Design

## Решение

Повторно использовать валидатор списка исключений, который применяет `inventory`, но ограничить чтение входного файла карты её собственным пределом 64 КиБ. При отсутствии списка действует прежний обход. Некорректный список даёт `unknown` и не применяется частично. Совпавший путь пропускается до чтения метаданных; в отчёт попадает только путь и фиксированный тип `project-exclusion`, без `reason` из проекта. Карта не проверяет audit receipt и не объявляет исключение одобренным аудитом.

Сопоставление записей и фактических путей вынести в общий helper для `inventory` и `map`: точное совпадение на всех платформах, затем на Windows — совпадение ASCII-букв без учёта регистра. Это закрывает распространённый случай `Artifacts`/`artifacts`, не меняя поведение Unix.

`.highgrade/releases` — копия локально установленного CLI и шаблонов, поэтому исключается по точному маршруту; `.highgrade/project` остаётся видимой. `.pnpm-store`, `.output` и `.tanstack` добавляются к встроенным кэшам. Широкое имя `artifacts` в общий список не добавляется: оно может быть исходником другого проекта и в SNAF уже задано локальным списком.

Файл `src/router.{ts,tsx,js,jsx}` помечается как `router-file` только по относительному пути. Это кандидат для чтения агентом, без вывода команд или заявления о конкретном фреймворке.

## Проверки

Фикстуры должны показать: исключённый каталог не читается и не даёт ложных кандидатов; свободный текст причины не попадает в отчёт; испорченный список даёт `unknown`; проект без списка продолжает работать; `.highgrade/project` и скрытые навыки сохраняются; маршрутизатор попадает в `entry_points`. После тестов запустить кандидат на SNAF и сравнить категории и статус с прежним снимком.
