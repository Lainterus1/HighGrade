# Design

`highgrade-approve` принимает одну ясную задачу. `work` уже доводит код, документы, проверки и ревью до готовности; approve сверяет доказательства с точным составом, оформляет завершение OpenSpec, готовит и проверяет staged diff, создаёт коммит. Если местная инструкция назначает обратимую локальную активацию частью этого этапа, вызов approve разрешает её из зафиксированного SHA; отсутствие такого маршрута не блокирует коммит. Ошибка активации не отменяет коммит и не выдаётся за полную готовность. В других проектах локальной активации может не быть.

`highgrade-push` выбирает непрерывный диапазон локальных коммитов и удалённую цель. Перед отправкой сверяет каждую задачу и посторонние коммиты, состояние удалённой ветки и возможный автоматический деплой. Явное поручение с диапазоном и целью не требует повторного согласования; неоднозначное «push» сначала показывает пакет. После обычного push сверяет удалённый SHA. Навык не активирует пользователя локально и не делает новый коммит.

Миграция глобальной установки с v0-2-6 создаёт оба новых маршрутизатора до переключения активного указателя. Старый `highgrade-deploy` удаляется только после проверки новой поставки. При откате его восстанавливают из проверенной копии до переключения, затем удаляют новые маршрутизаторы. Прерванная операция оставляет активный журнал проверяемым. Новый CLI обозначает известные неактивные остатки; старый CLI не знает новых имён, поэтому каждый новый SKILL.md сверяет своё владение с активным журналом до выполнения.

Для исходного High Grade локальный approve собирает изолированный `git archive` локального коммита и выполняет `global-update` preview/apply по проектной инструкции. Публикация этого же или последующего диапазона осуществляется отдельным push; локальную активацию не называют публикацией. Запись о фактическом выпуске хранит исходный SHA, удалённый SHA и активную версию без переписывания исторического ревью.

Первый выпуск v0-2-7 требует перехода: в активной v0-2-6 ещё нет `highgrade-approve`. При явном поручении принять этот выпуск исходный проект читает проверенную локальную часть `procedures/deploy.md` действующей v0-2-6 для коммита; дальнейшую местную активацию выполняет CLI из изолированной копии этого SHA по проектной инструкции. Это проектная переходная процедура, а не утверждение о запуске отсутствующего навыка. После `global-status` v0-2-7 применяется обычный новый маршрут. Переход не даёт разрешения на коммит или активацию от одной задачи по реализации.
