# Пилот передачи bootstrap в init

Дата: 2026-09-23. Временный проект Parcel Notes создан в системном каталоге Temp только для эксперимента и удалён после проверок. Пользовательская установка High Grade и внешние проекты не изменялись.

## Исходный проект и решение агента

В проекте были README, маленький Python CLI и тест, `notes/platform.md` с архитектурой, `CONTRIBUTING.md` со смешанными инженерными правилами и командами, а также `guides/CLAUDE.md` об отдельном эксперименте. Не было AGENTS, канонических документов в `docs/`, проектной инструкции и реестра.

Первый `inspect --bootstrap` вернул структурный `failed`: шесть из семи путей отсутствовали; четыре ссылки из README отсутствовали, а две ссылки с отсутствующими источниками имели `unknown`. Обход посетил 10 записей и прочитал 2 файла. Кандидат `CONTRIBUTING.md` для DEVELOPMENT был полезен, но покрывал также ENGINEERING; `guides/CLAUDE.md` для AGENTS был ложным. Архитектуру в `notes/platform.md` и инженерные правила внутри `CONTRIBUTING.md` агент нашёл при ручном чтении, вне списка кандидатов. Итого из двух показанных кандидатов один содержал часть нужной роли, один был ложным; два содержательных источника для обязательных ролей сканер сам не выделил. Это искусственный пример, не оценка точности на реальных проектах.

| Обязательный путь или связь | Состояние и кандидат | Проверенное содержание вне кандидатов | Решение |
|---|---|---|---|
| `README.md` | Есть; ссылок на четыре канонических документа нет | Назначение проекта соответствует роли | Сохранить, добавить ссылки |
| `AGENTS.md` | Нет; `guides/CLAUDE.md` предложен по имени | В `CLAUDE.md` только заметка об отдельном эксперименте; агентских правил нет | Отклонить кандидата с причиной, создать AGENTS и ссылку на инструкцию |
| `docs/ARCHITECTURE.md` | Нет; кандидатов нет | Устройство найдено в `notes/platform.md` | Перенести и обновить входящую ссылку |
| `docs/ENGINEERING.md` | Нет; кандидатов нет | Инженерные правила найдены внутри `CONTRIBUTING.md` | Выделить в отдельный документ |
| `docs/DEVELOPMENT.md` | Нет; кандидат `CONTRIBUTING.md` | В нём же есть реальные команды; документ смешанный | Выделить команды; оставить в CONTRIBUTING навигацию |
| `.highgrade/project/INSTRUCTIONS.md` | Нет; кандидатов нет | Проектных решений High Grade ещё нет | Создать содержательную инструкцию и связь с реестром |
| `.highgrade/project/documents.json` | Нет; кандидатов нет | Реестра не было | Создать записи ролей, областей и бюджетов |
| Шесть обязательных связей | Четыре `missing`, две `unknown` из-за отсутствующих источников | После переноса известны все целевые пути | Обновить README, AGENTS и инструкцию; повторить проверку |

Открытых вопросов после полного чтения синтетического проекта не осталось. `guides/CLAUDE.md` сохранили как отдельный исторический документ; пустой каталог `notes` удалили. Записи реестра классифицировали остальные области.

## Проверки результата

- До адаптации Python-тест проекта: 1 пройден. После адаптации: 1 пройден.
- После адаптации `inspect --bootstrap`: `passed`, все семь путей и шесть связей присутствуют, `candidate_scan=not_needed`, `visited_entries=0`.
- Обычный `inspect`: сначала `unknown` из-за оставшегося пустого `notes`; после удаления пустого каталога — `passed` без находок. Это показывает, что итоговая проверка выявила и несоответствие карты областей, которое предварительная проверка не обещает покрывать.
- `doctor` подтвердил совместимость проектной инструкции; общий статус `unknown` только из-за отсутствия `openspec` в текущем `PATH` пилотного процесса. Спецификации поведения у синтетического проекта не было.

Вывод: механическая проверка путей и ссылок полезна как вход и итоговый контроль. Поиск кандидатов даёт лишь подсказки; сохраняем его для отсутствующих путей, но не расширяем эвристики по этому примеру. Структурный `failed` до инициализации должен переводиться в таблицу адаптации, а не останавливать полный аудит.

## Проверки исходного кандидата v0-2-4

- `cargo fmt --all -- --check`, `cargo build --release --locked`, `git diff --check` и `node scripts/check-repository.mjs` прошли.
- `cargo test --locked`: 62 теста пройдены, включая 14 сценариев bootstrap. Контрактный тест использует настоящие шаблоны из `kit/templates/` и проверяет их структурную совместимость с CLI; содержательную пригодность шаблонов он не доказывает.
- Все 22 SHA256 в `kit/manifest.json` совпали с материалами. Изолированная установка v0-2-4, `global-status` и bootstrap установленным CLI прошли; профиль удалён.
- OpenSpec 1.13.1 с отключённой телеметрией: строгая валидация до архивации — 3 пройдено, 0 ошибок. Информационные замечания касаются длины нескольких требований.
- Повторная проверка MyCodex: `candidate_scan=not_needed`, `visited_entries=0`, все пути и связи присутствуют. SNAF только чтением: `candidate_scan=performed`, отсутствует проектная инструкция; остальные находки соответствуют прежней проверке. Полный реальный init на SNAF не проводился.
- Независимое статическое ревью дало `REVIEW_GO` без подтверждённых замечаний. Сборку и сценарии проверял основной исполнитель.
- OpenSpec-изменение штатно архивировано как `2026-09-23-improve-bootstrap-init-handoff`; два требования объединены в действующей спецификации `project-bootstrap`. Строгая валидация после архивации: 2 пройдено, 0 ошибок, только информационные замечания о длине требований.
- После архивации маршрут исходного проекта измерен в 78 804 байта, согласованный бюджет снижен с временных 82 000 до 80 000 байт. Обычный `inspect` оставляет лишь прежнее предупреждение `ExternalLinkUnchecked` для GitHub-ссылки README.
