# Разработка и проверки

Область: воспроизводимые действия в High Grade. Статус каждой выполненной проверки находится в [ревью организации](reviews/project-organization-review.md) и [манифесте импорта](imports/plugins-import.json), не в этом справочнике команд.

## Проверка структуры

Из корня High Grade:

```powershell
node scripts/check-repository.mjs
node scripts/check-repository.mjs --verify-import
```

Первая команда проверяет обязательные документы и точки входа плагинов, выводит размеры и явно обозначает отсутствие согласованных бюджетов. Вторая дополнительно сверяет файлы с манифестом первоначального переноса. После намеренных изменений плагина несовпадение с исходным импортом ожидаемо; это проверка происхождения, а не запрет разработки. Скрипт не запускает плагины, анализаторы или установку и ничего не записывает.

## SVG Vectorizer

Исходник: [README плагина](../plugins/svg-vectorizer/README.md). Там указаны зависимости, установка окружения, native тесты и smoke-проверка. Старый VERIFICATION.md и примеры — исторические доказательства, не проверка нового пути. Нельзя переносить виртуальное окружение как переносимую зависимость.

## Code Health Audit

Вход: [SKILL.md](../plugins/code-health-audit/skills/code-health-audit/SKILL.md); зависимости и preflight: [toolchain](../plugins/code-health-audit/skills/code-health-audit/references/toolchain.md). Аудит предназначен для Python; не применять его оценку ко всему смешанному репозиторию High Grade. Его собственные тесты расположены внутри scripts/tests; для полного прохода нужен предусмотренный закреплённый runtime.

## Обновление установленной копии

Изменение plugins/ не обновляет кеш Codex. Переключение источника marketplace, переустановка и проверка обнаружения выполняются отдельным поручением после проверки компонента. В текущем переносе эти действия не выполнялись. Документация плагина об историческом personal-пути не является текущим источником разработки High Grade.

## Что ещё не готово

Проектный CLI, init/work/refresh/update, связь проверок с OpenSpec, динамические бюджеты и хуки обсуждаются в [TOOLING](proposals/TOOLING.md) и [техническом предложении](proposals/technical-design.md). Их набор и упаковка не утверждены; программы сейчас не пишутся. Полные функциональные тесты плагинов на новом месте требуют отдельных окружений; structural PASS этого не заменяет.
