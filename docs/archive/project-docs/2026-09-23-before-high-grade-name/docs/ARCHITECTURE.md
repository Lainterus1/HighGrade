# Действующая архитектура MyCodex

Область: что фактически существует в репозитории разработки. Устройство будущего продукта рассматривается в [техническом предложении](proposals/technical-design.md), его требования — в [SPECIFICATION](workflow/SPECIFICATION.md).

```text
MyCodex/
  README.md, AGENTS.md           вход и правила проекта
  docs/
    ARCHITECTURE.md              действующее устройство
    ENGINEERING.md               правила изменения
    DEVELOPMENT.md               доступные команды
    workflow/                    принятые требования и политика контекста
    proposals/                   инструменты и технические варианты для обсуждения
    research/                    основания подхода, факты и ограничения источников
    reviews/                     результаты проверок
    imports/                     доказательства переноса и сохранности
    archive/                     заменённые документы и завершённые планы
  plugins/                       самостоятельные исходные пакеты
  scripts/check-repository.mjs    уже существующая проверка bootstrap
  .mycodex/project/documents.json первичная карта документов
```

SVG Vectorizer — отдельный пакет с Python и Node-компонентами. Code Health Audit — отдельный Python-плагин. Зависимости, тесты и установки не объединены; распределение по направлениям отложено автором. Копии в прежних каталогах и кеше Codex сохранены, подключение не переключено.

check-repository.mjs существовал до текущей организации. Он проверяет роли/файлы, измеряет размер и по флагу сверяет импорт. Он не реализует смысловой анализ, бюджеты или полный CLI. В этой задаче он не меняется.

Четыре навыка, поставки releases, загрузчик, OpenSpec-интеграция, хуки и установка из технического предложения пока отсутствуют. Git не инициализирован. Реестр .mycodex — начальные данные сопровождения, а не признак работы будущего установщика.

## Владение знаниями

SPECIFICATION владеет требованиями переносимого workflow; CONTEXT — его политикой документации. ENGINEERING применяет общие правила к разработке MyCodex ссылками, а не копиями. TOOLING содержит варианты программ. Технический документ детализирует один вариант и не выбирает его за автора. Исторические документы не определяют текущий следующий шаг.
