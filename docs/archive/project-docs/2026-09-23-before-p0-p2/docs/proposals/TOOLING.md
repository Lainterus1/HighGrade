## Четыре навыка

Названия highgrade-init/work/refresh/update — рабочие имена будущих навыков.

| Навык | Вход | Обязанность | Выход и граница |
|---|---|---|---|
| Инициализация | Запрос, существующий контекст, ответы автора | Полный аудит готового проекта, интервью, режим документации, политика Git, источники, предложение бюджетов | Согласованное устройство и один план. Преобразования затем по поручению; приёмка адаптации отдельная |
| Выполнение | Порученная задача и её основной источник | Область, реализация, штатные проверки, ревью по риску, документация, контекст, архив, временные обходы | Результат с доказательствами либо незавершённое состояние и один Next. Для малых задач достаточно кратких правил AGENTS |
| Актуализация | Явный запрос и область | Общая с init процедура обследования, смысловая сверка, пересмотр бюджетов и разрешённые исправления | Что подтверждено, изменено и неизвестно. В режиме анализа не пишет файлы |
| Обновление | Явный запрос и выбранная поставка | Проверка целостности и совместимости, сохранение адаптации, переключение и проверка результата | Рабочая выбранная поставка либо сохранённая прежняя с объяснением; конфликт не активируется |

Архив и документы сопровождаются штатно. Отдельного навыка аудита нет. OpenSpec владеет задачами своих изменений; сводный план не становится вторым backlog. Обязательное независимое ревью не заменяется самопроверкой при недоступности проверяющего.

## Один Rust CLI с независимыми модулями

Имена ниже — проектируемые операции, не готовые команды для запуска.

| Операция | Вход → выход | Полномочия |
|---|---|---|
| doctor | Корень, конфигурация, средства → доступность, версии, ограничения | Чтение; без установки зависимостей и запуска сервисов |
| inspect | Область, реестр документов → размеры, ссылки, маршруты контекста, сигналы пересмотра | Чтение; не доказывает смысловую согласованность и не повышает бюджеты |
| trace | Спеки, отметки, инвентарь тестов, отчёты и записи запусков → связи, статусы, пробелы, актуальность | Чтение; не запускает тесты и не ведёт ручной реестр связей |
| install / update | Выбранная локально подготовленная основа, проект → проверенное подключение/обновление | Только разрешённые файлы; сохранение и восстановление прежнего состояния |

Общая часть: настройки, пути, форматы и диагностические результаты. Общий запускатель тестов, отдельный архиватор, универсальный анализатор зависимостей и BDD-движок исключены. Проектные команды напрямую запускает агент по WF-CHECKS-01.

## Проверки и доказательства

Первый выпуск подтверждает связи на Rust и Playwright Test (WF-TRACE-01–03). Отдельные отметки содержат ID сценариев, названия тестов свободны. Синтаксис и извлечение проверяются до заявления о поддержке. Производная карта не редактируется вручную; ссылка не равна исполнению или смысловой правильности теста.

WF-EVIDENCE-01–03 определяют компактную запись и исходный машинный отчёт, Git для значимых доказательств, локальную тяжёлую диагностику и перепроверку по влиянию изменений. Видео выключено по умолчанию. Неизвестное влияние не считается актуальным подтверждением. Параметры хранения согласуются в проекте.

## Выпуск и развитие

| Категория | Состав |
|---|---|
| Первый выпуск | Windows; Codex app и CLI проверяются отдельно; русский; исходники GitHub; локальная сборка; добровольные обновления; пять ролей документов и реестр |
| Запланировано позднее | Covers-обёртка; отдельные постепенные миграции собственного SVG/CHA-кода на Rust |
| По потребности | Единый подробный отчёт тестов; дополнительные адаптеры; хуки при доказанных пропусках; английский перевод; готовые бинарные поставки |
| Исключено | Центральное управление проектами, телеметрия, автоматические обновления, обязательный gstack, второй backlog, переписывание сторонних движков |

Выбрано разрешительное направление лицензирования; конкретная лицензия — после проверки состава. Тренировочные проекты уже есть у автора; выбор и испытания отложены до готовности кандидата (WF-PILOT-01), пути сейчас не требуются.

Следующее действие — P0 из [плана](../plans/first-release.md). Технические детали прорабатываются исполнителем; изменение продуктовых гарантий возвращается автору. Программы пишутся только по отдельному поручению.
