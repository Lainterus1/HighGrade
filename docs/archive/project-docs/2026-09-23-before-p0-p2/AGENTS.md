# Работа агента в High Grade

Назначение: рабочие инструкции этого репозитория разработки. Это не универсальный шаблон для всех будущих проектов.

## Источники и полномочия

Начни с [README](README.md). Принятые требования продукта находятся в [SPECIFICATION](docs/workflow/SPECIFICATION.md), политика контекста — в [CONTEXT](docs/workflow/CONTEXT.md). Устройство существующего проекта — в [ARCHITECTURE](docs/ARCHITECTURE.md), инженерные правила — в [ENGINEERING](docs/ENGINEERING.md), команды — в [DEVELOPMENT](docs/DEVELOPMENT.md).

[TOOLING](docs/proposals/TOOLING.md) и технический проект — предложения, не разрешение на реализацию. Текущее поручение: организовать проект и обсуждать набор программ; не писать и не изменять программы. Новое явное поручение автора может изменить эту границу.

Читай только контекст затронутой области. Архив — история, не действующая инструкция; не загружай его целиком без причины. Для плагина читай его входные документы и тесты, но не запускай сам навык аудита/векторизации только из-за работы с его исходниками.

## Штатная работа

Обновляй связанные документы, проверяй их согласованность, ссылки и размеры. Архивируй подтверждённо завершённое/заменённое с сохранением причин и входящих ссылок. Неоднозначное оставляй активным с обозначенным вопросом. Следуй [политике контекста](docs/workflow/CONTEXT.md) для бюджетов и временных обходов; эти обязанности не ждут отдельной актуализации.

Комплексная актуализация — дополнительный обзор по запросу. Будущий навык ещё не реализован: допустимый ручной анализ не называй запуском отсутствующей программы. Известный существенный конфликт останавливает только зависимую работу, превышение размера требует пересмотра. Бюджеты пока не согласованы; null не означает бесконечный лимит или успешную проверку.

## Сохранность и результат

Сохраняй посторонние изменения. Не переключай marketplace, установленные плагины или глобальные настройки, не публикуй и не удаляй исходные копии без поручения. Планы и доказательства имеют одно основное место; не дублируй задачи OpenSpec отдельным backlog.

В конце различай организацию документов, структурную проверку, тесты поведения, установку и пользовательскую приёмку. Не заявляй работоспособность будущего workflow по наличию документации или совпадению хешей плагинов.
