# Работа агента в MyCodex

Назначение: порядок работы внутри репозитория разработки workflow и плагинов. Эти инструкции не являются шаблоном AGENTS для всех будущих проектов.

## Контекст задачи

- Читай [README](README.md), затем только нужные части [ARCHITECTURE](docs/ARCHITECTURE.md), [ENGINEERING](docs/ENGINEERING.md) и [DEVELOPMENT](docs/DEVELOPMENT.md).
- Вопросы продуктового устройства workflow сверяй с [концепцией](docs/designs/codex-workflow-design.md) и её дополнением о контексте. Технический проект — предложение, не доказательство существующей реализации.
- Для плагина читай его SKILL.md, имеющиеся инструкции, конфигурацию и тесты. Не запускай сам навык аудита или векторизации лишь потому, что редактируешь его исходники.
- Состояние задачи и доказательства бери из её основного плана; не создавай дублирующий список OpenSpec-задач.

## Штатное сопровождение

В рамках разрешённой задачи обновляй связанные документы, проверяй их согласованность с кодом, ссылки и размеры. Архивируй подтверждённо завершённое/заменённое с сохранением причин и ссылок; для неоднозначного материала сначала обозначь вопрос. Учитывай временные обходы по ENGINEERING. Не откладывай сопровождение до отдельной актуализации.

Отдельная актуализация даёт обзор состояния проекта по запросу. Навык ещё не реализован; соответствующий разрешённый анализ выполняется явно, без заявления о запуске отсутствующего инструмента.

## Границы

Сохраняй посторонние изменения. Не переключай установленные плагины, marketplace, глобальные настройки Codex, не публикуй и не удаляй исходные копии без соответствующего поручения. Новые существенные изменения поведения и зависимостей согласуй; разрешённые локальные детали выполняй самостоятельно. Не объявляй структурную проверку полноценным тестом плагина.

Существенный конфликт блокирует только зависимую работу. Превышение объёма вызывает пересмотр, не остановку всего проекта. Диапазоны бюджетов пока не согласованы: не выдумывай их и не выдавай отсутствие лимита за успешную проверку бюджета.
