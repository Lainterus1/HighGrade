# Архитектура MyCodex

Область: текущее устройство репозитория разработки. Целевое устройство распространяемого workflow описано отдельно в [техническом проекте](designs/mycodex-technical-design.md).

## Что существует

- Корневые инструкции и docs: назначение, инженерные правила, процедуры, согласованные решения и планы.
- plugins/svg-vectorizer: самостоятельный пакет преобразования растра в SVG с Python- и Node-компонентами.
- plugins/code-health-audit: самостоятельный Python-плагин аудита с закреплёнными анализаторами и контрактами доказательств.
- scripts/check-repository.mjs: небольшая проверка структуры этого репозитория и, по флагу, точности первоначального импорта. Это не будущий универсальный CLI MyCodex.
- .mycodex/project/documents.json: первичная карта документации; бюджеты не назначены. Файл пока обслуживается локальной проверкой структуры, не полной реализацией реестра из технического проекта.

## Границы компонентов

Плагины хранятся рядом, но их зависимости, тесты, лицензирование и способы установки не объединяются. Они не становятся обязательными частями workflow. Последующее распределение по направлениям — отдельная задача.

Исходники plugins — новое место сопровождения. Копии в исходных каталогах и кеше Codex сохранены; их работа и обновление не переключены. Поддержка исходников, проверка runtime и установка в Codex — разные состояния.

Workflow пока состоит из проектных документов. Каталоги core, releases, четыре навыка и общий CLI из проекта устройства ещё не созданы. Нельзя ссылаться на них как на доступные команды.

## Источники решений

Актуальны [концепция](designs/codex-workflow-design.md), [контекст](designs/context-governance-proposal.md) и текущее уточнение автора: сначала поддерживать плагины в plugins, распределить по блокам позже. Существующий mycodex-organization.md сохранён как ранний черновик, не активный источник структуры; его распределение по направлениям сейчас не применяется.
