# Инженерные соглашения

Область: как изменяем MyCodex и его компоненты. Текущее устройство находится в ARCHITECTURE, команды — в DEVELOPMENT.

## Изменения и доказательства

Выполняй минимальное изменение, нужное для задачи. При изменении поведения согласуй требования и обеспечь предусмотренную проверку. В этом bootstrap OpenSpec ещё не установлен: не создавай фиктивные спеки или результаты. Подключение OpenSpec относится к реализации согласованного workflow.

Сохраняй native тесты каждого плагина и закреплённые версии его зависимостей. Новый общий runtime workflow не заменяет Python-зависимости существующих плагинов. Проверки структуры, совпадение файлов, полноценные тесты, установка и пользовательская приёмка сообщаются отдельно.

## Документы и временные решения

Каждое правило имеет одно основное место; остальные документы ссылаются на него. Структура гибкая, назначение и действующий статус ясны. При сокращении сохраняй требования, исключения и причины. Локальная проверка не подтверждает весь проект.

Временный обход допустим внутри разрешённой задачи, если сохраняет требования, не скрывает ошибку и имеет причину, проверку, условие удаления и ссылку на задачу. При наступлении условия пересмотр обязателен, молчаливого продления нет. Срок не разрешает автоматически удалять рабочий код. Предусмотренное поведение при отказе описывается как требование, не временная заплатка.

Архивируй подтверждённо завершённые материалы с причинами и исправлением ссылок. История исходников и удаление функциональности не заменяются переносом кода в archive. Пока Git не инициализирован, сохраняй исходные копии/манифесты перед существенными изменениями; не заявляй наличие Git-истории.

## Поставка

Не коммить секреты, .venv, node_modules, кеши и локальные отчёты. До публикации проверь права и лицензии собственных пакетов и всех зависимостей; наличие разрешения на перенос исходников не доказывает готовность лицензирования для GitHub. Никакой автоматической отправки обратной связи.
