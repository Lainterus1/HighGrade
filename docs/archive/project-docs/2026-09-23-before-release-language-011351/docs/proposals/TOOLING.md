# Набор инструментов для обсуждения

Статус: обсуждение инструментов с отдельно отмеченными принятыми решениями. Автор поручил организовать материалы и обсуждать назначение программ, не писать их. Требования в [SPECIFICATION](../workflow/SPECIFICATION.md) и [CONTEXT](../workflow/CONTEXT.md) приняты; принятые роли навыков отмечены ниже, единый командный интерфейс принят, Rust выбран; зависимости, конкретные команды и форматы ещё обсуждаются. Хуки исключены из первой версии. Реализация не поручена.

## Что уже есть

| Компонент | Фактическая роль | Граница |
|---|---|---|
| SVG Vectorizer | Исходный пакет в plugins/svg-vectorizer | Самостоятельная поддержка; не обязательный инструмент workflow |
| Code Health Audit | Исходный пакет в plugins/code-health-audit | Аудит Python; не универсальная оценка всего проекта |
| check-repository.mjs | Ранее созданная проверка структуры, размеров и импорта High Grade | Не изменяется в текущей задаче; не будущий общий CLI |

Команды доступных проверок находятся в [DEVELOPMENT](../DEVELOPMENT.md). Прежние установленные и исходные копии плагинов не обновляются автоматически от изменения plugins/.

## Состав навыков и открытые детали

| Навык | Вход → результат | Что требуется решить |
|---|---|---|
| Инициализация | Для существующего проекта принят полный аудит WF-INIT-01 в [требованиях](../workflow/SPECIFICATION.md); аудит и интервью дают основания для адаптации, устройства и плана | Детальный состав отчёта, сохранение незавершённого интервью и согласование целевого устройства |
| Выполнение | Приняты размещение процедуры WF-EXEC-01 и ревью по риску WF-EXEC-02 в [требованиях](../workflow/SPECIFICATION.md); реализации нет | Условия подключения навыка, контрольные точки и формат результата |
| Актуализация | Явный запрос → дополнительный обзор состояния и разрешённые исправления | Состав прохода и отчёта; не переносить сюда штатные обязанности |
| Обновление workflow | Принят отдельный навык по явному запросу, WF-UPDATE-01 в [требованиях](../workflow/SPECIFICATION.md); реализации нет | Команды, проверка совместимости и механизм восстановления в границах D16/D20/D21 |

Принято [WF-AUDIT-01](../workflow/SPECIFICATION.md): инициализация и актуализация используют общую внутреннюю процедуру обследования; отдельного навыка аудита нет. Для самостоятельного обследования используется режим анализа актуализации.

Таким образом, приняты четыре роли навыков: инициализация, выполнение, актуализация и обновление workflow.

Имена highgrade-init/work/refresh/update в техническом документе — кандидатный интерфейс. Ни один такой навык сейчас не создан и не установлен.

Принято [WF-INIT-02](../workflow/SPECIFICATION.md): при инициализации существующего проекта автор выбирает сохранение и адаптацию полезной структуры документации либо приведение к стандартному шаблону High Grade. Полный аудит помогает оценить последствия. Выбор фиксируется в проектной адаптации и плане; обязательные роли и требования качества действуют в обоих режимах.

Принято [WF-INIT-03](../workflow/SPECIFICATION.md): после начала согласованной адаптации существующего проекта обычная продуктовая разработка возобновляется по завершении обязательных этапов адаптации. Во время перехода допускаются работы по адаптации и необходимые срочные исправления. Это порядок работ, а не разрешение на реализацию; конкретные принятые пробелы D22 сохраняются.

Принято [WF-INIT-04](../workflow/SPECIFICATION.md): после выполнения плана, проверок и необходимого ревью агент готовит итоговый отчёт, а пользователь явно принимает первоначальную адаптацию. До приёмки обычная продуктовая разработка не возобновляется; исключение для срочных исправлений сохраняется. Техническая готовность не равна приёмке; правило не повторяется для каждой обычной задачи.

Принято [WF-GIT-01](../workflow/SPECIFICATION.md): при инициализации автор выбирает локальные коммиты по отдельному поручению либо автоматические локальные коммиты завершённых задач после проверок и необходимого ревью. Политика сохраняется в проекте; посторонние изменения не включаются. Отправка на GitHub, слияние и выпуск требуют отдельных полномочий. Выбор политики самого High Grade и операции Git сейчас не поручены.

## Предложенные скрипты/команды

| Назначение | Доказательство / результат | Не должно делать |
|---|---|---|
| Диагностика готовности | Доступность зависимостей, команд и конфигурации | Устанавливать/чинить окружение без поручения |
| Измерение контекста | Размеры, связи, область и сигналы пересмотра | Самостоятельно менять смысл или повышать потолки бюджетов |
| Связи сценариев и проверок | По [WF-TRACE-01](../workflow/SPECIFICATION.md) карта собирается из отметок в тестах; проверяются ссылки, результаты и пробелы | Вести второй ручной реестр связей или выдавать ссылку за правильный выполненный тест |
| Установка/обновление | Сохранение адаптации, проверка кандидата, восстановление | Обновлять все проекты или молча активировать конфликтующие правила |

Принято [WF-CHECKS-01](../workflow/SPECIFICATION.md): агент запускает штатные команды проверок напрямую и фиксирует результаты. Общий запускатель проверок исключён; проверка связей сценариев и тестов сохраняется.

Принято [WF-ARCHIVE-01](../workflow/SPECIFICATION.md): архивирование выполняет агент штатными средствами, общие проверки контролируют сохранность и ссылки. Самостоятельный архиватор исключён.

Принято [WF-CLI-01](../workflow/SPECIFICATION.md): один командный инструмент с подкомандами и независимыми модулями. По [WF-RUST-01](../workflow/SPECIFICATION.md) выбран Rust; собственные плагины также планируется переносить постепенно, с отдельной оценкой каждого. Существующие программы пока не изменяются.

Принято [WF-TRACE-02](../workflow/SPECIFICATION.md): первые испытания связи требований с тестами и результатами — Rust + Playwright Test, до первого выпуска. Конкретный инструмент запуска/отчёт Rust, отметки и форматы ещё обсуждаются. Это проверка переносимости, а не обязательные зависимости каждого проекта; испытания пока не выполнены.

Принято [WF-TRACE-03](../workflow/SPECIFICATION.md): первая версия использует отдельные отметки рядом с тестами, имена свободные; конкретный синтаксис ещё проверяется. Программная обёртка наподобие Covers запланирована следующим этапом и не задерживает первый выпуск. Переход сохраняет ID сценариев и не вводит второй ручной источник связей.

Принято [WF-EVIDENCE-01](../workflow/SPECIFICATION.md): первая версия сохраняет компактную запись запуска и исходный машинный отчёт; чтение отчётов отделяется от сопоставления связей. Единый подробный отчёт High Grade возможен по подтверждённой потребности, но не запланирован как обязательный этап. Конкретные поля, пути и сроки хранения ещё обсуждаются.

Принято [WF-EVIDENCE-02](../workflow/SPECIFICATION.md): компактная запись и машинный отчёт значимых проверок сохраняются в Git вместе с материалами задачи; тяжёлая диагностика — локально вне Git. Видео по умолчанию выключено. Промежуточные результаты очищаются по согласованной политике; пути, пороги и сроки пока не выбраны. Большие или чувствительные отчёты требуют допустимого способа хранения с явными ограничениями доступности.

Принято [WF-EVIDENCE-03](../workflow/SPECIFICATION.md): актуальность результата определяется состоянием проверенной области и существенных зависимостей. Затронутые или неопределённые влиянием изменения требуют повторных проверок; несвязанные правки не отменяют результат автоматически. Используются штатные средства, границы проекта и оценка агента, без универсального анализатора зависимостей. Конкретный механизм фиксации состояния ещё обсуждается.

## Хуки и автоматика

Принято [WF-HOOKS-01](../workflow/SPECIFICATION.md): первая версия без хуков. Обязательные проверки выполняются по явной рабочей процедуре. Повторяющиеся подтверждённые пропуски на испытаниях — условие пересмотра этого решения. Ранее предложенный Stop-обработчик отложен; постоянный сервер и мониторинг не запрошены.

Принято [WF-RELEASE-01](../workflow/SPECIFICATION.md): первый выпуск workflow не зависит от миграций SVG и CHA на Rust; они планируются отдельными этапами.

Принято [WF-DISTRIBUTION-01](../workflow/SPECIFICATION.md): пока только GitHub-репозиторий с исходниками; готовые сборки и установочные пакеты отложены.

Принято [WF-LICENSE-01](../workflow/SPECIFICATION.md): для собственного содержимого выбрано свободное использование, изменение и распространение, включая коммерческое, без обязательного открытия доработок. Конкретная лицензия выбирается после проверки происхождения и условий заимствованных материалов; сторонние лицензии сохраняют силу. Лицензия ещё не применена, публикация не поручена.

## Порядок следующего обсуждения

1. Выбрать минимальные роли инструментов и границы ответственности, начиная с штатного выполнения и дополнительной актуализации.
2. Затем определить входы/выходы, пользовательские команды и достаточные доказательства.
3. После этого выбрать упаковку и способ проверки совместимости. Реализацию начинать только по новому поручению.

[Техническая проработка](technical-design.md) сохраняет вариант с четырьмя навыками, CLI на Rust и локальными поставками. Его последовательность P1–P6 — возможный план последующей реализации, сейчас не активная задача. Другие варианты допустимы, если сохраняют принятые требования.
