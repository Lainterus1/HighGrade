# Разработка и проверки

Область: воспроизводимые действия в High Grade. Историческая организация проверялась в [раннем ревью](reviews/project-organization-review.md); текущая консолидация — в [новом отчёте](reviews/first-release-review.md). Происхождение пакетов — в [манифесте импорта](imports/plugins-import.json). Этот файл содержит команды, не постоянно обновляемый журнал результатов.

## Проверка структуры

Из корня High Grade:

```powershell
node scripts/check-repository.mjs
node scripts/check-repository.mjs --verify-import
```

Первая команда проверяет обязательные документы и точки входа плагинов, выводит размеры и явно обозначает отсутствие согласованных бюджетов. Вторая дополнительно сверяет файлы с манифестом первоначального переноса. После намеренных изменений плагина несовпадение с исходным импортом ожидаемо; это проверка происхождения, а не запрет разработки. Скрипт не запускает плагины, анализаторы или установку и ничего не записывает.

## Обновление установленной копии

Изменение plugins/ не обновляет кеш Codex. Переключение источника marketplace, переустановка и проверка обнаружения выполняются отдельным поручением после проверки компонента. В текущем переносе эти действия не выполнялись. Документация плагина об историческом personal-пути не является текущим источником разработки High Grade.

## Что ещё не готово

CLI install/doctor/inspect и минимальный навык реализованы; [контракт](implementation/p0-p2-contract.md) описывает поддерживаемые форматы. Полные четыре процедуры и связь тестов с OpenSpec ещё не реализованы. Хуки исключены из первого выпуска. [TOOLING](proposals/TOOLING.md) задаёт обязанности, [техническое предложение](proposals/technical-design.md) — механизмы для проверки, [план](plans/first-release.md) — этапы. Автор разрешил P0–P2; последующие этапы этим поручением не охвачены. Полные функциональные тесты плагинов на новом месте требуют отдельных окружений; structural PASS этого не заменяет.

## Rust CLI P0–P2

Из корня проекта, Rust 1.97.0 Windows MSVC проверен:

```powershell
cargo fmt --all -- --check
cargo test --locked
cargo build --release --locked
.\target\release\highgrade.exe doctor --root "$PWD"
.\target\release\highgrade.exe inspect --root "$PWD" --registry .mycodex/project/documents.json
```

Первое получение зависимостей требует сети; с заполненным Cargo cache можно добавить --offline к cargo test/build. Rustfmt — компонент toolchain, он не включён в исходники проекта. Код 2 диагностики означает unknown, а не успешную проверку. В High Grade бюджеты не согласованы и OpenSpec не установлен: это ожидаемые открытые состояния, не повод менять конфигурацию ради зелёного отчёта.

Подключение к выбранному корню, только после полного аудита и явного согласования, описанных в контракте:

```powershell
.\target\release\highgrade.exe install --root '<целевой корень>' --source "$PWD/bundle" --audit '<путь к подтверждению относительно целевого корня>'
```

Эта команда копирует текущий exe, правила и минимальный навык; не проводит интервью и не принимает адаптацию. Пустой/синтетический аудит реального проекта недопустим. Не запускай установку на тренировочных проектах до согласованного этапа P6.

Обнаружение точки входа проверяется через Codex app-server JSON-RPC initialize → initialized → skills/list с `cwds=[целевой корень]`, `forceReload=true`. Такой результат устанавливает обнаружение навыка, не прохождение интерфейса приложения или полной процедуры init. Доказательства текущего прогона — [отчёт](reviews/p0-p2-review.md).
