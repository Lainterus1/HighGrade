## Замечания ревью и решения

- Вложенный junction мог пропустить запись Cargo: preflight всего target до сборки; регрессия проверяет сохранность внешнего каталога.
- Обычная параллельная release-сборка могла подменить бинарник после выхода Cargo: один зарезервированный target/release-build для кандидатов; обычный cache независим. Регрессия запускает конкурирующую сборку в нужном окне.
- Двойная ошибка rename могла удалить прежнего кандидата: recovery-копия вынесена из TemporaryDirectory; повтор отказывает до восстановления. Регрессия проверяет исходные байты.
- `CARGO_BUILD_TARGET` менял местоположение результата: сборщик теперь берёт executable из JSON-артефакта текущего Cargo запуска; регрессия собирает два разных SHA с разными target.
