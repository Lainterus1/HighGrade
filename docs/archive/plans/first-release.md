## Результат

Переносимый workflow: четыре навыка и небольшой Rust CLI, общая основа отдельно от проектной адаптации, без управления чужими проектами. Первая поставка русскоязычная, исходниками через GitHub, с локальной сборкой под Windows; Codex app и CLI проверяются отдельно. Автономность означает независимость установленных материалов от репозитория автора, а не работу самого Codex или сетевых тестов без интернета.

Обязательны обычная задача с документацией, контекстом, проверками и архивом без refresh; добровольное обновление с сохранением адаптации; связи сценариев с реально выполненными тестами Rust и Playwright. Скорость чужого BDD не является нормативом High Grade.

## Что уже существует

Пять основных документов, SPECIFICATION/CONTEXT, начальный реестр `.mycodex/project/documents.json`, архив, исследование BDD, импортные манифесты и существующий `scripts/check-repository.mjs`. Реестр имеет несогласованные бюджеты, скрипт подтверждает только структуру и импорт. SVG и CHA остаются независимыми пакетами; установленные копии не переключаются. Пилот SNAF проведён в отдельном проекте; PlantsNotify не начинался.

## Что не входит в первый выпуск

- Хуки: пересмотр при повторяющихся доказанных пропусках.
- Covers: запланированный следующий этап, сначала отдельные отметки.
- Миграции SVG/CHA: отдельные планы, не задерживают workflow.
- Универсальный подробный отчёт: только при подтверждённой потребности.
- Бинарные поставки, полный английский перевод, Linux/macOS: пока не заявляются.
- Центральное управление, автоматическая отправка ошибок, общий запускатель тестов, отдельный архиватор, собственный BDD-движок: исключены.

## Этапы и критерии выхода

P0–P5 имеют реализацию и локальные доказательства; P6 разделён на готовность кандидата и два последовательных пилота. Первый пилот технически проверен, но ещё не принят автором. Отметка выполнения требует доказательств, а не наличия этого списка.

Это один сводный план до подключения OpenSpec. Когда подробные задачи поведения перейдут в OpenSpec, здесь остаются ссылки и порядок этапов, а не дублирующие списки задач.

- [x] P0 — технические контракты без изменения продуктовых гарантий; runtime OpenSpec проверен в P4.
- [x] P1 — локальная поставка и обнаружение навыка backend app/CLI. Полный GUI-сценарий не проверен; полные процедуры — P3.
- [x] P2 — диагностика и контекст; несогласованные бюджеты сохраняют unknown.
- [x] P3 — четыре процедуры, общий аудит, автономная поставка; агентское поведение проверяется на пилотах.
- [x] P4 — OpenSpec 1.13.1, реальные Rust/Playwright отчёты и отрицательные проверки; Rust-срез ограничен стандартными top-level integration tests.
- [x] P5 — штатный архив в процедурах, update с выбранным новым exe, preview/decision, переключением и откатом; ограничение router ABI описано.

Сроки уточняются после P0/P1, особенно для Rust-отчётов, интеграции Codex и восстановления на Windows. Численных обещаний скорости или длительности пока нет.

## Матрица доказательств

| Область | Подтверждение | Отрицательная проверка |
|---|---|---|
| Подключение | Основа обнаруживается обоими интерфейсами | Нет CLI, конфликт имени, повтор установки, обрыв; никакой активации до требуемого аудита |
| Init | Полный аудит применимой области, устройство и план | Непрочитанные файлы видны; интервью продолжается; A/B не выбирается молча |
| Адаптация | Проверки и ревью → отчёт → явная приёмка | Молчание/pass не приёмка; продуктовая работа до неё не возобновляется; срочное исправление пересматривает доказательства |
| Work / Git | Проверки, документы, архив без refresh | Коммит без поручения при A; чужие файлы в коммите при B; незавершённое обязательное ревью не объявляется выполненным |
| Контекст | Размеры документов и маршрута, область, ссылки | Неизвестный бюджет не PASS; малые повышения не обходят потолок; новая область не теряется |
| Trace | Связь с обнаруженным и выполненным тестом | Дубли, ложная ссылка, skipped, пустой suite, устаревший/повреждённый отчёт; старое исключение не покрывает изменённый сценарий |
| Refresh | Область, расхождения и ограничения | Режим анализа не пишет; локальный результат не выдаётся за глобальный |
| Archive | История, причины и доказательства сохранены | Отклонённая гипотеза не меняет спеки; коллизия/обрыв не теряют оригинал |
| Update | Кандидат проверен до активации | Конфликт смысла/формата, изменённые входы, занятый файл, обрыв, postcheck failure, чужая правка |
| Переносимость | Нет зависимости от каталога автора и gstack | Не сканирует соседей, не ищет молча другой runtime; нет абсолютных авторских путей |
| Windows | Пробелы, кириллица, CRLF, регистр | Junction/выход за корень, заблокированный файл, некорректный путь дают явную ошибку |

Для параметризованных тестов и повторных попыток сохраняется различимость исполнения: последний pass не скрывает прежний сбой. Конкретный агрегат — контракт P0/P4; исходные результаты не теряются. Большинство логики CLI проверяется локально; немного интеграционных проверок подтверждают реальные границы. Браузерные проверки не имеют норматива «тысячи specs/с».
