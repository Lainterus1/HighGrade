# Контекст и штатное сопровождение

Действующая политика контекста и архива для High Grade и подключённых проектов. История решений — в [SPECIFICATION](SPECIFICATION.md), проверки — в [QUALITY](QUALITY.md), команды — в [DEVELOPMENT](../DEVELOPMENT.md). Автоматический контроль не гарантирует полноту.

## D25 — документы и их ответственность

| Обязательный источник | Единственная основная роль |
|---|---|
| README | Назначение и границы проекта, навигация |
| AGENTS | Порядок работы агента, полномочия, маршруты чтения |
| ARCHITECTURE | Действующее устройство, компоненты, данные и инварианты |
| ENGINEERING | Инженерные соглашения, обработка ошибок, зависимости, совместимость, критерии качества изменений |
| DEVELOPMENT | Воспроизводимые команды подготовки, запуска, проверок и применимых эксплуатационных процедур |
| Машинный реестр | Пути, роли, область, режим чтения, бюджеты, основания и условия пересмотра; без пересказа документов |

Канонические пути: `README.md`, `AGENTS.md`, `docs/ARCHITECTURE.md`, `docs/ENGINEERING.md`, `docs/DEVELOPMENT.md`, `.highgrade/project/INSTRUCTIONS.md` и `.highgrade/project/documents.json`. При init эквивалентное содержание переносят или разделяют; недостающее создают после поиска. README ссылается на четыре основных документа, AGENTS — на местную инструкцию, она — на реестр. OpenSpec владеет поведением и задачами изменения. Дополнительный документ создают по потребности и ответственности, не ради дерева.

По потребности: TESTING — стратегия проверок, OPERATIONS/RUNBOOK — эксплуатация, SECURITY — угрозы, CONTRIBUTING — внешние участники, CHANGELOG — выпуски, ROADMAP — приоритеты. Важная тема не требует отдельного файла; эти названия не вводят версионирование.

ADR фиксирует причины, альтернативы, последствия и пересмотр значимого решения: при долгом влиянии, дорогой отмене, существенных альтернативах или исключении, не на каждую спеку. ADR и спеки связаны многие-ко-многим; решение и реализация различаются. Заменённому ADR дают статус и ссылку на замену, сохраняя путь при входящих ссылках.

## D26 — непротиворечивость

Проверяются применимые документы, общие и проектные правила, код, тесты и доказательства. У правила один основной источник по ответственности; новый файл не всегда главнее. Код не отменяет требование, тест не доказывает всё поведение, архив не задаёт норму.

Локальная правка проверяет связанные источники, общий инвариант расширяет область. Init и дополнительный обзор охватывают заявленный применимый набор. Отчёт называет проверенное и непроверенное; локальный результат не доказывает глобальную согласованность.

Конфликт показывают с положениями, путями и влиянием. Рассинхронизацию принятого агент исправляет сам, новый существенный выбор возвращает автору по D12. Исключение или fallback не скрывает конфликт. Скрипт проверяет структуру, агент — смысл; полнота не гарантирована.

## D27-B — объём и бюджеты

При init автор согласует бюджеты и диапазоны. Агент может обоснованно менять значение внутри диапазона; верхнюю границу меняет автор. Основание — области, связи, риск и опыт задач, не только строки кода.

Пересмотр хранит базу, прежнее и новое значение, причину, вариант сокращения и условие следующей проверки. Малые повышения не сдвигают потолок и не обнуляют рост. Лимит не повышают ради исчезновения предупреждения; сокращение сохраняет требования, исключения и причины.

Отдельно контролируются постоянные инструкции, маршрут задачи и история вне обычной загрузки. Обязательный документ не всегда читается целиком; архив не является источником действующих правил.

Метрики: байты и строки, токены либо оценка с методом, изменение размера, ссылки, дубли, охват, новая область без источника и наступивший пересмотр. Размер файлов не равен окну сеанса; «безопасная зона» не гарантирует покрытие. Неизвестное остаётся неизвестным.

Начальный бюджет — гипотеза, проверяемая реальными задачами новой сессии: найти требование, код и проверку, продолжить работу, отличить действующее решение от исторического. Для High Grade фактический статус диапазонов указан в [проектном реестре](../../.highgrade/project/documents.json); `null` при наличии означает not-agreed, не успех и не бесконечный лимит.

## D28-A — реакции

Превышение бюджета — предупреждение и пересмотр, не запрет завершения задачи. Существенное противоречие или отсутствие необходимого контекста останавливает только зависимую работу; независимая продолжается. После исправления — повтор затронутой проверки. Возраст файла или совпадение ключевых слов сами по себе не доказывают блокирующую проблему. Неисполненная проверка не становится успешной.

## D29-A — архив

Агент архивирует завершённые планы, заменённые документы и разобранные неудачные гипотезы. Сохраняет статус, причину, замену и доказательства, проверяет входящие ссылки. Неясное остаётся активным. Ошибка переноса не считается завершением; восстанавливаются только собственные изменения, чужие правки сохраняются.

Архив — история по запросу, без дублирования; OpenSpec-архив не копируется. Отвергнутая гипотеза не меняет действующую спеку. Удаление функциональности требует отдельного решения; архивирование кода не делает его неисполняемым.

Обычные редакции хранит Git; без него нужен способ сохранить исходники до преобразования. Для High Grade Git действует с v0-2-1, прежние решения хранят архив и манифесты. Большие временные результаты не добавляют автоматически; архив не чистят по возрасту. В действующем контексте остаются краткие причины отказа со ссылкой на детали.

## D30-A — временные обходы

Обход в разрешённой задаче допустим при сохранении требований и видимости ошибки. Зафиксируй причину, код, проверку, условие удаления и задачу; второго backlog нет. Изменение поведения или гарантий согласуется по D12.

При наступлении условия обход пересматривают; продление требует причины и нового условия, существенные последствия — решения автора. Срок не разрешает удалять работающий код. Предусмотренная спекой деградация не обход. Поиск try/except и fallback даёт кандидатов, не доказательства.

## D32 — штатная работа и дополнительная актуализация

Документы, размеры, архив и временные обходы сопровождаются в ходе обычных задач, без ожидания отдельного навыка. При завершении изменения проверяется затронутая область, а не всё дерево без причины. Первая версия работает без хуков по WF-HOOKS-01 в SPECIFICATION; повторяющиеся подтверждённые пропуски являются основанием пересмотра, а не разрешением включить хук автоматически.

Навык актуализации по запросу — дополнительный комплекс мер, когда автору нужна понятная картина состояния: что подтверждено, устарело, исправлено, заблокировано или неизвестно. Он использует те же правила и инструменты, находит накопленные пропуски и выполняет разрешённые исправления; режим «только анализ» ничего не меняет. Он не создаёт второй список задач и не обещает непрерывный фоновый контроль.

## D33-A — оформление

Обязательное содержание определяется ролью документа; внутри канонических файлов структура гибкая. В начале — назначение/границы. Заголовки предметные, разделы самостоятельные, правила не дублируются. Действующее, предложенное и историческое различаются; неочевидные ограничения имеют причины. Команды, пути и примеры проверяемы, непроверенные примеры помечены. История работы и длинные отчёты вынесены из основных документов. Косметика не блокирует задачу.

## Снятый D31

Автор отменил обсуждение версионирования функций и документов. Действующие документы обновляются на месте. Добровольные обновления поставки workflow по D16/D20/D21 сохраняются; это ранее принятое правило, а не возобновление D31. Отметка проверки относится к фактическому обзору, не к форматированию.
