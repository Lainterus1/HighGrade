# Глобальный workflow High Grade

Статус: исходная поставка v0-2-9 сокращает повторы этапов и очищает прежние выпуски после успешного обновления; v0-2-7 [опубликована ранее](../releases/v0-2-7.md). `approve` и `push` разделены. Текущую установленную версию показывает `global-status`. Проверки и документы — в [QUALITY](QUALITY.md) и [CONTEXT](CONTEXT.md); [SPECIFICATION](SPECIFICATION.md) хранит историю решений. Пилоты целевых проектов проводятся отдельно.

## Владение и границы

High Grade ставит восемь общих навыков и Rust CLI в профиль пользователя, не копируя их в проекты. Проект хранит `.highgrade/project/INSTRUCTIONS.md`, свои документы, OpenSpec, тесты и доказательства. Его `AGENTS.md` указывает на общий маршрут; местная инструкция — на выборы, исключения, команды и действующие источники. Init выявляет конфликт обязанностей местных навыков. Существенное противоречие показывается автору; принятое исключение фиксируется и не переспрашивается. Центрального реестра проектов и фонового обхода нет. SVG Vectorizer и Code Health Audit — отдельные пакеты.

Общие маршруты: `highgrade-init`, `highgrade-task`, `highgrade-spec`, `highgrade-work`, `highgrade-clear`, `highgrade-approve`, `highgrade-push`, `highgrade-update`. Короткие SKILL.md выбирают процедуры и CLI через один активный выпуск. Обновление не переписывает проекты: совместимость местной инструкции проверяется при следующем входе, конфликт разбирает clear.

## Пользовательский маршрут

1. **Init** обозревает структуру проекта, углублённо проверяет области адаптации и риска, сопоставляет документы и навыки, фиксирует непрочитанное, пробелы и план. После разрешённого выполнения проверяет структуру; подключение не равно приёмке.
2. **Task** собирает независимые существенные вопросы в один раунд. При пошаговом обсуждении даёт один раунд дополнений; ясное разрешённое поручение передаёт дальше. Запрос на анализ остаётся только чтением.
3. **Spec** оформляет новое поведение в OpenSpec. Ясная техническая правка без нового поведения может идти прямо в work; второго backlog нет.
4. **Work** выполняет задачу, достаточные проверки затронутого поведения, документы, архив и нужное по риску независимое ревью. `trace` помогает читать поддерживаемые отчёты, но не заменяет тесты.
5. **Clear** по запросу обозревает состояние только чтением; исправления требуют соответствующего поручения.
6. **Approve** по явному вызову сверяет задачу, ранее полученные доказательства и точный состав, делает локальный коммит и назначенную проектом местную активацию из его SHA. Без такого маршрута коммит допустим; ошибка активации оставляет частичный статус. Push не следует из approve.
7. **Push** по отдельному поручению сверяет непрерывный диапазон готовых коммитов, задачи, цель и последствия CI, отправляет без force по умолчанию и проверяет удалённый SHA. Диапазон может включать несколько задач. Неоднозначный пакет показывается автору до отправки; эксплуатационная активация требует разрешения.
8. **Update** по отдельному запросу переключает проверенную общую поставку. При сбое до успешной проверки прежний активный выпуск восстанавливается автоматически; после успеха собственные файлы старых выпусков удаляются. Проекты не меняет и из clear не запускается.

## Инструмент и доказательства

CLI даёт read-only `doctor`, `inspect`, `inventory` и `trace`. `doctor` обнаруживает инструменты в PATH, а версии проверяются отдельно. `inspect --bootstrap` показывает семь обязательных путей, кандидатов и связи до реестра; обычный `inspect` проверяет структуру, реестр, ссылки и бюджеты. Содержание оценивает агент. `trace` читает Rust nextest и Playwright; неподдерживаемое остаётся неизвестным. Штатные тесты запускаются средствами проекта, не CLI.

Первый выпуск рассчитан на Windows и исходники GitHub. Хуки, Covers, бинарные пакеты, другие платформы и перенос отдельных плагинов на Rust отложены.

## Условия готовности

Локальная проверка, коммит, местная активация, публикация, CI и приёмка — разные состояния. Запись опубликованного выпуска хранит SHA, проверки и активацию без копий машинных результатов. Переносимость полного маршрута подтверждают отдельные пилоты нового и существующего проектов с проверкой сохранности чужих файлов и восстановления при сбое; синтетический init доказывает только свой сценарий. SNAF и другие проекты не меняются без поручения.
