# Глобальный workflow High Grade

Статус: согласованная цель текущей реализации. Контракты P0–P6 описывают исторического кандидата с проектными копиями. Этот документ заменяет их в вопросах поставки, состава навыков и подключения проекта. Неизменённые требования к контексту, доказательствам, архиву и трассировке остаются в [SPECIFICATION](SPECIFICATION.md) и [CONTEXT](CONTEXT.md).

## Владение и границы

High Grade — один переносимый набор из шести навыков Codex и одного CLI на Rust, устанавливаемый на уровне пользователя. Он не управляет проектами из каталога своих исходников. Подключённый проект хранит местные решения в `.highgrade/project/INSTRUCTIONS.md`, а также собственные документы, OpenSpec, тесты и доказательства. Общие навыки, CLI и процедуры в проект не копируются. Дополнительные местные навыки допустимы; init выявляет пересекающиеся обязанности до выбора активного маршрута. SVG Vectorizer и Code Health Audit остаются самостоятельными пакетами, не обязательными для основного workflow.

Общие навыки: `highgrade-init`, `highgrade-task`, `highgrade-spec`, `highgrade-work`, `highgrade-clear`, `highgrade-update`. Их короткие маршрутизирующие SKILL.md стоят в профиле пользователя; подробные общие процедуры и CLI выбираются через одну активную версию. Добровольное обновление меняет общую логику сразу для всех проектов, но не переписывает их файлы. При входе выполняется лёгкая проверка проектной инструкции; несовместимость останавливает только зависимую работу High Grade и передаётся на разбор в clear. Центрального реестра проектов и фонового обхода нет.

AGENTS в подключённом проекте коротко направляет подходящие задачи к High Grade. Местная инструкция хранит только выборы проекта, принятые исключения, команды и ссылки на действующие документы. Она не дублирует AGENTS, ARCHITECTURE, ENGINEERING, DEVELOPMENT, OpenSpec или тесты. Противоречие местных и общих правил показывается автору с вариантами; ни одна сторона не выигрывает молча. Уже принятое исключение записывается и не переспрашивается.

## Пользовательский маршрут

1. Если проект не подключён, init обследует существующий проект или интервьюирует автора нового, инвентаризует документы и навыки, задаёт только нерешённые вопросы и предлагает план адаптации. Реализация плана остаётся в разрешённой области. Техническое подключение не равно пользовательской приёмке.
2. Для новой задачи task предлагает обсуждение либо анализ имеющегося контекста. Каждая карточка решения стабильно содержит вопрос и последствия, рекомендацию с причиной, два или три содержательных варианта и возможность своего ответа. Перед написанием спеки агент кратко показывает цель, границы, наблюдаемое поведение и проверки и спрашивает дополнения. Запрос только на анализ не пишет файлы.
3. После подтверждения spec создаёт OpenSpec-изменение, когда меняется устойчивое поведение или контракт. Он читает местную инструкцию и действующие источники; второго backlog нет. Оформление, рефакторинг без изменения поведения и отдельные технические задачи могут идти прямо в work. Task инициирует spec без дополнительной команды пользователя после согласования условий.
4. Work исполняет порученное из основного источника задач, запускает штатные проектные проверки, использует trace для поддерживаемых доказательств сценариев, сопровождает документы, контекст и архив, получает независимое ревью значимых изменений. Малую ясную задачу можно выполнять напрямую по AGENTS без долговременного плана.
5. Clear — дополнительный обзор состояния и разрешённая актуализация по запросу. Он делит с init процедуру аудита и охватывает противоречия, бюджеты, устаревшее, временные обходы, архив и совместимость. Анализ остаётся только чтением. Clear не означает автоматического удаления и не является обязательным ритуалом после задачи.
6. Update по явному запросу проверяет и обновляет общую пользовательскую поставку, переключает её после проверок и сохраняет откат. Он не меняет автоматически проекты и не запускается из clear.

## Инструмент и доказательства

Один Rust CLI сохраняет read-only `doctor`, `inspect` и `trace`. Штатные тесты остаются у проекта. CLI устанавливает/обновляет общую основу и структурно проверяет проектную инструкцию; он не проводит смысловой аудит, интервью, написание OpenSpec или общий BDD-прогон. Trace поддерживает уже проверенный срез Rust nextest и Playwright; неподдерживаемое остаётся unknown. Первый выпуск — Windows и исходники на GitHub. Covers, хуки, готовые бинарные пакеты, другие платформы и перенос SVG/CHA на Rust — позднее.

## Условия готовности

Глобальная поставка обнаруживается Codex app и CLI без копий общих навыков в проекте. Изолированные новые и существующие проекты демонстрируют init, task→spec, прямую работу, clear, обновление/откат, выявление конфликтов и сохранность чужих файлов. Сам High Grade использует проектную инструкцию и измеряет бюджеты своих документов. Повторный проход SNAF и PlantsNotify следует после публикации. Публикация требует проверенного push в нужный GitHub-репозиторий, лицензии/проверки происхождения и инструкции установки; она не означает приёмку целевых проектов.
