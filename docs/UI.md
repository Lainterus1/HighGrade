# Локальный интерфейс High Grade

Этот документ описывает запуск и наблюдаемое поведение установленного интерфейса. Структура frontend — в [ui/README](../ui/README.md), проверки — в [DEVELOPMENT](DEVELOPMENT.md#интерфейс-и-storybook), сборка — в [BUILD](BUILD.md#ресурсы-интерфейса).

## Запуск

`highgrade ui` фиксирует текущую папку проекта; `highgrade ui --root <путь-к-проекту>` выбирает её явно. Один процесс — один корень, включая отдельные worktree. Второй проект открывается вторым запуском. Порт выбирается системой на 127.0.0.1. Адрес выводится до открытия браузера; `--no-open true` оставляет ручное открытие. Остановка: Ctrl+C в запустившем терминале. Закрытие вкладки само процесс не останавливает.

`highgrade ui --check true` проверяет встроенный комплект без чтения проекта, открытия порта или браузера; JSON-отчёт содержит версии CLI/API, SHA исходников и число файлов. Этот режим не сочетается с `--root` или `--no-open`. Отсутствие, повреждение или несовместимость ресурсов дают `UiBundleInvalid`; установка проверяет кандидата до записи профиля.

## Чтение и правка

Приложение встроено в CLI: читает актуальные структуры, поддерживает поиск/темы/порядок и явное обновление внешней редакции. Текст не подменяется во время чтения. Правки сохраняются явно, по локальному CAS; при конфликте ввод остаётся в форме. Перечитайте и сравните, затем явно выберите текущую версию либо примените свои поля и сохраните. При потере ответа повторной записи автоматически нет.

Карточка показывает цель, названия изменений, границы и условия «Готово, когда». Название требования раскрывает исходную формулировку. Условия готовности видны списком; одинаковые условия показаны один раз. Сценарии, задачи, обоснование, проверки, история, диагностика и связи скрыты; редактор сохраняет служебные поля. Последнее решение о приёмке и его актуальность видны у интегрированной спеки. Без актуальной готовности и приёмки она находится в «Все»; карточка объясняет состояние проверки. При пустой очереди и отсутствии текущей работы открывается «Все».

Формулировки требований и условия готовности берутся из документа без пересказа и обрезания. При переключении сразу выделяется выбранная спека и показывается загрузка; последнее нажатие определяет итоговую карточку. Статусы имеют прямоугольные метки с текстом и цветом: решение — янтарный, работа — синий, история — песочный, приёмка — зелёный, отмена — серый, диагностика — красный.

## Решения

Согласование требований не разрешает выполнение и не запускает агента. Для готового результата выберите «Результат принят» или «Нужна доработка» и нажмите «Сохранить статус». Форма не запрашивает SHA и имя; комментарий необязателен. Система сохраняет источник «Локальный интерфейс», время и проверенный снимок. Уже известная версия обращения используется автоматически; без неё приёмка допустима. Существенный дрейф требует нового решения. Интегрированные требования развиваются связанным изменением.

Блок результата использует сохранённый текст. Явно обозначенная версия и путь отчёта доступны в раскрываемых исходных сведениях; действия и ограничения остаются видимыми. Форма не вызывает LLM и не требует нового резюме.

В пределах открытой страницы Close/Escape и переключение сохраняют черновик решения, привязанный к каноническому корню проекта, спеке и обращению. Выбранный статус и комментарий не теряются после ошибки; ответы на вопросы и согласование требований также сохраняют введённое имя. Актуальность проверяется по снимку, включая сохранённую необязательную версию обращения. Неоднозначный POST остаётся заблокирован после повторного открытия. «Проверить состояние решения» только читает: найденная запись не повторяется, подтверждённое отсутствие на неизменной редакции разрешает отдельное явное сохранение. При несохранённом вводе страница запрашивает подтверждение ухода через beforeunload; восстановление после закрытия страницы не обещается.

## Установка и совместимость

Установленному UI не нужны Node, Cargo, Storybook или внешняя сеть. Неполный/несовместимый встроенный комплект даёт `UiBundleInvalid` до открытия порта: переустановите полный выпуск. Разработчик пересобирает frontend и CLI по [BUILD](BUILD.md#ресурсы-интерфейса). `/highgrade-ui.json` содержит отпечатки и происхождение ресурсов; `/licenses/Manrope-OFL.txt` и `/licenses/Lucide-LICENSE.txt` — уведомления.

Прежние неподдерживаемые UI структуры видны в счётчике исключений, без переноса. Действующий компактный состав карточки закреплён [HG-0058](../specs/changes/HG-0058/spec.json); первоначальный маршрут HG-0052–HG-0057 сохранён [в архиве](archive/plans/specification-ui-sequence.md).

## Контракт API 2

Один origin. `GET /api/session` возвращает версию, имя/канонический путь и случайный токен текущего процесса. Токен живёт в памяти клиента/сервера, не в URL или журнале. Остальные API требуют `X-HighGrade-Api: 2`; запрос прежней версии получает `ApiVersionMismatch`. Записи требуют совпадающий Origin и `X-HighGrade-Token`. Host проверяется с точным портом; чужие Origin/Fetch-Site отклоняются. CORS не включён, страница запрещает встраивание и использует локальные скрипты.

| Маршрут | Содержание |
|---|---|
| GET /api/specs | Проекция spec-ui: категории, признак интеграции, действия, счётчики, исключённые профили |
| GET /api/specs/{id} | Реальная поддерживаемая спека и store_sha256 |
| POST /api/specs/{id}/edit | `{expected_local, input}` (либо expected): валидируемый patch по общим правилам spec-edit |
| POST /api/specs/{id}/attention | `{expected, input}`: attention_input из spec-schema |
| POST /api/shutdown | Перестать принимать соединения, завершить начатые запросы |

HTTP вызывает общий Rust-слой без shell и временных файлов ввода. Схема не принимает root, путь файла или команду. Поддержка проверяется внутри той же блокировки, что CAS. Тело ограничено 1 МиБ. Успешный ответ возвращается после сохранения; потеря ответа не означает ни успех, ни гарантированную отмену: клиент перечитывает состояние, сохранив несохранённый ввод.

Успех — общий Report CLI. Ошибки транспорта/каталога — `{error: {code, message}}`; конфликт — HTTP 409. Ошибка проверки Report — 422 с findings. CatalogMissing, CatalogUnsupported, RecoveryRequired и InvalidFormat различаются. Сервер не вызывает init/migrate/recover. Прежние неподдерживаемые UI структуры видны в счётчике исключений, без переноса.

GET списка и документа проверяет формат и наличие каталога на том же снимке под блокировкой, из которого формируется ответ; предварительной повторной загрузки нет. Каждый запрос читает актуальный каталог с диска, межзапросного кеша нет.

`src/ui.rs` владеет HTTP/жизненным циклом, `src/specs/attention.rs` — решениями/проекцией; `src/specs.rs` — общей точкой чтения/записи. Оформление — в [ui/README](../ui/README.md). Служебные стили Radix получают случайный nonce сеанса, независимый от API-токена; CSP не разрешает произвольные inline-стили или inline-скрипты.

## Внешний вид и отзывчивость

Editorial использует тёплый светлый фон, светлую поверхность документа и тёмно-зелёное основное действие. Заголовок документа набран локальной Lora, текст и управление — Manrope. Общие стили применяются также к редактору, диалогам, ошибкам и состояниям загрузки; состав сведений и действия не меняются. Оба шрифта и лицензии включены в локальный комплект, внешний сервис шрифтов не нужен.

Служебные подписи требований, сценариев и задач показаны без HG-ID; номер спеки остаётся в списке и заголовке. Операции показаны квадратными значками с доступными названиями: добавить — зелёный плюс, изменить — синий карандаш, удалить — красный минус. Состояние неизвестной готовности подписано «Не удалось проверить». Карточка занимает доступную ширину. Требования раскрываются в строках; условия готовности видны списком. Абзацы ограничены по длине строки; основной текст 16 px. Номер и статус располагаются над названием. Выбранная спека отмечена фирменным геометрическим маркером. Статус «Нужно решение» остаётся только в списке спек. Идентификаторы в исходных данных и запросах записи сохраняются.

При быстром переключении чтение прежнего выбора отменяется, включая ожидание повторного запроса при занятом каталоге. Записи остаются последовательными и не отменяются. Редактор сравнивает только изменённые поля без глубокого копирования всей спеки на каждый ввод; фильтры и темы пересчитываются по изменению исходных данных.
