# Локальный интерфейс High Grade

Этот документ описывает запуск и наблюдаемое поведение установленного интерфейса. Структура frontend — в [ui/README](../ui/README.md), проверки — в [DEVELOPMENT](DEVELOPMENT.md#интерфейс-и-storybook), сборка — в [BUILD](BUILD.md#ресурсы-интерфейса).

## Запуск

`highgrade ui` фиксирует текущую папку проекта; `highgrade ui --root D:/project` выбирает её явно. Один процесс — один корень, включая отдельные worktree. Второй проект открывается вторым запуском. Порт выбирается системой на 127.0.0.1. Адрес выводится до открытия браузера; `--no-open true` оставляет ручное открытие. Остановка: Ctrl+C в запустившем терминале. Закрытие вкладки само процесс не останавливает.

## Чтение и правка

Приложение встроено в CLI: читает актуальные структуры, поддерживает поиск/темы/порядок и явное обновление внешней редакции. Текст не подменяется во время чтения. Правки сохраняются явно, по локальному CAS; при конфликте ввод остаётся в форме. Перечитайте и сравните, затем явно выберите текущую версию либо примените свои поля и сохраните. При потере ответа повторной записи автоматически нет.

Карточка показывает цель, названия изменений, границы и все условия «Готово, когда». Нажатие на название требования раскрывает его формулировку; условия готовности остаются видны отдельным списком. Сценарии, задачи и раздел «Подробности» скрыты. В редакторе доступно условие готовности, а служебные части сценария сохраняются. Обоснование, проверки, запуски и результаты проверок не отображаются; скрытые поля сохраняются при редактировании. Подробная история обращений, диагностика и связи скрыты; последнее решение о приёмке и его текущая актуальность показаны у интегрированной спеки. Исходные данные остаются в документе. Статусы показаны прямоугольными плашками: решение — янтарная, работа — синяя, интегрированная история — песочная, принято — зелёная, отменено — серая, диагностика — красная. Интегрированная спека без актуальной готовности и приёмки находится в «Все», а не в «В работе»; карточка отдельно объясняет текущую проверку. При пустых очереди решений и текущей работе первым открывается «Все». Текст берётся из документа без пересказа и обрезания; повторяющиеся условия готовности показываются один раз. При переключении сразу выделяется выбранная спека и показывается загрузка; последнее нажатие определяет итоговую карточку.

## Решения

Согласование требований не запускает агента и не разрешает выполнение. Для приёмки готового результата укажите Git SHA либо неизменяемый ID проверенной сборки; хеш спеки этим идентификатором не является. Готовые интегрированные требования доступны для чтения; их развитие оформляется связанным изменением через обычный маршрут High Grade.

## Установка и совместимость

Установленному UI не нужны Node, Cargo, Storybook или внешняя сеть. Неполный/несовместимый встроенный комплект даёт `UiBundleInvalid` до открытия порта: переустановите полный выпуск. Разработчик пересобирает frontend и CLI по [BUILD](BUILD.md#ресурсы-интерфейса). `/highgrade-ui.json` содержит отпечатки и происхождение ресурсов; `/licenses/Manrope-OFL.txt` и `/licenses/Lucide-LICENSE.txt` — уведомления.

Прежние неподдерживаемые UI структуры видны в счётчике исключений, без переноса. Действующий компактный состав карточки закреплён [HG-0058](../specs/changes/HG-0058/spec.json); первоначальный маршрут HG-0052–HG-0057 сохранён [в архиве](archive/plans/specification-ui-sequence.md).

## Контракт API 2

Один origin. `GET /api/session` возвращает версию, имя/канонический путь и случайный токен текущего процесса. Токен живёт в памяти клиента/сервера, не в URL или журнале. Остальные API требуют `X-HighGrade-Api: 2`; запрос прежней версии получает `ApiVersionMismatch`. Записи требуют совпадающий Origin и `X-HighGrade-Token`. Host проверяется с точным портом; чужие Origin/Fetch-Site отклоняются. CORS не включён, страница запрещает встраивание и использует локальные скрипты.

| Маршрут | Содержание |
|---|---|
| GET /api/specs | Проекция spec-ui: категории, признак интеграции, действия, счётчики, исключённые профили |
| GET /api/specs/{id} | Реальная поддерживаемая спека и store_sha256 |
| POST /api/specs/{id}/edit | `{expected_local, input}` (либо expected): валидируемый patch по общим правилам spec-edit |
| POST /api/specs/{id}/attention | `{expected, input}`: attention_input из spec-schema |
| POST /api/shutdown | Перестать принимать соединения, завершить начатые запросы |

HTTP вызывает общий Rust-слой без shell и временных файлов ввода. Схема не принимает root, путь файла или команду. Поддержка проверяется внутри той же блокировки, что CAS. Тело ограничено 1 МиБ. Успешный ответ возвращается после сохранения; потеря ответа не означает ни успех, ни гарантированную отмену: клиент перечитывает состояние, сохранив несохранённый ввод.

Успех — общий Report CLI. Ошибки транспорта/каталога — `{error: {code, message}}`; конфликт — HTTP 409. Ошибка проверки Report — 422 с findings. CatalogMissing, CatalogUnsupported, RecoveryRequired и InvalidFormat различаются. Сервер не вызывает init/migrate/recover. Прежние неподдерживаемые UI структуры видны в счётчике исключений, без переноса.

`src/ui.rs` владеет HTTP/жизненным циклом, `src/specs/attention.rs` — решениями/проекцией; `src/specs.rs` — общей точкой чтения/записи. Оформление — в [ui/README](../ui/README.md). Служебные стили Radix получают случайный nonce сеанса, независимый от API-токена; CSP не разрешает произвольные inline-стили или inline-скрипты.

## Внешний вид и отзывчивость

Служебные подписи требований, сценариев и задач показаны без HG-ID; номер спеки остаётся в списке и заголовке. Операции показаны квадратными значками с доступными названиями: добавить — зелёный плюс, изменить — синий карандаш, удалить — красный минус. Состояние неизвестной готовности подписано «Не удалось проверить». Карточка занимает доступную ширину: цель выделена нейтральным фоном, требования — строки с цветными значками слева и подсветкой раскрытого пункта, условия готовности — единый открытый список. Абзацы ограничены по длине строки; основной текст 16 px. Номер и статус располагаются над названием. Выбранная спека отмечена фирменным геометрическим маркером. Статус «Нужно решение» остаётся только в списке спек. Блок приёмки компактен и не повторяет техническую инструкцию передачи; поля автора и проверенной версии сохранены. Идентификаторы в исходных данных и запросах записи сохраняются.

При быстром переключении чтение прежнего выбора отменяется, включая ожидание повторного запроса при занятом каталоге. Записи остаются последовательными и не отменяются. Редактор сравнивает только изменённые поля без глубокого копирования всей спеки на каждый ввод; фильтры и темы пересчитываются по изменению исходных данных.
