# Действующая архитектура High Grade

Область: фактическое устройство исходного проекта. Продуктовые правила нового маршрута — в [GLOBAL](workflow/GLOBAL.md); прежний кандидат P0–P6 описан в [историческом плане](archive/plans/first-release.md) и проверенных контрактах.

```text
MyCodex/                         локальное имя каталога High Grade
  README.md, AGENTS.md           вход и правила исходного проекта
  .highgrade/project/            местная инструкция и реестр документов
  specs/                         требования, отдельные spec/results и приёмка
  openspec/                       сохранённые прежние требования и история
  docs/                           требования, политика контекста, план, доказательства, архив
  Cargo.toml, Cargo.lock          Rust CLI и закреплённые зависимости
  src/                            doctor, inspect с bootstrap, trace, безопасные пути, global install/update
  tests/                          контрактные проверки на изолированных данных
  kit/                            восемь глобальных навыков, процедуры, шаблоны, manifest v3
  bundle/                         исторический проектный кандидат manifest v2
  plugins/                        отдельные исходники SVG и Code Health Audit
  scripts/check-repository.mjs    структурная проверка исходного проекта
```

Общий набор устанавливается в профиль пользователя: маршрутизаторы навыков — в `.agents/skills/highgrade-*`, неизменяемые материалы и CLI — в `.highgrade/global/releases/<release>/`, активный указатель — в `.highgrade/global/active.json`. Проектный `.highgrade/project/INSTRUCTIONS.md` содержит только местную адаптацию. CLI работает с явно выбранными корнями. Команды `global-install`, `global-update`, `global-status` отделены от `doctor`, `inspect`, `inventory` и `trace`. Они не изменяют содержание проекта; чтение нативных спек использует временный lock.

`package`, `install`, `bundle/` и команды `legacy-install`/`legacy-update` сохраняют совместимость прежнего маршрута. Удаление требует отдельной миграционной проверки.

`doctor` проверяет заголовок схемы инструкции и явно сообщает `schema-only` / `semantic_compatibility=not_assessed`; смысловую совместимость сверяет агент по поставляемой процедуре. `inspect --bootstrap` до создания реестра показывает семь обязательных путей и фиксированные Markdown-связи; при отсутствующем пути он ограниченно обходит один корень для поиска возможных альтернатив, а при полном наборе путей пропускает этот обход. Обход применяет проектные исключения и пропускает `.highgrade/releases`, но не подтверждает одобрение аудита исключений. Обычный `inspect` сверяет роли с каноническими путями, ссылки и бюджеты по реестру; `trace` сопоставляет ID из нативного JSON и исторического OpenSpec, отметки тестов и native-отчёты Rust nextest/Playwright. CLI не проводит интервью, смысловой аудит, ревью и реализацию продукта. Эти действия выполняют навыки и агент.

SVG Vectorizer и Code Health Audit — самостоятельные исходные пакеты. Их зависимости и runtime не объединены с CLI. Установленные копии этих плагинов не переключаются при публикации High Grade.

## Владение знаниями

Местные владельцы документов и текущий маршрут Проекта перечислены в [проектной инструкции](../.highgrade/project/INSTRUCTIONS.md). Общие правила Поставки принадлежат `kit/`; история и архив не заменяют действующие инструкции.

## Нативные спецификации Поставки

`src/specs.rs` владеет моделями и маршрутом команд; `progress.rs` — нумерацией и решениями; `storage.rs` — проектными spec/results, миграцией и журналом восстановления; `relations.rs` — связями/тегами; `checks.rs` — явным запуском штатных проверок. Каталог `specs/` независим от служебной `.highgrade`; нестандартный путь задаёт проектный `specs-location.json`. JSON-сводка вычисляется. Lock/CAS и журнал защищают согласованность: прерывание требует явного восстановления, а не чтения смеси файлов. Лимит отдельного документа/транзакции — 8 МиБ. Legacy store читается совместимо до явной миграции; после неё остаётся историческим источником, дрейф которого обнаруживается.

Проверки различают структуру, контракт, наблюдения, актуальность файлов и ревью. CLI не сертифицирует смысл или подлинность внешнего отчёта. Новые задачи Проекта и подключаемых проектов используют нативный маршрут. Прежние OpenSpec-контракты сохранены без миграции. Команды и границы — в [справочнике Поставки](../kit/references/cli.md#структурированные-спецификации).
