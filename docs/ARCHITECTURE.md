# Действующая архитектура High Grade

Область: фактическое устройство исходного проекта. Продуктовые правила нового маршрута — в [GLOBAL](workflow/GLOBAL.md); прежний кандидат P0–P6 описан в [историческом плане](archive/plans/first-release.md) и проверенных контрактах.

```text
HighGrade/                       имя репозитория High Grade на GitHub
  README.md, AGENTS.md           вход и правила исходного проекта
  .highgrade/project/            местная инструкция и реестр документов
  specs/                         требования, отдельные spec/results и приёмка
  docs/archive/legacy-openspec/   неизменённые прежние требования и история
  docs/                           требования, политика контекста, план, доказательства, архив
  Cargo.toml, Cargo.lock          Rust CLI и закреплённые зависимости
  src/                            doctor, inspect с bootstrap, trace, безопасные пути, global install/update
  tests/                          контрактные проверки на изолированных данных
  kit/                            девять глобальных навыков, процедуры, шаблоны, manifest v3
  bundle/                         исторический проектный кандидат manifest v2
  plugins/                        отдельные исходники SVG и Code Health Audit
  scripts/check-repository.mjs    структурная проверка исходного проекта
```

Общий набор устанавливается в профиль пользователя: полные инструкции навыков — в `.agents/skills/highgrade-*`, неизменяемые материалы и CLI — в `.highgrade/global/releases/<release>/`, активный указатель — в `.highgrade/global/active.json`. Проектный `.highgrade/project/INSTRUCTIONS.md` содержит только местную адаптацию. CLI работает с явно выбранными корнями. Команды `global-install`, `global-update`, `global-recover`, `global-status` отделены от `doctor`, `inspect`, `inventory` и `trace`. Они не изменяют содержание проекта; чтение нативных спек использует временный lock.

`package`, `install`, `bundle/` и команды `legacy-install`/`legacy-update` сохраняют совместимость прежнего маршрута. Удаление требует отдельной миграционной проверки.

`doctor` проверяет схему инструкции, но смысловую совместимость сверяет агент. `inspect --bootstrap` до создания реестра показывает семь обязательных путей и Markdown-связи; при пропуске пути ищет альтернативы в одном корне с проектными исключениями. Обычный `inspect` сверяет роли, ссылки и бюджеты по реестру; `trace` сопоставляет ID JSON и совместимого прежнего формата с тестами и отчётами Rust nextest/Playwright. Интервью, смысловой аудит, ревью и реализацию выполняют навыки и агент.

SVG Vectorizer и Code Health Audit — самостоятельные исходные пакеты. Их зависимости и runtime не объединены с CLI. Установленные копии этих плагинов не переключаются при публикации High Grade.

## Владение знаниями

Местные владельцы документов и текущий маршрут Проекта перечислены в [проектной инструкции](../.highgrade/project/INSTRUCTIONS.md). Общие правила Поставки принадлежат `kit/`; история и архив не заменяют действующие инструкции.

## Нативные спецификации Поставки

Формат 4 (`--to compact`) хранит общие объекты истории. Метаданные отделены от редакции; новые baseline фиксируют только modify/remove с общим CAS.

`specs.rs` — модели/команды; `presentation.rs` — порядок JSON; `progress.rs` — нумерацией и решениями; `storage.rs` — проектными spec/results, миграцией и журналом восстановления; `relations.rs` — связями/тегами; `checks.rs` — явным запуском штатных проверок. Каталог `specs/` независим от служебной `.highgrade`; нестандартный путь задаёт проектный `specs-location.json`. JSON-сводка вычисляется. Lock/CAS и журнал защищают согласованность: прерывание требует явного восстановления, а не чтения смеси файлов. Лимит отдельного документа/транзакции — 8 МиБ. Legacy store читается совместимо до явной миграции; после неё остаётся историческим источником, дрейф которого обнаруживается.

CLI не сертифицирует смысл и подлинность отчёта. История форматов — в [архиве](archive/legacy-native-specs/2026-09-25/); команды — в [справочнике](../kit/references/tools/specifications.md#структурированные-спецификации).

Нативная CLI предоставляет компактные представления и patch через spec-edit; shared_inputs дополняют входы checks. Отпечатки различают контракт, доказательства и входы; эквивалентные повторы сохраняют решение. Старые отпечатки читаются консервативно. Реестр документов назначает роли существующим путям, допускает roles одного файла; служебные пути фиксированы.
