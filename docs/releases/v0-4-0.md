# Выпуск v0-4-0

HG-0075 развивает актуализацию через `highgrade-clear`. Пользователь выбирает документацию, тесты и объём проверки. Skill уточняет только недостающие параметры, всегда применяет Planner и проходит выбранную область по этапам. Метод отделяет прочитанные источники от списка файлов и выполненные проверки от плана.

Для выбранных тестов предусмотрены реальные изолированные мутации реализации, разбор выживших изменений и повтор исходных тестов после восстановления кода. Анализ остаётся read-only. Исправления идут через согласованный маршрут Work. Обычная задача Work не получает обязательный аудит качества всех тестов.

Автор поручил коммит, локальную активацию и push. Затем автор назначил версию 0.4.0. Предыдущая установленная версия — v0-3-13; её `global-status` прошёл перед подготовкой. Формат спецификаций и протокол CLI не изменены. Решение о человеческой приёмке не дано.

Основная работа и её пределы описаны в [проверке](../evidence/clear-refresh/verification.md) и [независимом ревью](../evidence/clear-refresh/review.md). Изолированный агентный прогон исправил документацию и тесты: слабый baseline пропускал семь нарушений, усиленные тесты обнаружили все семь. Независимый повтор подтвердил эти результаты. Один прогон на Linux не доказывает устойчивость модели или результат на другой платформе. Отдельные варианты read-only, прерывания и неизвестной области проверены нормативно.

Публикация назначена в origin/main. Единственный workflow проверяет Linux и Windows и не выполняет развёртывание. Общий inspect сохраняет прежний UNKNOWN для постороннего каталога presentation. Изменение `.gitignore` исключено из выпуска. Источник пользовательских изменений — [release-notes.json](../../kit/references/release-notes.json).

Подготовка версии прошла: 8 Python-тестов и 48 Rust-тестов global/package/release-notes; сборка UI, генерация навыков, структура и спеки прошли. [Оригинал проверок](../evidence/objects/31a003f7b0abb2245e90deec199b6fafef0f9360235ddb7ec669d9cd45176c4b.blob) сохраняет команды, время, stdout/stderr и хеши входов. Текущий HG-0075 имеет `technical=ready`, `review=go`, `human=pending`. Его причинные входы не изменились. [Проверка передачи по Git index](../evidence/objects/9f3333c1fbd840a27ee04f82f3aa958040dcda1ddd4d93a47a09138c90598d03.blob) прошла; все обязательные отчёты и входы включены с исходными байтами.

[Независимое ревью подготовки выпуска](../evidence/objects/36cf236efe43befa6a51f56fa034bdd4588420761c950525404c0c2d6a714b05.blob) дало GO. Проверены версии, хеши, отсутствие дрейфа причинных входов, исходные результаты и финальный index. Коммит, сборка, активация и CI требуют своих фактических подтверждений.

Поставка собрана штатным `build-release.py` из коммита `ea6d14ab1babcbe4e29e23b31fb9b42f76074c5c`. Все 42 файла кандидата совпали по хешам; материалы совпали с этим коммитом. Встроенный UI подтвердил CLI 0.4.0, этот source SHA и launcher protocol 1.

Preview подтвердил полный переход `v0-3-13 → v0-4-0`. После смыслового GO [apply](../evidence/objects/3fe942d9a1d329976907130f0c382f93e6d0de56e0116564954788e22049a842.blob) применил тот же `candidate_sha256`: `66ab88c6c62d975b994ed832cb7745c7bb8de4c8c7642bf3cabcce8cb99a2da7`. Получены `applied=true`, `active_release=v0-4-0` и `postcheck=passed`. Повторные global-status, проверка встроенного UI и диагностика чтения каталога прошли. [Проверка установленной идентичности](../evidence/objects/0bd1f95d84fe690427944d2d356018f335eee4712b5855c4f8e21508c6ae215c.blob) подтвердила CLI, manifest journal и все 40 материалов, включая девять skills.

[Манифест оригиналов сборки и активации](../evidence/objects/5e6d9f450a16c7fadc6ead8b5770253f9fd22c60e6abaa274fec593b4da64a9c.json) сохраняет успешные результаты и два первоначальных отказа команд: недопустимое сочетание аргументов UI и временный StoreBusy от параллельных проверок каталога. UI повторён с правильными аргументами. После окончания параллельных команд lock отсутствовал; последовательная диагностика прошла без удаления lock или восстановления. Эти отказы не объявлены PASS. Проектный UI не запускался.

Эта запись и оригиналы активации входят в отдельный служебный коммит. Он сохраняет source SHA Поставки и не меняет CLI, kit или причинные входы HG-0075. Повторная сборка и активация для записи не нужны. Публикуемый пакет включает оба коммита. Приёмка остаётся `human=pending`; доступный exact-SHA CI сообщается после push.
