# Сборки и временные файлы Проекта

Для разработки Cargo использует стандартный `target/`. Для кандидата активации:

```powershell
python scripts/build-release.py <точный-SHA-коммита>
```

Скрипт разрешает ref в SHA, экспортирует его через Git archive и собирает с `--release --locked`. Незакоммиченные файлы в кандидат не входят. Общий для всех кандидатов `CARGO_TARGET_DIR` — target/release-build. Этот кэш зарезервирован для скрипта; не направляй в него ручные Cargo-запуски. Он отделён от обычного target/release, чтобы параллельная разработческая сборка не подменила бинарник кандидата. Зависимости не компилируются в отдельных каталогах каждого выпуска. Временные исходники удаляются после успеха и ошибки.

Бинарник кандидата берётся из `compiler-artifact` текущего запуска Cargo; это сохраняет точность при заданном `CARGO_BUILD_TARGET`.

## Что остаётся

| Путь | Жизненный цикл |
|---|---|
| target/debug, target/release | Общий воспроизводимый кэш Cargo; очищать через cargo clean только при необходимости, ценой повторной компиляции |
| target/release-build | Один общий кэш всех сборок кандидата, управляемый блокировкой скрипта |
| target/release-candidate | Один кандидат: CLI, kit и candidate.json с исходным SHA и хешами. Следующая успешная сборка заменяет его |
| target/reports/release-build.log | Диагностика последней попытки сборки |
| target/work | Временные исходники и блокировка; после штатного завершения пуст |
| target/nextest, target/tools | Последний тестовый запуск и установленный тестовый инструмент |

Сбой сборки сохраняет прежнего кандидата. При двойной ошибке замены/отката прежняя копия остаётся в target/release-candidate.previous; следующий запуск откажет до ручной проверки и восстановления. Изменённые/посторонние файлы кандидата и reparse points отвергаются; скрипт не удаляет их автоматически. Одновременный запуск отвергается блокировкой. После принудительного завершения процесса сначала убедись, что сборка больше не работает; оставшийся release-* и release-build.lock в target/work можно убрать после проверки границ и нужных доказательств. `finally` не гарантирует уборку при выключении компьютера.

## Активация и доказательства

Маршрут preview → apply с одним candidate_sha256 — в [проектной инструкции](../.highgrade/project/INSTRUCTIONS.md). Используй CLI и kit одного кандидата. Скрипт не активирует поставку и не публикует Git. Сам SHA не гарантирует побитово одинаковый бинарник разных сборок; для apply сохраняется fingerprint конкретного кандидата.

Долговременное доказательство храни в specs/changes/<ID>/evidence либо docs/evidence; запись выпуска — в docs/releases. Кэш target не является долговременным хранилищем. Временные пилоты создавай через TemporaryDirectory; нужные отчёты копируй до выхода. Не оставляй полную сборку на каждый SHA или выпуск. Сохранённые локальные журналы уборки — в игнорируемом .highgrade/local/archive; они могут содержать контекст пилотов и не публикуются автоматически.

Проверка маршрута: `python -m unittest discover -s scripts/tests -v` (реальные Git/Cargo, ошибка компиляции, чужие файлы, ссылка/junction). Python 3.12 и Cargo обязательны; дополнительных Python-пакетов нет.
