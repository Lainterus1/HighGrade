## Переданный на проверку снимок

Проверенная реализация: `target/release/highgrade.exe`, SHA-256 `c2bed28852796eb2549df5bfa3d2374717e98cf64019221e02e67ce17267f3f5`. Это локальная сборка. Хеши переданной спецификации и входов находятся в `target/spec-progress/handoff.json`.

После уточнения языка актуальные проверки и приёмка неизменённых требований записаны в HG-0001. Архивная HG-SPEC-PROGRESS сохраняет исходный снимок. Текущий результат выпуска — в [записи v0-2-13](../releases/v0-2-13.md).

Проверки для обновлённой передачи:

1. `target/release/highgrade.exe spec-list --root .`: проверить JSON, техническую готовность и отдельный статус человеческой приёмки. У HG-0001 ожидаются technical=ready и human=accepted; прежний архивный снимок может показывать устаревшие доказательства.
2. В отдельном пустом каталоге вызвать spec-list, затем spec-new с `--title` и полученным `--expected`: ожидается HG-0001, дата инструмента и стандартный шаблон; следующий номер — HG-0002.
3. Проверить spec-read и spec-schema: приёмка представлена историей; HG-0001 содержит явное решение автора; исходная архивная задача не переписывалась. В изолированных тестах проверены пакетное принятие, возврат и дрейф.

Только явный ответ человека по проверенной версии разрешает запись spec-decide. Публикация и активация остаются отдельными действиями.

Ограничения: CLI не удостоверяет личность человека, достоверность указанного build ID или полноту заявленных входов. Счётчик общий для одного store; независимым Git-веткам нужен согласованный порядок создания задач. Приёмка относится к конкретной версии.
