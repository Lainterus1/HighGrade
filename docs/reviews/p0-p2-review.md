# Проверка реализации P0–P2

Дата: 2026-09-23. Область: [план первого выпуска](../archive/plans/first-release.md), только P0–P2. [Технический контракт](../implementation/p0-p2-contract.md) описывает форматы и ограничения. Полномочия автора: последовательный план и выполнение этих этапов, включая код, локальные тесты и документацию.

## Результат

P0: определены источники, проверенные версии, исходная поставка, пути, схемы, ошибки и границы будущей связи OpenSpec с тестами. OpenSpec проверен по официальным исходникам/документации; runtime не установлен. Предположения следующего этапа явно вынесены в контракт.

P1: Rust CLI собирается локально; bundle содержит минимальный highgrade-init и правила. Подключение требует явного подтверждения аудита со снимком файлов, сохраняет чужие инструкции, повторяется без дублирования. Обнаружение repo-навыка подтверждено отдельными вызовами skills/list у backend поставки Codex app и CLI. Их SHA256 совпадают; это не две независимые реализации. Полное взаимодействие через GUI и полноценная процедура init не проверены, последняя ещё не реализована.

P2: doctor/inspect читают состояние без исправлений. Реализованы роли/области документов, размеры, локальные Markdown-ссылки/якоря, бюджеты документа и маршрута, история бюджета, неизвестные области. Собственные бюджеты High Grade и OpenSpec остаются unknown; это корректно обнаруженные ограничения, не пройденные проверки.

## Доказательства

- `cargo test --locked --offline`: 30 тестов, 0 ошибок; исходники и поведенческие тесты входят в поставку.
- `cargo fmt --all -- --check` и `cargo build --release --locked --offline`: успешно на Rust 1.97.0 Windows MSVC. Rustfmt добавлен как штатный компонент существующего toolchain.
- Release-кандидат установлен дважды в синтетический корень с кириллицей и пробелами. Файлы проекта сохранены, doctor не записывает изменений.
- Повтор и обрыв на четырёх границах публикации проверены; полный `.part` продолжает установку, неполный остаётся для ручного разбора с ошибкой. Чужие правки не заменяются.
- Проверки путей охватывают traversal, ADS, резервные имена Windows и junction. Проверки контекста охватывают UTF-8/CRLF, ссылки, бюджет/потолок/историю, пустые значения, дубли и неизвестные области.
- Обе точки поставки Codex обнаружили `highgrade-init`, scope=repo, enabled=true. Проверка выполнялась через standalone app-server без создания задач, запуска модели и переключения глобальных настроек.

Машинные данные: [сводка](p0-p2-evidence.json), [обнаружение навыка](p0-p2-discovery.json), [release-проверка](p0-p2-release-probe.json), [итог Rust-тестов](p0-p2-tests.txt). [Диагностика реального проекта](p0-p2-project-diagnostics.json): 18 зарегистрированных источников, ошибок структуры/ссылок и неизвестных областей нет. Шесть BudgetNotAgreed (пять документов и маршрут) оставляют inspect в unknown; doctor отдельно показывает отсутствующий OpenSpec и неподключённую основу в репозитории разработки. Read-only подтверждён сравнением файлов до/после. Это не подменяет смысловой аудит.

Проверка импорта: 54 файла совпали с первоначальным импортом. 56 защищённых файлов плагинов и старого структурного скрипта не изменены относительно начала задачи. 12 изменённых исходных документов сохранены в архиве с SHA256.

## Независимое ревью

Нативный независимый reviewer рассмотрел фактический код и тесты. Найдены и исправлены три случая ложного покрытия: пропуск дочернего документа при запросе родителя, маскировка неизвестной области entry-документом, неявное покрытие всей папки из-за расположенного в ней документа. Для каждого добавлен регрессионный тест. При проверке самого проекта дополнительно исправлено распознавание Markdown task-list; флажки больше не считаются битой ссылкой, добавлен тест.

При сверке контракта выявлено несоответствие JSON ошибок основной программе. Исправлен единый Report/failed/exit1, добавлен CLI-тест. Финальный вердикт после повторной проверки: **REVIEW_GO**, открытых замечаний предыдущего ревью не осталось. Нативное ревью не заявляется межмодельным или внешним.

## Остаточные ограничения

Это прототип, не готовый workflow. P3–P6, полноценные четыре навыка, исполнение OpenSpec, Rust/Playwright trace, update и испытания на проектах автора не выполнялись. Скорость BDD в тысячах сценариев не заявляется.

Receipt не доказывает качество смыслового аудита; `passed` не означает пользовательскую приёмку. Полная автоматическая recovery при любом аварийном обрыве не обещана. Кастомные Markdown-якоря, ссылки в сеть, конкурентные внешние редакторы и другие файловые системы имеют ограничения контракта.

Исходники SVG/CHA и прежний check-repository.mjs сохраняются без изменений. Изменяемые документы архивируются с исходными SHA256. Git не инициализируется, коммиты/push/публикация не выполняются, установленные плагины не переключаются. Следующий продуктовый этап — P3 по отдельному поручению.
