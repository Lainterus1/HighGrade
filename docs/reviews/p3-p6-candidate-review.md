## Границы и решения до публикации

- Первый Rust-адаптер подтверждает только top-level integration tests с обычным путём `tests/<binary-name>.rs`; прочие Rust targets остаются `unknown`. Он не обещает покрытие всех форм Rust тестов или «тысячи specs/с». Native runner остаётся отдельным.
- `capture_root` и хеши фиксируют переносимость и актуальность перечисленных источников, но не доказывают качество теста, полноту выбора затронутых зависимостей или подлинность внешнего run record. Нужен агентский разбор влияния.
- P5 обновляет неизменяемые материалы/CLI при неизменных четырёх router-файлах. Их будущая миграция требует отдельного контракта. Прототип manifest v1 в целевом проекте автоматически не мигрирует.
- CLI P5 запускает выбранный exe с `--version` и `doctor` до переключения и установленный новый exe с `doctor` после него. Если postcheck не проходит, возвращает прежний активный указатель. Это функциональная локальная проверка CLI, но не полноценное испытание процедур агента или пользовательская приёмка.
- Репозиторий пока не содержит `LICENSE`/`NOTICE`; импортный манифест подтверждает локальное происхождение 54 файлов, но не право на лицензирование каждого фрагмента. В исходниках SVG/CHA нет собственных LICENSE/NOTICE; прямые зависимости перечислены в Cargo/Node/Python манифестах, они не включены в исходный bundle. Из метаданных Cargo все 25 сторонних пакетов имеют заполненное поле license; в Node lock найдены MIT, BSD, ISC, MPL-2.0, CC0 и BlueOak. Перед публичной передачей требуется конкретная лицензия проекта и отдельная проверка прав на код/примерные ассеты. По [документации GitHub](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/licensing-a-repository) публичный репозиторий без лицензии не даёт другим обычного права использовать и изменять код.
- Бюджеты документов High Grade пока `not-agreed`; структурный скрипт только измеряет объём. Настоящие два пилота нужны для проверки интервью, адаптации, приёмки, архивирования и длительного сопровождения с человеком. Глобальные настройки Codex, установленные плагины, Git/GitHub и чужие проекты не менялись.

Следующий шаг: автор выбирает один существующий и один новый тренировочный проект. После пилотов повторить выявленные сценарии, исправить дефекты, провести итоговое ревью, затем отдельно принять выпуск и решить публикацию/лицензию.
