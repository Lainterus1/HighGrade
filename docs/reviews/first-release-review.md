# High Grade: ревью плана первого выпуска

Дата: 2026-09-23. Объект: действующие документы High Grade и [сводный план](../plans/first-release.md). Поручение — консолидировать принятые решения, уточнить обязанности, подготовить план и провести ревью; программы не писать. Это проверка документов, не свидетельство работоспособности продукта.

## Вывод и область

Принятый объём сведён в один план. Критические продуктовые противоречия не обнаружены; выявленные расхождения технического предложения и статусов исправляются по ранее согласованным требованиям. Работоспособность навыков, CLI, установки, восстановления и Rust/Playwright пока не доказана. Следующая стадия — P0, не массовая реализация и не испытания чужих проектов.

Проверены README, AGENTS, ARCHITECTURE, ENGINEERING, DEVELOPMENT, SPECIFICATION, CONTEXT, TOOLING, technical-design, архивный вход и реестр документов. Исходники плагинов и существующий скрипт не менялись. Исторические отчёты сохраняют прежний статус; их результаты не перенесены на новый план. Тренировочные проекты не читались.

## Проверка по 11 направлениям

1. **Архитектура.** Четыре навыка и один CLI разделены по ответственности; OpenSpec владеет поведением и задачами, агент — исполнением и смысловым обзором, CLI — детерминированными проверками. Общая основа и адаптация раздельны. Уточнена граница предварительного аудита/подключения (R2). Единая точка риска — чтение общей конфигурации/выбор поставки; ошибку нельзя скрыть другой установкой.

2. **Ошибки и восстановление.** Техническая схема содержит реестр логических ошибок и видимые реакции. Нет связи/отчёта, пустой suite, ошибочный формат и unknown различаются. Установка/update/архив имеют восстановление собственной операции без потери чужих изменений. Это требования к будущим проверкам P1/P5, не реализованные обработчики.

3. **Безопасность.** Нет сервиса, нового аккаунта, телеметрии или отдельного LLM API. Существенные угрозы: выход файловых операций за корень, подмена инструкций содержимым проекта, командная инъекция, секреты в отчётах, недоверенная поставка. Пути/полномочия/источник/содержимое отчётов должны проверяться; хеш не подтверждает доверенность источника. Совместимость лицензий остаётся до публикации, не объявляется проверенной.

4. **Потоки данных и пограничные случаи.** В технической схеме разобраны нормальный, отсутствующий, пустой, повреждённый и устаревший входы, приёмка и смена поставки. Два порядка конкурентного изменения рассмотрены; все собственные writers должны согласованно использовать блокировку/проверку входов. Внешние редакторы не соблюдают её автоматически; строгой транзакции между ними не обещано. Нужны проверки контролируемых прерываний.

5. **Качество и сложность.** Удалён дублирующий протокол решений из двух предложений (R6). Covers, единый подробный отчёт, каталог адаптеров и миграции плагинов не прячутся в первом выпуске. Модули CLI могут разделять базовые функции путей/ошибок, но не должны вырасти в платформу. Метрики сложности кода неприменимы: новый код не написан.

6. **Испытания.** План содержит наблюдаемые положительные и отрицательные результаты для всех принятых процедур, включая R3. Rust и Playwright обязательны для проверки переносимости связей. Параметризация, повторные попытки, отсутствие отчёта и устаревшие входы требуют отдельных случаев. CLI проверяется локальными/интеграционными тестами; поведение навыков — настоящими сессиями в обоих интерфейсах. Начальный выбор тренировочных проектов отложен до готовности кандидата.

7. **Производительность.** Главные риски — полный аудит, совокупный читаемый контекст и большие отчёты. Нужны измерения времени, объёма и памяти на представительных данных; p99 и предельная ёмкость пока неизвестны. Прочитать всё для каждой малой правки не требуется; полный аудит init не урезается без решения автора. Нет обещания тысяч браузерных сценариев в секунду.

8. **Наблюдаемость.** Компактные записи и исходные отчёты позволяют различать факт выполнения, область и актуальность. Тяжёлая диагностика локальна, видео выключено. Ошибки workflow остаются в проекте до ручного извлечения; приложение не экспортирует их автоматически. Отчёт CLI не подменяет смысловую оценку. Отдельная панель мониторинга не нужна.

9. **Поставка и внедрение.** GitHub с исходниками, локальная сборка, Windows first; не готовые бинарные релизы. Подключение, выполнение адаптации, техническая готовность, приёмка и публикация различаются. Отказ от кандидата сохраняет прежнюю основу. Проверки на реальных тренировочных проектах и разрешение публикации ещё впереди.

10. **Дальнейшее развитие.** Запланированы Covers и отдельные миграции SVG/CHA. Подробный отчёт, хуки и новые платформы — по потребности. Обратимость текстовых решений высокая; реальные миграции схем/установок должны быть подтверждены P5. На год вперёд сохраняется ясное разделение обязанностей; новая платформа знаний не добавлена.

11. **Пользовательский путь.** Веб-интерфейс отсутствует, поэтому визуальный аудит экранов не применим. Рассмотрен путь автора в диалоге/CLI: существующий контекст → недостающие вопросы → согласованный план → выполнение по поручению → отчёт → приёмка. Пустое/частичное/ошибочное состояние должно быть понятно без ложного «готово». Дополнительная новая UI-подсистема не предлагается.

## Независимое ревью и диаграммы

Первый независимый проход: внутренний агент Codex, только чтение SPECIFICATION, CONTEXT, TOOLING и technical-design. Вердикт исходного снимка — REVIEW_GO_WITH_CONDITIONS, два P2 (R2/R3). Повторный проход подготовленного снимка завершён: REVIEW_GO для согласованности документов, R2/R3 закрыты, новых существенных замечаний нет. После него дополнены только записи результатов проверок и счётчик проходов. Это не отдельная модель и не внешний провайдер. Внешний Claude Code не обнаружен через Get-Command; внешний процесс не запускался.

Диаграммы технического предложения пересмотрены: архитектура, владение файлами, инициализация/приёмка, ошибки чтения, штатный цикл, переключение/возврат и конкурентные порядки. Диаграмма фактической ARCHITECTURE обновлена только новым планом/ревью. Ни одна диаграмма не объявляет будущую реализацию существующей.

## Проверки текущего изменения

После переноса структурная проверка check-repository.mjs --verify-import прошла: 54 импортных файла совпадают с исходным манифестом. Дополнительно проверены 15 зарегистрированных источников, локальные ссылки, 25 уникальных WF-ID, сохранность 55 файлов исходных пакетов/скрипта и 10 архивных оригиналов. Ошибок не обнаружено. Машинные результаты — [first-release-checks.json](first-release-checks.json). Исполняемые тесты High Grade отсутствуют; они не запускались.

Размеры основных источников после сведения: SPECIFICATION — 63 015 байт, CONTEXT — 15 446, TOOLING — 8 922, техническая схема — 25 139. SPECIFICATION имеет 259 физических строк при 63 КБ: один лимит строк скрыл бы объём. Он остаётся источником требований, читаемым по затронутым разделам, а не обязательной полной загрузкой каждой задачи. Диапазоны бюджетов пока not-agreed; назначать произвольный зелёный лимит в этом ревью нельзя.

## Остаточные вопросы и следующий шаг

P0 должен закрыть актуальную совместимость Codex/OpenSpec, механизм поставки, форматы, Rust-отчёт и отметки. До соответствующих этапов открыты численные бюджеты High Grade, конкретная лицензия, параметры хранения и выбор тренировочных проектов. Эти вопросы не повод заново выбирать уже согласованные роли или писать программы без поручения.

Документальный результат можно использовать для продолжения проектирования. Он не означает техническую готовность выпуска, выполненное внешнее/инженерное ревью или пользовательскую приёмку. Единственный Next находится в плане.
