# Проверка проектного каталога спецификаций

Поставка v0-2-14 / CLI 0.2.14 активирована; исходные проверки ниже относятся к её кандидату. Задачи: HG-0002 → HG-0003 → HG-0004 в [каталоге](../../specs/README.md). Автор принял все три спеки и разрешил активацию/публикацию; фактическое состояние — в [записи выпуска](../releases/v0-2-14.md).

## Что проверено

- Отдельные spec/results, действующие требования, пользовательский путь и сохранность после удаления `.highgrade`; соседние неизменённые файлы не переписываются.
- Явная миграция v1/v2, точная резервная копия, обнаружение поздней записи старой CLI, конкурентная нумерация, прерывание записи, восстановление staging, запрет удаления обязательных документов и присвоения чужого каталога.
- Повторная проверка включённой спеки, неизменность требования/spec.json, история доказательств и устаревание прежней приёмки.
- Связи без наследования, отсутствующие ID, циклы, готовность зависимостей; реестр тегов, запрет удаления используемого тега, объединение ссылок, JSON-выборка с краткими зависимостями.
- Настоящие Python unittest/JUnit и Cargo-тесты: успех, ошибка, пропуск, пустой отчёт, тайм-аут, дрейф входов; ошибка внутри пачки сохраняет предыдущие результаты. Проверки имеют свои отчёты, команду и снимки входов. Чтение не запускает код; ручная проверка остаётся явной.

Автоматические проверки: [catalog_contracts.rs](../../tests/catalog_contracts.rs); связи с конкретными сценариями и исходные отчёты принадлежат results.json соответствующих спек. Старые тесты совместимости остаются в spec_contracts/trace_contracts; прежний OpenSpec не менялся.

[Запись упражнения](../evidence/spec-catalog/isolated-pilot.json): копия kit установлена в временный профиль; после удаления доступности исходного пути установленная CLI создала отдельный Rust-проект и каталог docs/specs, настроила тег/раннер, выполнила реальный Cargo-тест, включила требование и повторила проверку после удаления проектной `.highgrade`. Требование и spec.json сохранились побайтно. Ревью в упражнении — явно обозначенный тестовый актор; пользовательская приёмка pending. Это проверка маршрута CLI, а не обещание качества любого продукта или поведения агента в любом проекте.

[Наглядный пример](../examples/spec-catalog/README.md) показывает русскоязычные поля текущего формата. Инструкции, шаблоны и справочник входят в kit и не ссылаются на документы исходного Проекта как на обязательный контекст.

## Ограничения

Полнота inputs, смысл ожиданий и подлинность стороннего отчёта требуют ревью. Поддержаны точный Cargo-тест и JUnit; остальные штатные форматы допускают прямой запуск с spec-evidence. Лимит документа и транзакции — 8 МиБ, счётчик не распределён между независимыми Git-ветками. На Windows тайм-аут завершает дерево процессов, на других платформах — прямой процесс; раннер отвечает за дочерние процессы. Внешние ссылки inspect не проверяет. Активная общая CLI 0.2.14 обслуживает каталог; старые CLI не должны писать в исторический store после миграции.
