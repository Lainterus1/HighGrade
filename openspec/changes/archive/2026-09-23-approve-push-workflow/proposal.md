# Proposal

## Why

Локальная готовность задачи и отправка накопленных коммитов сейчас смешаны в `highgrade-deploy`. Последний выпуск также показал допустимый местный порядок «коммит → локальная активация → push», который проектная инструкция не описывает. Действующие документы называют опубликованную v0-2-6 кандидатом, а полный маршрут вне исходного проекта пока не испытан.

## What Changes

- Заменить `highgrade-deploy` на `highgrade-approve` для принятия конкретной задачи и `highgrade-push` для публикации выбранного диапазона готовых коммитов; сохранить `highgrade-update`.
- В `approve` завершать содержание и доказательства задачи, создавать коммит и, если проектом определена локальная активация, применять её из этого коммита. Публикация и эксплуатационное развёртывание не следуют из вызова `approve`.
- В `push` проверять весь выбранный диапазон, задачу и цель публикации; один push может включать несколько задач. Не повторять согласование уже явно названного неизменного диапазона.
- Согласовать правила, статус и короткую запись выпуска; убрать устаревшие проектные формулировки из действующих источников, сохранив историю решений; уточнить границу `work`/`approve`.
- Сделать `doctor` честной проверкой доступности инструментов, а версию OpenSpec проверять отдельно; добавить проверку исходной поставки в CI.

## Impact

Общие навыки и процедуры, миграция пользовательской поставки, OpenSpec-контракт, правила этого репозитория, реестр контекста, тесты и CI. SNAF и другие целевые проекты не меняются. Push и активация пользовательской установки в рамках реализации не выполняются.
