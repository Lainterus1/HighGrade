# Proposal

## Why

Сейчас установленный навык `deploy` сразу разрешает commit, push и активацию. Это смешивает локальное завершение принятой задачи с удалённой публикацией и плохо подходит проектам с PR, автоматическим CI или отдельным развёртыванием. Автор выбрал безопасную границу: новый `highgrade-deploy` завершается проверенным локальным коммитом, push выполняется только по явному согласованию.

## What Changes

- Сделать локальный коммит результатом вызова `highgrade-deploy` по умолчанию. До него завершать документы, архив, проверки и точный отбор файлов.
- Отдельно разрешать push и прочие удалённые действия. Явное поручение может быть дано в том же запросе или после предъявления конкретного коммита; оно не выводится из одного слова `highgrade-deploy`.
- Выполнять активацию только по явно разрешённому проектному маршруту. Не требовать её описания для одного локального коммита; после публикации различать подтверждённую удалённую версию и фактическую активацию.
- В общей процедуре оставить инварианты проверки и сохранности, а детали Git-цели, PR/CI, команд, проверки и отката брать из проектной инструкции или связанного runbook. Убрать из неё пример `global-update` самого High Grade.
- Переименовать общий навык `deploy` в `highgrade-deploy` и безопасно мигрировать установленную v0-2-5 с возможностью отката.

## Impact

Контракт OpenSpec, общая процедура и маршрутизатор `highgrade-deploy`, шаблон проектной инструкции, описание общего workflow, проектный маршрут High Grade и миграция в Rust CLI. `highgrade-update` сохраняет свою обязанность.
