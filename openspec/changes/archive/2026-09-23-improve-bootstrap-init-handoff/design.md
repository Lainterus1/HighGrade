# Design

## Решение

Сохранить bootstrap как проверку стандарта High Grade. Поиск кандидатов остаётся ограниченной подсказкой только для отсутствующих канонических путей. Не расширять словари имён и меток по одному искусственному примеру: содержательное сопоставление остаётся у агента.

После предварительного отчёта init создаёт одну таблицу адаптации, а не отдельный backlog. Для каждого отсутствующего пути в ней фиксируются проверенный кандидат, ручной поиск вне кандидатов и действие; для смешанного документа указываются обе роли и исходный путь. Отвергнутый кандидат помечается с причиной. При полном наличии канонических файлов агенту нужна только проверка их связей и содержания, поэтому обход дерева для кандидатов пропускается. `candidate_scan` в JSON принимает `performed` или `not_needed`; `not_needed` не означает полный аудит. Проверка списка исключений и источников ссылок сохраняется.

Тестовый проект синтезирован в системном временном каталоге: `CONTRIBUTING.md` смешивает инженерные правила и команды, `notes/platform.md` содержит архитектуру под необычным именем, `guides/CLAUDE.md` даёт ложного кандидата. После записи исходного отчёта агент вручную переносит/разделяет содержание, создаёт действительно отсутствующие инструкции и реестр, обновляет ссылки и запускает обычный `inspect`. Итог и ошибки фиксируются в ревью; временное дерево удаляется по проверенному абсолютному пути.

## Границы

Не создавать автоматический классификатор содержания, не менять правила семи путей и шести ссылок, не объявлять фикстуру доказательством точности подсказок на реальных проектах. Не активировать глобальную поставку.
