# HG-0020: агентные упражнения Planner

Время наблюдения: 2026-09-25 UTC. Инструмент: Codex CLI `0.155.0-alpha.16.4`; кандидат High Grade `v0-2-17` установлен через `global-install` в отдельный временный профиль. Проекты упражнений созданы под временным каталогом `highgrade-planner-pilot-20260925`. Общая пользовательская Поставка не переключалась. Запуски использовали `codex exec --sandbox workspace-write --skip-git-repo-check --cd <изолированный проект> --json`; для продолжений — `codex exec resume` из каталога соответствующего проекта. [Машинная сводка](agent-pilots.json) сохраняет точные запросы и проектные входы пилотов, контракты двух синтетических спек до выполнения, ID сеансов, вызовы Goal, SHA-256 выходов и отпечаток кандидата. Сырые журналы CLI остались в локальных сеансах Codex по указанным ID и не скопированы в репозиторий, поскольку содержат посторонний контекст.

| Сценарий | Наблюдение |
|---|---|
| HG-0020-S1 | В `auto-project` местный `AGENTS.md` принимал автоматический Planner+Goal, а запрос не называл навык. Агент прочитал установленный маршрутизатор, создал ровно один Goal, проверил `FIRST`, перечитал первый файл и записал `SECOND:FIRST`; итоговое состояние `DONE`, `Next: none`. В сеансе `01a0d920-addb-7302-bae9-ab3445e32f73` — один `create_goal`, один `update_goal`. Новая спека и второй список задач не создавались. |
| HG-0020-S2 | В `spec-project` существовали связанные нативные HG-0001 и HG-0002. Один Goal охватил HG-0001-T1 → HG-0002-T1 с двумя ID спек; единственный план хранил порядок и барьер. Агент перечитал обе спеки, проверил `A` и `B:A`, пометил обе задачи выполненными и записал их доказательства. После прерывания он сверил файлы и продолжил с неподтверждённого действия. Сеанс `01a0d923-4d46-72a1-adce-56cbdb9793f5`: один `create_goal`, один `update_goal` за оба хода. Обе спеки оставлены `in_progress` / `pending` без ревью и интеграции согласно границе пилота. |
| HG-0020-S3 | В отдельном `one-project` запрос на один файл `ONE` прошёл прямым маршрутом: точные байты `4F 4E 45` проверены PowerShell, каталога плана нет, активного Goal нет. Сеанс `01a0d92e-2363-7753-b4f7-29e3818f2924`: `create_goal` — 0. |
| HG-0020-S4 | Цели в сеансах S1 и S2 содержали конечный результат, порядок этапов, проверку, границы и условие блокировки; состояние после этапа указывало один `Next`, после общей проверки — `Next: none`. Тексты вызовов `create_goal` и хеши итоговых состояний сверены с локальными журналами и файлами. |
| HG-0020-S5 | `resume-project`: первый ход оставил активный Goal и один `Next` после проверки `BASE`. Перед продолжением первый файл был контролируемо заменён на `BROKEN` (SHA-256 `D84771511DBEAA7374796D8B58D21045B82BCAD601CC302037828379EDB47814`). Агент обнаружил расхождение, восстановил и перепроверил `BASE`, затем создал `DERIVED:BASE` из повторно прочитанного входа. Вторая проверка подтвердила зависимость; Goal завершён только после неё. Сеанс `01a0d924-6942-7312-8887-126d198e8788`: один `create_goal` за все ходы. Отдельно прерванный ход S2 возобновился с перечитыванием обеих спек и уже существующего второго файла. |
| HG-0020-S6 | Пока Goal `base/derived` был активен, запрос на отдельную цепочку `other-a/other-b` не заменил его: второй `create_goal` не вызван, оба новых файла отсутствуют. Агент сохранил независимую подготовку и указал на конфликт. |
| HG-0020-S7 | В `plan-project` явный запрос ограничивал результат планом P → Q. Создан и завершён один Goal именно для проверенного плана; порядок и барьеры сверены, `docs/p.txt` и `docs/q.txt` не появились. Сеанс `01a0d929-3e32-7661-b6b4-50d34c013b47`: один `create_goal`, один `update_goal`. |
| HG-0020-S8 | Во всех упражнениях проверены только разрешённые технические шаги. В S2 спеки оставлены без `spec-integrate` и человеческой приёмки; в S6 новая цепочка не выполнена; в S7 реализации нет. Коммит, локальная активация общей Поставки и push не выполнялись. |

Проверка файлов и отсутствия запрещённых результатов выполнена локальным Python чтением байтов и SHA-256; конкретные значения находятся в машинной сводке. После независимой сверки временные проекты удалены; точные входы сохранены в сводке, локальные журналы Codex доступны по ID сеансов. Ограничение: ручное упражнение подтверждает поведение этих сеансов, а не гарантирует выбор модели для каждого будущего запроса. Первую попытку CLI с `--ephemeral` не учитывали как успешную: инструмент Goal требует сохраняемый сеанс.
